## P757 session

**15. Symlink `D` deletions in worktree blocked `git rebase main` — took multiple rounds to diagnose**
w1 had ~150 `D` entries in `git status` from `setup-worktree.sh` symlinking `scripts/` and `supabase/migrations/`. These are not real deletions but symlink artifacts. The diagnosis required checking `ls -la scripts` and took two rounds before the root cause was confirmed. The agent should recognize this pattern immediately: any worktree with a mass of `D` entries in `scripts/` or `supabase/migrations/` is exhibiting the known symlink artifact — no further diagnosis needed.
- Category: wrong-assumption
- Severity: moderate

**16. Spec created in main, then manually copied to w1 — worktree + unstaged-changes forced a detour**
`/create-bug` must run from main repo (worktree guard). w1 had unstaged P745 WIP, blocking `git rebase main`. The spec had to be `cp`-ed from main into w1 manually. This is the same pattern as items 7–8 from P755: the symlink layout makes migration and spec files created in main invisible from worktrees, requiring a manual copy step every time. No process improvement was proposed during the session.
- Category: process-gap
- Severity: moderate

**17. Migration staged in main via symlink; integration test in w1 only — first commit attempt failed pre-commit hook**
The migration was written to `supabase/migrations/` (symlinked, physically in main). The integration test was only in w1's `e2e/`. The pre-commit hook on main rejected the commit because: (a) deploy-manifest not stamped from main and (b) the integration test path was not reachable from main. Both are predictable consequences of the symlink layout. The agent should have staged test + manifest from main before the first commit attempt rather than waiting for hook failure.
- Category: process-gap / repeated-step
- Severity: moderate

**18. Playwright test had inter-test state dependency — scenario 3 failed on isolated retry**
Scenario 3 read `letterIdForKnown` set by scenario 1. On retry, Playwright ran scenario 3 in isolation and `letterIdForKnown` was `undefined`. The fix was to move letter sealing into `beforeAll`. Tests with cross-scenario state dependencies are a known fragility pattern; the initial test should have been written with `beforeAll` setup from the start.
- Category: wrong-assumption
- Severity: moderate

**19. Code review flagged `create_letter_delivery` (P707) as uncovered write path — was a false positive**
The review subagent flagged P707's RPC as a potential gap in `receiver_profile_id` coverage. Checking the migration showed it uses `auth.uid()` directly, so no gap. The false positive required a migration lookup. This is a foreseeable false positive: any RPC that uses `auth.uid()` at the DB layer cannot have the same caller-supplied gap as application-layer code. The review prompt should include a note to check whether the write path uses `auth.uid()` before flagging it.
- Category: unnecessary-question
- Severity: minor

**20. Updated integration test synced to main manually with `cp` — no automated path**
After adding a new scenario (case-mismatch) to the integration test in w1, the file had to be `cp`-ed back to main. This is the mirror of item 16: test files physically in w1 cannot be committed from main without manual copying. The pattern repeated twice in the same session (spec copy in, test copy out). There is no documented or automated solution for this in `worktree-setup.md`.
- Category: repeated-step
- Severity: minor
