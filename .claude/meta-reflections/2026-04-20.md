The initial `deleteLetter()` used `.delete().eq('id', id)` without `.select('id')`. The agent did not apply that lesson to the DELETE case before writing the code — the bug was caught only by the code review subagent. Should have proactively added `.select('id')` and checked `data.length === 0` as the canary pattern whenever writing any DML through Supabase client.

`SessionChannelEntry.channel` was initialized as `channel: null!`. ESLint's `no-non-null-assertion` rule blocked the commit. Fix required changing the type to `ReturnType<...> | null`, initialization to `channel: null`, and adding an `if (entry.channel)` guard in `removeChannel`. A type that can hold `null` should never be initialized with a non-null assertion — the pattern was avoidable at write time.
Category: wrong-assumption
Severity: minor

Category: missed-signal
Severity: moderate

**5. Untracked files deleted when switching branches**
When switching branches with staged/untracked files present, git deleted untracked source files from the working tree. Recovery required `git show main:file > file` for files already on main and rewriting others from session summary content. Pre-branch-switch `git status` + explicit stash/park would have prevented the loss.

**6. `git.index.lock` left from failed operation — manual removal required**
