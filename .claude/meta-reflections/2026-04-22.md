## Problems & Friction

**1. P785 not discovered until T11 execution**
- What happened: The git env var leak (GIT_DIR etc.) was present in the canary since P783 shipped, but only surfaced during T11 execution when a nested git init in a scratch dir polluted the outer index. The P783 canary's Invariant 3 (eval adversarial test) tested re-lex injection but not env var inheritance.
- Category: missing-context
- Severity: moderate
- Root cause survives: yes — the P783 canary's hermetic sandbox used `unshare` for filesystem isolation but did not unset git env vars, so the isolation was incomplete along one axis.

**2. `git config core.bare=true` appeared twice without identified write site**
- What happened: `git add` failed with "fatal: must be run in a work tree" on the main repo twice. `git config core.bare false` fixed it each time, but the config layer that received `bare=true` was never identified (`git config --list --show-origin` was not run at the moment of failure).
- Category: missed-signal
- Severity: moderate
- Root cause: not fully determined. Strong hypothesis: P785-class GIT_DIR pollution wrote to a config layer. Would have been confirmed by running `--show-origin` at failure time.

**3. T01 cherry-pick required subset extraction because original commit bundled orthogonal changes**
- What happened: T01 on P781 bundled `.gitignore` additions (main-relevant) with p779/p780 spec dedupes (branch-local no-ops). Cherry-picking to main required the subset pattern. This was recoverable but added ~10 min of surgery.
- Category: process-gap
- Severity: minor
- Root cause: no convention against bundling main-relevant infra changes with branch-local spec housekeeping in the same commit. Feature branch commits should keep main-cherry-pickable changes isolated.

**4. Symlink cross-session pollution existed for the duration of P781 analysis without being flagged**
- What happened: `scripts/` and `supabase/migrations/` were symlinked in worktrees since the worktree system was built. The cross-session pollution risk (file created in session A visible in session B) and `git add` "beyond symlink" failure were known failure modes but not codified as a rule until T11 surfaced them concretely.
- Category: missing-context
- Severity: moderate
- Root cause: the original worktree setup decisions captured the symlink approach for convenience but deferred the failure-mode audit. The phantom-deletion entries in decisions.md documented one symptom (` D` entries in git status) without tracing to the root (symlinks for mutable dirs).

**5. Umbrella spec P781 reached 15 tasks before decomposition was triggered**
- What happened: Decomposition was run only after the full technical analysis accumulated 15 tasks across 4 domains. The spec was already in a state that made the dependency graph complex to untangle. Earlier decomposition (at ~6-8 tasks) would have produced cleaner child scopes.
- Category: process-gap
- Severity: minor
- Root cause: no hard threshold in the `/decompose` skill or pre-decompose check that flags when task count exceeds 8-10 before full analysis completes.
