# Ralph Loop - Design System Spec Gaps

## Iteration 3 - Position Button Colors

**Issue:** Position buttons (Agree/Disagree/Unsure) use semantic colors that may violate design system intent.

**Current implementation:**
- Active "Agree" button: `bg-emerald-500` (green)
- Active "Disagree" button: `bg-rose-500` (red/rose)
- Active "Unsure" button: `bg-gray-500` (gray)

**Design spec says:**
- Green ONLY for: "Confirmation screens, verified/accepted status badges, success state indicators"
- Red for: "Destructive actions (Delete, Remove, Disconnect)"

**Question:** Are position buttons "status indicators" or "action buttons"?
- If status: Green for "agreed" might be acceptable (like a verified badge)
- If action: Should use blue for all positions, with different opacity/borders for active state

**Recommendation:** Consider adding spec guidance for:
1. Toggle buttons that show current state vs action buttons
2. Position/opinion indicators in social features
3. Whether semantic colors (green/red) are allowed for non-action UI elements

**Current approach:** Keeping existing colors for now, but converting to shadcn/ui Button for component consistency.
