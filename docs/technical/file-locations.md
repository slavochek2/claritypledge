# File Locations Guide

**For agents:** Where to create files when working on Clarity Pledge.

---

## Quick Reference

| What | Where | Tool/Skill |
|------|-------|------------|
| Feature specs | `features/p{N}_{slug}.md` | `/create-spec` |
| E2E tests | `e2e/p{N}-{description}.spec.ts` | Created during `/dev` |
| Technical docs | `docs/technical/{name}.md` | Manual (ask first) |
| Strategic docs | `docs/{name}.md` or `docs/milestones/` | Manual (ask first) |
| Blog content | `content/blog/{slug}.md` | `/prepare-blog` |
| Migration scripts | `scripts/archive/migrations/YYYYMMDD-{name}.{js,mjs,cjs,sh}` | Manual |
| User feedback / session observations | `.private/docs/user-feedback.md` | Append dated entry |
| Analysis outputs | **Terminal only** | Never create files |
| Temporary files | `/tmp/` or system temp | Never project directories |

## Detailed Rules

### ✅ Feature Specs (`features/`)

**When:** Creating new features, bugs, tasks, or comments

**Location:** `features/p{N}_{slug}.md`

**How:**
- Use `/slava:build:create-spec` (unified spec creation skill)
- **Never** create manually (skills handle P-number assignment)

**Completed features:**
- Moved to `features/done/{sprint}/`, where `{sprint}` is the date folder named in
  `features/done/CURRENT_SPRINT` — resolved by `scripts/git-ops.sh` when `/ship` closes the spec.
  Older folders use a `{N}_{mon}_{yy}` naming from a retired sweep; both shapes are present.
- `/ship` auto-closes on success (move + set `status` + `completed_at`)
- `scripts/sweep-done.sh` can move files that land at `features/done/` root (Kanban drag, manual
  `mv`) into a dated subfolder, but **nothing calls it** — not pre-commit, not any skill. Run it by
  hand, or expect loose specs to stay at `done/` root. (P1199 owns reconciling the two folder
  shapes; P1221 recorded the root cause.)

**Examples:**
```
features/p145_position_loading_architecture.md
features/p147_kanban_ui_improvements.md
features/done/5_feb_26/p268_position_display.md
features/done/4_27_jan26/p101_cards_ux_overhaul.md
```

### ✅ End-to-End Tests (`e2e/`)

**When:** Implementing features that require E2E testing

**Location:** `e2e/p{N}-{description}.spec.ts`

**Naming convention:**
- Include P-number for traceability: `p{N}-{what-it-tests}.spec.ts`
- Use kebab-case for description

**Examples:**
```
e2e/p145-profile-position-loading.spec.ts
e2e/p147-kanban-ui.spec.ts
e2e/p145-regression.spec.ts
```

**UAT documentation:**
- User acceptance tests: `features/uat/p{N}.md`
- Generated by `/generate-uat` skill

**When:** Documenting architecture, patterns, processes

**Location:** `docs/technical/{name}.md`

**Always ask first:** "Should I create `docs/technical/{name}.md`?"

- User decides what deserves permanent documentation

### ✅ Strategic Documentation (`docs/`)

**When:** Business decisions, product strategy, definitions

**Location:**
- Concepts: `docs/definitions.md`
- Business: `docs/lean-canvas.md`
- Trade-offs: `docs/decisions.md`
- Philosophy: `docs/philosophy.md`
- Evidence: `docs/theory-of-change.md`
- Milestones: `docs/milestones/m{N}-{name}.md`

**Always ask first:** "Should I update `docs/{name}.md`?"

**Never duplicate:** These are sources of truth
- Add to source doc and link from elsewhere
- Don't copy content to multiple places

### ✅ Blog Content (`content/blog/`)

**When:** Publishing blog posts

**Location:** `content/blog/{slug}.md`

**How:**
- Use `/slava:content:prepare-blog` skill
- Skill handles Ghost CMS frontmatter

**Examples:**
```
content/blog/building-clarity-pledge.md
content/blog/calibrated-communication.md
```

---

### ✅ Migration Scripts (`scripts/archive/migrations/`)

**When:** One-off data migrations, schema changes, bulk fixes

**Location:** `scripts/archive/migrations/YYYYMMDD-{description}.{js,mjs,cjs,sh}`

**Naming convention:**
- Date prefix: `YYYYMMDD-` (for chronological sorting)
- Description: Short kebab-case description
- Extension: Match implementation language

**Examples:**
```
scripts/archive/migrations/20260216-add-frontmatter-fields.cjs
scripts/archive/migrations/20260213-migrate-to-rank.cjs
scripts/archive/migrations/20260215-fix-done-status.js
```

**Why archive/migrations/?**
- One-off scripts (not ongoing tools)
- Keep for historical reference
- Don't clutter main `scripts/` directory

---

### ✅ Active Scripts (`scripts/`)

**When:** Reusable tools, validation, automation

**Location:** `scripts/{name}.{js,sh,cjs,mjs}`

**Criteria for `scripts/` vs. `scripts/archive/migrations/`:**
- **Active scripts:** Run repeatedly (pre-commit, validation, backups)
- **Archive scripts:** Run once (migrations, one-off fixes)

**Examples of active scripts:**
```
scripts/pre-commit-checks.sh
scripts/validate-features.cjs
scripts/validate-doc-links.cjs
scripts/mcp-backup.sh
scripts/kanban.sh
```

---

### ❌ Never Create: Analysis Outputs

**What:** Audit reports, analysis summaries, validation results

**Where:** **Terminal output only**

**Examples of what NOT to create:**
```
❌ FRONTMATTER_AUDIT_SUMMARY.md
❌ DUPLICATE_PREVENTION_ANALYSIS.md
❌ add-frontmatter-results.json
❌ frontmatter-audit-report.json
```

**Instead:**
- Output findings to terminal (use Bash `echo` or direct text)
- If results are large (>500 lines): Ask user "Save to docs/technical/ or terminal?"

**Why:**
- Avoids clutter
- Analysis is point-in-time (not permanent)
- User decides what deserves documentation

---

### ❌ Never Create: Project Root Files

**What:** Any file in project root that's not permanent config

**Examples of prohibited patterns:**
```
❌ /*.md (except CLAUDE.md, README.md, CONTRIBUTING.md, etc.)
❌ /*.json (except package.json, tsconfig.json, vercel.json, etc.)
❌ /TEST_*.md
❌ /*_AUDIT*.md
❌ /*_ANALYSIS*.md
❌ /*_SUMMARY*.md
❌ /*FIXES*.md
❌ *-results.json
❌ *-report.json
```

**Permanent config files (OK in root):**
```
✅ CLAUDE.md, README.md, CONTRIBUTING.md, SECURITY.md, CLA.md
✅ package.json, package-lock.json
✅ tsconfig*.json, vercel.json, components.json
✅ .gitignore, .env* (but .env is gitignored)
```

**Red flags to stop and ask:**
1. Filename is ALL_UPPERCASE.md
2. Filename contains SUMMARY, AUDIT, ANALYSIS, FIXES, RESULTS, REPORT
3. Creating JSON files in root (not package/tsconfig/config)
4. Creating scripts outside `scripts/` directory

---

### ❌ Never Create: Temporary Files in Project

**What:** Debug outputs, temp data, work-in-progress files

**Where to put them instead:**
- System temp: `/tmp/` (on macOS/Linux)
- User temp: `~/Downloads/` (if user needs to access)
- Terminal output (no file at all)

**Examples:**
```
❌ /debug-output.txt
❌ /temp-analysis.json
❌ /test-data.csv
```

## Decision Tree

**"I need to create a file. Where does it go?"**

```
Is it a feature spec?
  → Yes: Use /create-spec (auto-creates in features/)
  → No: Continue

Is it an E2E test?
  → Yes: Create in e2e/p{N}-{description}.spec.ts
  → No: Continue

Is it analysis/audit/validation output?
  → Yes: Output to terminal (no file)
  → No: Continue

Is it a one-off migration script?
  → Yes: Create in scripts/archive/migrations/YYYYMMDD-{name}.{ext}
  → No: Continue

Is it a reusable tool/script?
  → Yes: Create in scripts/{name}.{ext}
  → No: Continue

Is it documentation?
  → Yes: ASK FIRST → "Should I create docs/technical/{name}.md?"
  → No: Continue

Is it blog content?
  → Yes: Use /prepare-blog skill
  → No: Continue

Is it temporary/debug?
  → Yes: Use /tmp/ or terminal output (never project directories)
  → No: STOP AND ASK

If none of the above:
  → STOP AND ASK before creating any file
```

## Skills That Create Files

**These skills handle file creation correctly (trust them):**

| Skill | Creates | Location |
|-------|---------|----------|
| `/create-spec` | Feature specs | `features/p{N}_{slug}.md` |
| `/prepare-blog` | Blog posts | `content/blog/{slug}.md` |
| `/generate-uat` | UAT docs | `features/uat/p{N}.md` |
| `/ship` | Moves completed features | `features/` → `features/done/{sprint}/` |
| `/architect` | Appends to feature | Existing `features/p{N}_{slug}.md` |
| `/ux` | Appends to feature | Existing `features/p{N}_{slug}.md` |
| `/dev` | Appends to feature + creates E2E | Existing spec + `e2e/p{N}-*.spec.ts` |

**If a skill creates files in the wrong location → that's a bug, report it.**

## Pre-Commit Enforcement

**Script:** `scripts/pre-commit-checks.sh`

**What it checks:**
- No temporary files in project root
- No files matching prohibited patterns (AUDIT, ANALYSIS, etc.)

**What happens:**
- Warning (not blocking) if violations found
- Links to this document for guidance

**Upgrade path:**
- After 1 month of zero violations → upgrade to ERROR (blocking)
