# Clarity: A Framework for Structured Mutual Understanding

**Version 0.1 — Working Document**
**Date:** January 24, 2026
**Status:** Foundational exploration; concepts under development

---

## 1. The Core Problem

Human communication is fundamentally lossy:

1. **We assume others understand us more than they do.** When we speak, we believe our meaning has transferred. It hasn't—not fully.

2. **We assume we understand others more than we do.** When we listen, we construct our own interpretation and call it "understanding." It's a guess.

3. **We don't know our own minds at 10/10.** Even the speaker doesn't fully understand what they mean until they've worked to articulate it.

4. **Hidden axioms create invisible disagreement.** People hold different foundational beliefs without knowing it. They argue about conclusions when the real gap is in premises.

5. **Current AI conversations are underutilized.** The transcript of a person talking to AI is rich signal about how they think—but it just sits there, unprocessed, unhelpful to anyone else.

## 2. The Clarity Framework

### 2.1 Core Concept

**Clarity** is a process and system for transforming raw conversation into structured, shareable understanding. It operates on the insight that understanding isn't static—it's built collaboratively, and it evolves.

### 2.2 Key Entities

| Entity | Definition |
|--------|------------|
| **Stream of consciousness** | Raw, messy input from a person—what they say before it's shaped |
| **Story** | A coherent narrative or explanation that a person wants to share, shaped through iteration |
| **Point (Axiom)** | A belief or claim that a story relies on; the foundational assumptions |
| **Understanding rating** | A 0-10 scale where the speaker rates how well the listener has captured their story |

### 2.3 The Process

```
┌─────────────────────────────────────────────────────────────────┐
│                    WITHIN A CONVERSATION                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   1. SHARE (Stream of consciousness)                            │
│      Speaker talks freely, messily, contextually                │
│                        ↓                                        │
│   2. REFLECT (AI mirrors back)                                  │
│      "Here's what I heard. Is this your story?"                 │
│                        ↓                                        │
│   3. RATE (Speaker evaluates)                                   │
│      "That's a 6/10. What's missing is..."                      │
│                        ↓                                        │
│   4. ITERATE (Repeat 2-3)                                       │
│      Until speaker says "10/10—you got it"                      │
│                        ↓                                        │
│   5. EXTRACT AXIOMS                                             │
│      "What points does this story rely on?"                     │
│      "Which ones might others disagree with?"                   │
│                        ↓                                        │
│   6. RATE AXIOMS                                                │
│      Speaker rates agreement with each point (0-10)             │
│      Iterate until each point is clear                          │
│                        ↓                                        │
│   7. PUBLISH                                                    │
│      Story + Points become an artifact others can engage with   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                    ACROSS PEOPLE                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   8. OTHERS ENGAGE                                              │
│      New person tries to understand the story                   │
│                        ↓                                        │
│   9. STORY EVOLVES                                              │
│      New person may see angles the original author didn't       │
│      "Actually, that's a better version"                        │
│                        ↓                                        │
│  10. DISAGREEMENT SURFACES                                      │
│      If they disagree with a point, ask: why?                   │
│      Usually it's because they have a different story           │
│                        ↓                                        │
│  11. RECIPROCAL UNDERSTANDING                                   │
│      Now understand *their* story                               │
│      Help them evolve it                                        │
│                        ↓                                        │
│  12. CALIBRATION                                                │
│      Both parties update:                                       │
│      - How well they understand each other                      │
│      - How strongly they hold their points                      │
│      - What version of the points they now endorse              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.4 Criteria for Good Points

Drawing from epistemology and Clarity's specific goals:

| Criterion | Source | Meaning in Clarity |
|-----------|--------|-------------------|
| **Falsifiable** | Popper | The point makes claims that could be proven wrong |
| **Hard to vary** | Deutsch | You can't easily tweak the point to explain anything; it's tightly bound to its evidence |
| **Counterfactual** | Logic | The point specifies what *wouldn't* be true if it were wrong |
| **Antifragile** | Taleb | The point gets *stronger* when attacked with genuine, understood critiques |
| **Recursively teachable** | Clarity | When you teach someone this point, they can teach others without losing fidelity |

### 2.5 What Makes AI Special Here

- **AI is a tireless listener.** It doesn't assume. It can reflect back endlessly.
- **AI has no ego.** It doesn't need to be right; it can keep asking clarifying questions.
- **AI can track structure.** It can extract axioms, identify where stories depend on contested points, and map relationships.
- **AI can mediate.** When two people have different stories, AI can help each understand the other without either losing face.

## 3. Key Concepts Explained

### 3.1 Recursive Teachability

A point is **recursively teachable** if:
1. When Person A teaches it to Person B...
2. And Person B understands it at 10/10...
3. Then Person B can teach it to Person C...
4. And Person C also reaches 10/10 understanding.

The point propagates through minds without losing fidelity. Like a meme that stays coherent instead of mutating into noise.

**Why it matters:** This is how you know a point is truly robust. It's not just "I explained it well once"—it's "this explanation survives contact with many different minds."

**Open question:** What happens when a point gets *improved* through teaching? Is that drift (bad) or evolution (good)? 

Proposed answer: If the original author would say "yes, that's what I meant, but better," it's evolution. If they'd say "no, that's a distortion," it's drift.

### 3.2 Antifragility of Points

From Taleb: Something is **antifragile** if it gets stronger from stress, volatility, and attack.

Applied to points: A point becomes more antifragile when:
- People try to attack it with well-understood counter-stories
- The point survives the attack
- Each survival strengthens confidence in the point

**Key insight:** The attack must be *understood*. A strawman attack doesn't strengthen anything. Only genuine engagement—where the attacker's story is itself understood at 10/10—counts as a real test.

### 3.3 The Role of Stories

Points don't exist in isolation. They're embedded in stories.

- A **story** gives a point its context and meaning
- People disagree on points often because they have different *stories*
- To change someone's point, you often have to engage with their story first
- Stories can become "hard to vary" themselves—tightly bound to the points they support

## 4. Situating Clarity in Existing Work

### 4.1 Related Fields

| Field | Relevance to Clarity |
|-------|---------------------|
| **Epistemic calibration** | Academic work on how people align their confidence with reality; Clarity extends this to *mutual* calibration between people |
| **Common ground theory** (Clark, 1996) | How people establish shared understanding in conversation; Clarity proposes explicit mechanisms to verify and track this |
| **Argumentation mapping** | Tools like Kialo, Argdown, Rationale that structure debates; Clarity adds the *understanding verification* layer |
| **Collective intelligence** | How groups can be smarter than individuals; Clarity focuses on the granular process of two-person understanding first |
| **Sensemaking** (Weick, Dervin) | How people make meaning from ambiguous situations; Clarity is a specific protocol for collaborative sensemaking |

### 4.2 Existing Tools and How Clarity Differs

| Tool | What it does | How Clarity differs |
|------|--------------|---------------------|
| **Kialo** | Structured debate with pro/con argument trees | Kialo doesn't verify understanding—you can add arguments without proving you understood the other side |
| **Argdown** | Markdown syntax for argument mapping | Argdown is for reconstruction, not real-time collaborative understanding |
| **Pol.is** | Finds consensus among many views | Focuses on agreement, not on ensuring each person is actually understood |
| **Roam / Notion** | Tools for thought, networked notes | Personal knowledge management, not mutual understanding verification |
| **ChatGPT / Claude** | AI conversation | Current implementations don't structure conversations toward verified understanding or extract reusable artifacts |

### 4.3 Key Intellectual Influences

| Thinker | Contribution | Relevance |
|---------|--------------|-----------|
| **Karl Popper** | Falsifiability; knowledge grows through conjecture and refutation | Points should be falsifiable; understanding grows through testing |
| **David Deutsch** | "Hard to vary" explanations; The Beginning of Infinity | Good points are hard to vary; all progress comes from good explanations |
| **Nassim Taleb** | Antifragility; things that gain from disorder | Points should get stronger from genuine attack |
| **Herbert Clark** | Grounding in communication; common ground | The theoretical foundation for why mutual understanding requires active verification |
| **Pierre Lévy** | Collective intelligence enabled by symbolic tools | The vision of shared infrastructure for distributed cognition |

## 5. Open Questions

### 5.1 Conceptual

1. **What's the smallest unit of a "point"?** Is it a proposition? A belief? A claim + its supporting structure?

2. **How do you handle irreducible disagreement?** Some disagreements are about values, not facts. Does Clarity surface these as "fundamental differences" or try to go deeper?

3. **Can stories be formalized without killing them?** Stories are how humans make meaning. They resist structure. How much can you extract without losing the essence?

4. **What's the interface?** Is Clarity a conversation protocol? A knowledge graph? A social network? All of the above?

### 5.2 Practical

5. **Who is this for first?** 
   - Individuals trying to think better with AI?
   - Pairs trying to communicate?
   - Teams trying to align?
   - Communities trying to find common ground?

6. **How do you bootstrap?** The system is most valuable with many stories and points. How do you get enough content to be useful?

7. **How do you handle bad faith?** What if someone rates understanding at 10/10 when they haven't actually understood? What if someone games the system?

8. **How does this integrate with existing tools?** Git for version control? Notion for storage? What's the minimal viable implementation?

## 6. Where to Look Next

### 6.1 Academic Literature

- **Clark, H. (1996). Using Language.** The foundational text on common ground and grounding in communication.
- **Deutsch, D. (2011). The Beginning of Infinity.** "Hard to vary" explanations; the growth of knowledge.
- **Taleb, N.N. (2012). Antifragile.** Systems that gain from disorder.
- **Weick, K. (1995). Sensemaking in Organizations.** How people collectively make meaning.
- **Mercier & Sperber (2017). The Enigma of Reason.** Argumentation as the social function of reason.

### 6.2 Tools to Study

- **Kialo (kialo.com)** — Most successful argumentation platform; study what works and what's missing
- **Argdown (argdown.org)** — Markdown for arguments; good syntax inspiration
- **Pol.is** — Consensus finding at scale; how they handle many views
- **Collective Intelligence Project (cip.org)** — Framework for CI applied to technology governance

### 6.3 Communities

- **LessWrong / Rationalist community** — Deep engagement with epistemology, calibration, Popperian ideas
- **Tools for Thought community** — People building software for thinking; Roam, Obsidian, etc.
- **Deliberative democracy researchers** — Academia working on structured public deliberation

### 6.4 Questions to Pursue

1. What does "understanding verified at 10/10" actually mean operationally? Can you test it?

2. How do existing argument mapping tools handle the "teaching" problem—ensuring people actually understand arguments, not just see them?

3. What's the equivalent of "unit tests" for understanding? How do you verify someone understood without just taking their word for it?

4. What happens in Kialo when someone adds a counter-argument that misunderstands the original argument? How is that handled?

5. Is there research on how explanations degrade as they pass through people? (Like the "telephone game" but for ideas?)

## 8. Summary

**Clarity** proposes that:

1. Understanding is not automatic—it must be actively built and verified
2. AI can serve as a patient, tireless partner in building understanding
3. The output of understanding-work should be *artifacts* (stories + points) that others can engage with
4. When others engage, understanding deepens, stories evolve, and points become more robust
5. The test of a good point is whether it survives genuine attack and can be recursively taught

**Current status:** This is a foundational exploration. The concepts feel promising but need testing. The next step is to try the protocol manually and see what breaks.
