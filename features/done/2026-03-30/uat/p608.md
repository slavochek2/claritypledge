# UAT: P608 — Magic Link Reliability (PKCE + Resend + Monitoring)

## Prerequisites
- Access to a Microsoft 365 corporate email address (for ATP test)
- Access to Brevo transactional dashboard
- Access to Mixpanel project (ClarityPledge)
- Test on production after deploy

---

## UAT-1: PKCE Flow Active

### UAT-1.1: Magic link uses PKCE code (not token)
**Given:** User is on /signup
**When:** User submits signup form with email
**Then:** The magic link URL in the email contains a `code` parameter (not `token` or `token_hash`)
**Verify:** Check email source → inspect link URL params

### UAT-1.2: Same browser completes verification
**Given:** User received magic link via PKCE
**When:** User clicks the link in the SAME browser where they signed up
**Then:** Auth callback completes, profile is created, user is redirected
**Verify:** Playwright MCP or manual browser test

### UAT-1.3: Different browser fails gracefully
**Given:** User received magic link via PKCE
**When:** User opens the link in a DIFFERENT browser (or incognito)
**Then:** Auth callback shows a clear error message (not a blank page or crash)
**Verify:** Manual — open link in incognito window

## UAT-2: Resend Button

### UAT-2.1: Resend button visible after submission
**Given:** User submitted signup form successfully
**When:** "Check Your Email" confirmation screen is shown
**Then:** A "Resend" button is visible alongside "Use Different Email"
**Verify:** E2E test `e2e/p608-signup-resend.spec.ts`

### UAT-2.2: Resend triggers new email
**Given:** User is on "Check Your Email" screen
**When:** User clicks "Resend"
**Then:** Brevo transactional logs show a second email sent to the same address
**Verify:** Click resend → check Brevo dashboard for second send record

### UAT-2.3: Resend shows success feedback
**Given:** User clicked "Resend"
**When:** Email is sent successfully
**Then:** Button shows success state (check icon + "sent" text)
**Verify:** E2E test `e2e/p608-signup-resend.spec.ts`

### UAT-2.4: Use Different Email still works
**Given:** User is on "Check Your Email" screen
**When:** User clicks "Use Different Email"
**Then:** Form resets and user can enter a new email
**Verify:** E2E test `e2e/p608-signup-resend.spec.ts`

## UAT-3: Analytics — auth_method Property

### UAT-3.1: Magic link signup tracks auth_method
**Given:** User signs up via magic link (source=signup or source=pledge)
**When:** Auth callback fires `profile_created` event
**Then:** Mixpanel event includes `auth_method: 'signup'` or `auth_method: 'pledge'`
**Verify:** Mixpanel Live View → filter `profile_created` → check properties

### UAT-3.2: Google OAuth tracks auth_method
**Given:** User signs up via Google OAuth
**When:** Auth callback fires `profile_created` event
**Then:** Mixpanel event includes `auth_method: 'google'` or equivalent
**Verify:** Mixpanel Live View → filter `profile_created` → check properties

### UAT-3.3: Login tracks auth_method
**Given:** Existing user logs in
**When:** Auth callback fires `login_complete` event
**Then:** Mixpanel event includes `auth_method` property
**Verify:** Mixpanel Live View → filter `login_complete` → check properties

## UAT-4: Microsoft 365 Domain (ATP Resilience)

### UAT-4.1: Magic link works for Microsoft 365 email
**Given:** PKCE flow is enabled
**When:** User signs up with a corporate Microsoft 365 email address
**Then:** Magic link arrives AND works when human clicks it (ATP scanner cannot consume the PKCE token)
**Verify:** Manual — use a real M365 email, check Brevo logs show delivery, click link

## UAT-5: Monitoring (Mixpanel Alert)
