## UAT-1: Letter-backed story switch preloads ratings and phase

**Given** a /live session where both participants share a completed letter (status=sealed, delivery status=completed) that covers Story X  
**And** the session is in idle state (no story selected, or after clearing the current story)  
**When** the session creator selects Story X from the picker  
**Then** the live session state immediately reflects:
  - `ratingPhase = 'explain-back'`
  - `checkerSubmitted = true`
  - `responderSubmitted = true`
  - `checkerRating` = the letter sender's prediction for Story X
  - `responderRating` = the letter receiver's listener_rating for Story X
  - `livePositionsCreator` populated with the creator's positions from the letter
  - `livePositionsJoiner` populated with the joiner's positions from the letter
**And** both participants see the explain-back screen without going through rating-capture

---

## UAT-2: No-letter story switch is a blank entry

**Given** a /live session in idle state  
**And** the two participants have no shared completed letter covering Story Y  
**When** either participant selects Story Y from the picker  
**Then** the live session state reflects:
  - `selectedStoryId = Story Y id`
  - `livePositionsCreator` populated from the database (P792 behavior)
  - `livePositionsJoiner` populated from the database (P792 behavior)
  - `ratingPhase` is NOT set to `'explain-back'` (remains `'idle'`)
  - `checkerSubmitted` and `responderSubmitted` remain `false`
  - No `checkerRating` or `responderRating` values are preloaded

---

## UAT-3: Prior /live-only story switch is a blank entry

**Given** a /live session in idle state  
**And** the two participants have previously completed a /live round on Story Z (but have no shared letter covering Story Z)  
**When** either participant selects Story Z from the picker  
**Then** the live session state reflects:
  - `selectedStoryId = Story Z id`
  - `ratingPhase` is NOT set to `'explain-back'`
  - No ratings from the prior /live round are preloaded
**And** participants begin rating-capture fresh (practice integrity preserved)

---

## UAT-4: Same letter-backed story picked twice both preload

**Given** a /live session where participants share a completed letter covering Story X  
**And** the creator selects Story X (first pick), completes or clears the round  
**When** the creator selects Story X again from the picker (second pick)  
**Then** the session preloads again with the same letter data:
  - `ratingPhase = 'explain-back'`
  - `checkerRating` and `responderRating` are the same values as the first pick
**And** no special dedup or "already preloaded" block prevents the second preload

---

## UAT-5: P733 entry-from-letter behavior unchanged (regression)

**Given** a participant opens a /live session via letter results (P733 path, `sourceLetterId` set on the session)  
**When** the session bootstrap runs  
**Then** the session enters with:
  - `ratingPhase = 'explain-back'`
  - `checkerSubmitted = true`, `responderSubmitted = true`
  - `checkerRating` and `responderRating` from the originating letter
  - `livePositionsCreator` and `livePositionsJoiner` populated
**And** this behavior is identical to pre-P827 (no regression introduced by the composeLetterPreloadState refactor)

## UAT-6: Atomic write — no mid-write visible state

**Given** a /live session in idle state  
**And** both participants are connected and watching the session's Realtime channel  
**When** a letter-backed story is selected  
**Then** the partner receives exactly one Realtime update event that includes all of:
  - `selectedStoryId`
  - `ratingPhase = 'explain-back'`
  - `checkerRating` and `responderRating`
  - `livePositionsCreator` and `livePositionsJoiner`
**And** the partner never sees an intermediate state where positions are set but `ratingPhase` is still `'idle'`
