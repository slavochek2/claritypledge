# UAT: P878 — Relationship-scoped people picker

Manual acceptance test scenarios. Run before `/ship p878`.

---

## Scenario 1: Pick a known contact on create-agreement-page

**Given** I am logged in as a user who has an active agreement with Alice

**When** I navigate to `/agreements/new` and type "Ali" (≥3 chars) into the partner field

**Then**
- A dropdown appears within ≤600ms of the last keystroke
- The dropdown shows ≤8 results
- Alice's row is visible, displaying her avatar, name, and a verified/pledged badge
- No email address is shown in any result row
- I can click Alice's row and her name appears as a chip (raw email field hides or is replaced)

---

## Scenario 2: Stranger is invisible — scope isolation confirmed

**Given** I am logged in as User A with no prior relationship to Stranger B

**When** I type "Stranger" into the partner picker on create-agreement-page

**Then**
- The empty state message appears: **"No one you've connected with matches. Enter their email to invite them."**
- No results are shown (Stranger B's name never appears)
- I am not told whether Stranger B is a platform member (account-existence oracle avoided)

---

## Scenario 3: Admin user finds a stranger (founder override)

**Given** I am logged in as the user with `is_admin = true` in the database
*(Set via DB console — never via UI)*

**When** I type any 3+ character prefix of a user I have never contacted

**Then**
- Results appear for users outside my relationship scope
- Each result shows only avatar + name + badge (no email)
- I can select them and proceed to create an agreement or letter

---

## Scenario 4: First-contact email fallback — no relationship needed

**Given** I am logged in as any user

**When** I type a full email address of someone not in my relationship scope (e.g. `alice@example.com`)

**Then**
- No crash or console error
- The existing email-entry path handles the input (lookup or invite-link flow)
- The UI either shows a "not found — invite" state or proceeds normally through the P877-safe email RPC path

---

## Scenario 5: Mobile — dropdown does not overflow (375px and 320px)

**Given** I am on a mobile device (or dev tools at 375px then 320px viewport)

**When** I open the picker and the dropdown appears

**Then**
- The dropdown fits within the email field's container horizontally — no horizontal scroll
- At 320px the dropdown still shows names without truncation that hides identity-distinguishing text
- Touch targets on each result row are ≥40px tall (tap-ability check)

---

## Scenario 6: Verified badge is visible and distinguishable

**Given** I have a contact Alice who is verified/pledged and a contact Bob who is not

**When** Both appear in the same picker dropdown

**Then**
- Alice's row shows a visible verified or pledged badge icon
- Bob's row shows no badge (or a visually distinct "unpledged" state)
- The visual difference is perceivable without color alone (icon + tooltip or label)

---

## Scenario 7: Network tab — payload contains no email

**Given** I open Chrome DevTools → Network tab and filter for `/rpc/search_profiles`

**When** I type ≥3 chars in the picker and the request fires

**Then**
- The response JSON contains result rows
- None of the rows have an `email` key
- None of the rows have a `linkedin_url` or `reason` key
- The only keys present are: `profile_id`, `name`, `slug`, `avatar_url`, `avatar_color`, `has_pledged`, `is_verified`
