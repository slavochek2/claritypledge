# P1002: Move `.finish-reviewed` stamp to a worktree-shared path

## Problem

**Situation:** `/finish` writes a code-review artifact to `.claude/.finish-reviewed`; `/ship`'s gate reads it (`ship-gates.sh` gate 2.7 / 2.7b) to prove a review ran before merge.

**Complication:** The writer and reader resolve *different* files depending on the current working directory. `ship-gates.sh:87` reads `${REPO_ROOT}/.claude/.finish-reviewed`, where `REPO_ROOT` follows the `scripts` symlink and lands in the worktree when the gate runs from a worktree — but the stamp may have been written to the main repo's `.claude`, or vice versa. Two concrete failures observed during the P992 ship this session: (1) a `/finish`-in-worktree followed by a ship gate reported `.finish-reviewed not found` because the two resolved different `.claude` dirs; (2) the shared main-repo copy is a single unversioned file that a co-tenant session clobbers, so gate 2.7 flip-flopped PASS→FAIL between two runs seconds apart.

**Question:** How do we make one `.finish-reviewed` authoritative across the main repo and every worktree, so the writer and the gate can never disagree and co-tenants can't race it?

## Appetite

Low blast radius (one stamp file, four call sites, no product code). Fully reversible (revert the path resolution to `${REPO_ROOT}/.claude`). Zero decision density — the pattern is already settled: P950 moved `.privacy-reviewed` to `git-common-dir` for this exact reason (`git-ops.sh:2528`, `2767`), and this applies the same resolution to a second stamp.

## Solution

Resolve `.finish-reviewed` via `git rev-parse --git-common-dir` (which points at the main repo's `.git` from any worktree) in every place that touches it, mirroring how `.privacy-reviewed` is already resolved:

- **Reader:** `ship-gates.sh` gate 2.7 / 2.7b (`finish_file=...`).
- **Writers:** `/finish` step 6, `/dev` step 9.5a, `/fix` QA-gate stamp write.

All four must derive the same shared path. Pick one canonical location (either `<git-common-dir>/.finish-reviewed` to match `.privacy-reviewed`'s placement, or a shared `.claude/` under the common dir) and use it everywhere. The `.gitignore` entry, if any, moves with it.

**Verify the fix fires (epistemic gate 7):** before closing, run `/finish` from a worktree, then run `ship-gates.sh` from both the worktree and the main repo and confirm gate 2.7 reads the same stamp (PASS) in both — the current bug is precisely that it does not.

## Risks / Non-Goals

### Risks
- **Stale stamp across unrelated features.** A single shared stamp could let feature B's ship read feature A's review artifact. Mitigation: gate 2.7b already checks the stamp's freshness against the latest branch commit; keep that check and confirm it still discriminates per-branch after the path change. If it doesn't, the stamp must carry a branch/SHA discriminator (as `.privacy-reviewed` does via `merge-base --is-ancestor`).
- **Missed writer.** If one of the three writers isn't updated, it writes to the old per-worktree path and the gate silently never sees it. Mitigation: grep `finish-reviewed` across `scripts/` and `.claude/commands/` and confirm every read and write is converted in the same change.

### Non-Goals
- Do NOT change what gate 2.7 / 2.7b *check* (entry presence, freshness) — only *where the file lives*.
- Do NOT touch `.privacy-reviewed` — it already uses the shared path; this spec brings `.finish-reviewed` into line, not the reverse.
- Do NOT add a new stamp format or JSON schema change — the JSON-lines content is unchanged.

### Alternatives Considered
- **Make `ship-gates.sh` check both the worktree and main-repo `.claude`.** Rejected: papers over the split-brain instead of removing it, and still leaves two files that can disagree on freshness. The shared-path fix removes the second file entirely.
- **Leave as-is, document the gotcha.** Rejected: the failure is silent (a "not found" that looks like "review never ran") and recurs on every cross-boundary finish→ship, which is the common worktree flow.

### Rollback Strategy
Revert the path-resolution change in `ship-gates.sh` and the three skill files back to `${REPO_ROOT}/.claude/.finish-reviewed`. Single-line change per site; no data migration (the stamp is regenerated by the next `/finish`).
