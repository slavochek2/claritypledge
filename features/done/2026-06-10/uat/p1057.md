## Finding (not a blocker) — a fail-open in `getOpenInviteForSender`

`api.ts:4415` — `if (!code) return null;`. The function's contract is "is there an open invite?",
and it now answers **no** when the invite exists but its code could not be resolved. Its sibling
`getOpenLiveInviteForUser` handles the same case as `code: inviteCode ?? ''`, keeping presence
and code-knowledge separate. Consequence if it ever fires: the "Start a clarity session" guard
opens and a second session can be created against an outstanding invite.

Not currently reachable in the happy path — the probe returned a real code for both authorized
principals — and the `?? ''` alternative has its own failure mode (`navigate('/live/')`). Flagged
for `/fix`, deliberately **not** changed during `/verify`.
