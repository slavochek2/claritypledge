## UAT-1: Edit story — happy path

### UAT-1.1: Edit and Delete buttons appear for the author only
**Given:** Author is logged in and on their own story detail page (`/story/:id`)
**When:** Page loads
**Then:** "Edit" and "Delete" buttons appear below the story card, right-aligned on the same row as the Visibility selector
**Verify:** `mcp__claude-in-chrome__read_page` — confirm Edit and Delete buttons visible; open the same story as a different user (or logged-out) and confirm buttons are absent

### UAT-1.2: Clicking Edit opens textarea pre-filled with story content
**Given:** Author is on their own story detail page
**When:** Author clicks "Edit"
**Then:** The story card body is replaced by a textarea pre-filled with the current story content; card border turns blue; textarea receives focus automatically; Save and Cancel buttons appear below; character count shows `N / 10000`
**Verify:** `mcp__claude-in-chrome__click` on "Edit" → confirm textarea visible, pre-filled, focused; blue border present; char count showing

### UAT-1.3: Saving updated content persists and exits edit mode
**Given:** Edit mode is active
**When:** Author modifies the story text and clicks "Save"
**Then:** "Saving…" spinner visible on button; on success, textarea replaced with updated text, toast "Story updated" appears, edit mode exits; Edit and Delete buttons return
**Verify:** `mcp__claude-in-chrome__fill` textarea with new text → `mcp__claude-in-chrome__click` Save → confirm toast and updated content shown

### UAT-1.4: Cmd+Enter submits the edit form
**Given:** Edit mode is active with non-empty content
**When:** Author presses Cmd+Enter (Mac) or Ctrl+Enter (Windows)
**Then:** Story saves with the same outcome as clicking Save
**Verify:** `mcp__claude-in-chrome__fill` → keyboard shortcut → confirm save behaviour matches UAT-1.3

### UAT-1.5: Visibility selector still works while NOT in edit mode
**Given:** Author is on the story detail page (not in edit mode)
**When:** Author changes visibility using the selector
**Then:** Visibility updates as before (P424 regression check — P427 must not break this)
**Verify:** Change visibility to Private → confirm change persists on reload

## UAT-2: Edit story — cancel and edge cases

### UAT-2.1: Cancel discards changes silently
**Given:** Edit mode is active; author has typed unsaved changes
**When:** Author clicks "Cancel"
**Then:** Edit mode exits immediately; original story content restored; no toast; no confirmation dialog
**Verify:** `mcp__claude-in-chrome__fill` with different text → Cancel → confirm original content restored, no confirmation shown

### UAT-2.2: Pressing Escape cancels edit mode
**Given:** Edit mode is active
**When:** Author presses Escape
**Then:** Same as clicking Cancel — edit mode exits, original content restored
**Verify:** `mcp__claude-in-chrome__shortcuts_execute` Escape → confirm edit mode exited

### UAT-2.3: Save is disabled for empty content
**Given:** Edit mode is active; textarea has been cleared
**When:** Author clears all text
**Then:** Save button becomes disabled; tooltip "Story can't be empty" shown on hover
**Verify:** Clear textarea → hover Save → confirm disabled state and tooltip

### UAT-2.4: Unsaved changes guard blocks SPA navigation
**Given:** Edit mode is active with unsaved changes (content modified from original)
**When:** Author clicks the Back button or navigates to another page
**Then:** An inline prompt appears: "You have unsaved changes. Leave anyway?" with "Stay" (focused) and "Leave" buttons
**Verify:** Modify content → click Back → confirm prompt appears; click "Stay" → confirm still on story page in edit mode

## UAT-3: Delete story — happy path

### UAT-3.1: Delete opens confirmation dialog
**Given:** Author is on their own story detail page
**When:** Author clicks "Delete"
**Then:** Dialog opens with title "Delete this story?"; body text explains story is permanently removed but linked points are not; footer has "Cancel" (outline, focused) and "Delete story" (red/destructive)
**Verify:** `mcp__claude-in-chrome__click` Delete → confirm dialog visible with correct text

### UAT-3.2: Dialog shows linked point count for stories with linked points
**Given:** The story has N linked points (N > 0)
**When:** Author opens the delete confirmation dialog
**Then:** Dialog body includes "This story has N linked point(s)."
**Verify:** Use a story that has linked points → open delete dialog → confirm count line present

### UAT-3.3: Confirming delete navigates to profile with success toast
**Given:** Delete confirmation dialog is open
**When:** Author clicks "Delete story" (red button)
**Then:** "Deleting…" spinner visible on button, both buttons disabled; on success, dialog closes, user navigated to `/p/:authorSlug`, toast "Story deleted" appears
**Verify:** `mcp__claude-in-chrome__click` "Delete story" → confirm redirect to profile, toast shown, story no longer accessible at `/story/:id`

## UAT-4: Delete story — cancel flows

### UAT-4.1: Cancel on dialog closes dialog without deleting story
**Given:** Delete confirmation dialog is open
**When:** Author clicks "Cancel"
**Then:** Dialog closes, user remains on story page, story is unchanged
**Verify:** Click Cancel → confirm dialog closed, story content still visible, URL unchanged

### UAT-4.2: Pressing Escape closes the dialog
**Given:** Delete confirmation dialog is open
**When:** Author presses Escape
**Then:** Same as clicking Cancel
**Verify:** `mcp__claude-in-chrome__shortcuts_execute` Escape → confirm dialog closed, story unchanged

### UAT-4.3: Non-author cannot reach delete via URL manipulation
**Given:** A non-author user knows the story ID
**When:** Non-author navigates to `/story/:id` (the story is public or shared)
**Then:** Delete and Edit buttons are not present; RLS at the DB level prevents any mutation even if attempted programmatically
**Verify:** Log in as a different user, navigate to the story → confirm no Edit/Delete buttons visible
