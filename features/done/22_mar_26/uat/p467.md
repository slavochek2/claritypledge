- **Re-verified 2026-03-04:** 48.54px (min-h-[48px], py-2) — CSS changed from `py-3 h-11` to `min-h-[48px] py-2`
- **Result:** PASS (≤52px)

### ISSUE-2: ~~Rating button tap targets 38px tall — below 44px spec requirement~~ — FIXED ✅
- **Original measure:** 38px
- **Re-verified 2026-03-04:** 43.99px (min-h-[44px] py-2.5) — `min-h-[44px]` added
- **Result:** PASS (≥44px, sub-pixel rounding of exactly 44px)

### ISSUE-3: 406 console error on every chat page load
- **URL:** `https://gfjctyxqlwexxwsmkakq.supabase.co/rest/v1/story_points?select=story_id%2Cstories%28...%29&author_id=...&point_id=...&limit=1`
- **Error:** HTTP 406 Not Acceptable
- **Context:** Fired during `getStoryByUserAndPoint()` check for P465 edit mode detection
- **Impact:** Non-blocking (chat functions normally), but error appears on every load

### ISSUE-4: Restored session shows 2nd rating bubble buttons disabled with no "Save as-is →"
- **What happens:** After navigating away and back, sessionStorage-persisted state shows 2nd rating bubble with all buttons disabled (as if submitted) and "Save as-is →" absent, even though no 2nd rating was submitted in that load
- **Root cause:** Phase appears to restore correctly, but the active (non-submitted) rating bubble's interactive state is not correctly re-established
- **Impact:** Users who navigate away mid-flow may get a stuck state

### ISSUE-5: Rating button selected state never visually highlights after click
- **What happens:** After clicking a rating button, none of the 11 buttons show the selected (blue-filled, `ring-2`) visual state — all appear identical/faded at `opacity-50`
- **Root cause:** In `StoryGuideChat.tsx` `handleInlineRatingSelect()` (line 611 and 621), `setRatingValue(value)` is called and then `setRatingValue(null)` is called synchronously in the same callback. React batches these state updates — net result is `null`, so the `selectedValue === option.value` check in `RatingButtons` never renders the highlight class
- **Fix:** Remove `setRatingValue(null)` on line 621. The `frozenRatingId` state already prevents re-interaction. If a fresh state is needed for iteration 2, reset `ratingValue` when the *next* rating message is added (not immediately after the click)
- **Severity:** Visual only — functionality works (rating is sent correctly), but user gets no confirmation of which button they pressed
- **File:** `src/app/components/story-guide/StoryGuideChat.tsx`, lines 609-622
