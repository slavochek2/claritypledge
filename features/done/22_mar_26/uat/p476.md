## UAT-1: Full Unauthenticated Flow — Confirmation Page Appears

**Setup:** Open a private/incognito browser window. Navigate to `/agreements/:id/accept?token=...` where `:id` is a pending agreement ID and `token` is a valid invitation token.

**Steps:**
1. Observe the accept page — the certificate and "Seal & Create Account" button should be visible
2. Enter a name in the name field (pre-filled is OK)
3. Click "Seal & Create Account"
4. Observe what happens next

**Expected:**
- A full-screen email confirmation view appears — NOT a small inline message inside the certificate footer
- The confirmation view occupies the full viewport, similar to `/sign-pledge/confirm`
- The old "Check your email" message with a MailCheckIcon inside the certificate footer does NOT appear

**Verify:**
- Full-screen orientation visible — icon, heading, email displayed prominently, resend section
- No inline text inside the certificate footer saying "We sent a sign-in link to [email]"
- URL has changed (if a dedicated route was added) OR the certificate is no longer the main visible content

## UAT-2: Confirmation Page Copy Is Agreement-Specific

**Setup:** Continue from UAT-1 (on the confirmation page after OTP sent)

**Expected:**
- Copy says something like "complete signing the Clarity Partner Agreement" — NOT "complete your pledge"
- Copy does not mention "pledge" or "public profile"
- Heading says "Almost Done!" or equivalent (referring to completing the agreement)

**Verify:**
- Read all visible text on the confirmation page
- Confirm absence of the word "pledge" in any instruction or explanation text
- Confirm presence of "agreement", "signing", or equivalent agreement context

## UAT-3: Resend Button Sends New Email and Shows Success State

**Setup:** Continue from UAT-1 (on the confirmation page)

**Steps:**
1. Find the "Resend sign-in link" button or equivalent
2. Click it
3. Observe the UI response

**Expected:**
- A new OTP email is sent to the partner's invitation email
- The button shows a success state: "New link sent!" or equivalent
- The button is temporarily disabled (to prevent spam)
- The `localStorage` key `clarity-pending-accept-${agreementId}` is present (can verify in DevTools → Application → Local Storage)
- The resent link, when clicked, returns the partner to the accept page (not to `/`)

**Verify:**
- Success message visible after clicking resend
- Button disabled or replaced with success indicator
- In DevTools: Application → Local Storage → check `clarity-pending-accept-${agreementId}` key exists
