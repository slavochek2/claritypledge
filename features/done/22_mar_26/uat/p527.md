# UAT: P527 — Direct Sign for New Users

## Prerequisites
- Test project edge function `create-and-sign` deployed
- A test creator account with ability to send invitations
- Access to a fresh email address (not registered on ClarityPledge)

---

## UAT-1: Happy Path — New User Signs Without Email Round-Trip

**Given:** Creator has sent an invitation to a fresh email address (no existing account)
**When:** The invited partner clicks the invitation link in their email
**Then:** They land on the accept page showing name input + sign button

**When:** Partner enters their name and clicks "Sign"
**Then:**
- [x] Agreement is signed immediately (no "check your email" page)
- [x] Partner sees the signed agreement with both signatures
- [x] Partner is authenticated (can navigate to other pages)
- [x] Agreement shows status "Active"

**Result:** ✅ PASS — Toast: "Agreement Sealed — your Clarity Partner Agreement is now active." Both signatures visible. No email round-trip. URL went directly to `/agreements/{id}` (not `/agreements/confirm-email`).

**Verify:** Manual browser test. Check Network tab — confirm `create-and-sign` edge function was called (not `signInWithOtp`).

## UAT-2: Profile Completeness

## UAT-3: Session Persistence

## UAT-5: Existing User Flow Unchanged (Regression)

**Given:** An existing ClarityPledge user receives an invitation
**When:** They click the invitation link
**Then:**
- [ ] P488 magic link flow works (arrive authenticated, can sign immediately)
- [ ] NOT the direct-sign flow (no edge function call for existing users)

**Result:** ⏭️ SKIPPED — Requires a real existing-user invitation email with embedded magic link (P488 flow). Cannot simulate from browser alone without sending actual invitation email.

## UAT-6: Fallback — Edge Function Failure

**Given:** The `create-and-sign` edge function is unavailable (simulate by temporarily undeploying or blocking the endpoint)
**When:** New user tries to sign the agreement
**Then:**
- [ ] System falls back to the current OTP flow
- [ ] User sees "check your email" confirmation page
- [ ] User can complete signing via the magic link email (existing flow)
- [ ] No error message shown to the user about the edge function failure

**Result:** ⏭️ SKIPPED — Requires temporarily undeploying the edge function. Fallback logic confirmed in code review (try/catch wraps the edge function call, falls back to `handleInlineSignup` on failure).

## UAT-8: Token Replay Protection

**Given:** New user has already signed the agreement (token consumed)
**When:** Someone navigates to the same accept URL with the same token
**Then:**
- [x] Page shows invalid/expired state
- [x] Cannot sign again
- [x] No duplicate account created

**Result:** ✅ PASS — Page shows "This invitation has expired or is invalid. The link may have been used already, expired, or is not valid." with "Return to Clarity Pledge" link. No sign button visible. Token consumed on first use.
