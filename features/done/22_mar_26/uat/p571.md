# UAT: P571 — Hide test accounts from pledgers

## Prerequisites
- Migration applied to test DB (`./scripts/migrate.sh`)
- `founder's personal account` flagged via Supabase dashboard
- Dev server running (`npm run dev`)

---

### UAT-1: Test accounts hidden from /pledgers

**Given:** `e2e-agent@claritypledge.com` and `founder's personal account` have `is_test_account = true`
**When:** Visit `/pledgers` page
**Then:** Neither "E2E Agent" nor Slava's profile card appears in the listing
**Verify:** Visual check in browser — count cards, confirm no test accounts

### UAT-2: Pledger count excludes test accounts

**Given:** Same as UAT-1
**When:** Check any display of pledger count (landing page hero number, etc.)
**Then:** Count matches the number of visible cards on `/pledgers` (test accounts not counted)
**Verify:** Compare count number with actual card count

### UAT-3: Test accounts still functional

**Given:** `e2e-agent@claritypledge.com` has `is_test_account = true`
**When:** Run E2E test suite (`npm run test:e2e`)
**Then:** All existing tests pass — test account can still authenticate, create sessions, take positions
**Verify:** `npm run test:e2e` — all green

### UAT-4: RLS prevents self-clearing

**Given:** A test account user is authenticated
**When:** Direct REST PATCH to profiles with `{ is_test_account: false }`
**Then:** Request is rejected by RLS WITH CHECK policy
**Verify:** Integration test `p571-is-test-account-migration.spec.ts` test 3

### UAT-5: Real users unaffected

**Given:** A real user profile (not test account)
**When:** User updates their profile (name, role, reason, etc.)
**Then:** Update succeeds — WITH CHECK does not block normal profile edits
**Verify:** Sign in as real user, update profile, confirm changes saved
