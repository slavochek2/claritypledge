# UAT: P588 — /live Layout: Sticky CTA, Accordion Story, Peek Points

## BottomNav & Exit Affordance

### UAT-1.1: BottomNav hidden on /live
**Given:** User is in an active /live session (any phase)
**When:** Page renders on mobile viewport (375px)
**Then:** The global BottomNav (Home, Stories, etc.) is NOT visible at the bottom of the screen
**Then:** ~98px of viewport space is recovered compared to the current layout
**Verify:** Visual inspection on mobile. Check `bottom-nav.tsx` — `/live` is in `focusRoutes` array. Playwright: assert `[data-testid="bottom-nav"]` is not visible on `/live`.

### UAT-1.2: BottomNav still visible on non-/live routes
**Given:** User navigates to `/home`, `/stories`, `/profile`, or any route outside `/live`
**When:** Page renders
**Then:** BottomNav is visible as before
**Verify:** Visual inspection. Navigate away from /live and confirm BottomNav returns.

### UAT-2.1: End Session button red filled
**Given:** User is in an active /live session
**When:** Header bar renders
**Then:** "End Session" button is red filled (`bg-red-500 text-white`) — not outline, not ghost
**Then:** Button is clearly visible as the primary exit affordance
**Verify:** Visual inspection. Browser devtools: inspect computed styles on the End Session button — background-color is red-500 (#ef4444), text is white.

## Sticky CTA Bar

### UAT-3.1: CTA always visible (sticky positioning)
**Given:** User is in a /live phase that renders ActionArea (idle, waiting, gap-revealed, calibrated, explain-back, results)
**When:** Page loads and content fills the viewport
**Then:** CTA buttons (primary + "Speak freely") are pinned to the bottom of the viewport
**Then:** CTA buttons do not scroll with the content — they remain fixed in place
**Verify:** Visual inspection on 375px mobile. Scroll content up and down — CTA bar stays at bottom. Playwright: assert CTA buttons are within viewport bounds at all scroll positions.

### UAT-3.2: CTA bar not shown on perfect celebration phase
**Given:** Checker rated partner 10 and the "perfect" celebration phase renders
**When:** Page shows celebration screen
**Then:** Sticky CTA bar is NOT rendered — "Continue" button is inline, centered
**Verify:** Visual inspection during perfect phase.

### UAT-4.1: CTA visible with 0 points
**Given:** Story has 0 linked points (no "N points" toggle shown)
**When:** Page renders in gap-revealed or calibrated phase
**Then:** CTA buttons are visible at viewport bottom without scrolling
**Verify:** Visual inspection with a 0-point story on 375px viewport.

### UAT-4.2: CTA visible with 2 points expanded
**Given:** Story has 2 linked points; user expands the points list
**When:** 2 point peek previews are shown
**Then:** CTA buttons remain pinned at viewport bottom, fully tappable
**Then:** Content area scrolls independently behind the sticky bar if needed
**Verify:** Visual inspection on 375px. Expand 2 points — CTA stays visible.

### UAT-4.3: CTA visible with 5+ points expanded
**Given:** Story has 5+ linked points; user expands the points list
**When:** 5 point peek previews are shown (each ~48px)
**Then:** CTA buttons remain pinned at viewport bottom
**Then:** Content area scrolls to accommodate all point previews
**Verify:** Visual inspection on 375px with 5+ points. Scroll through points — CTA always visible. This is the worst-case scenario from the spec.

## Journey + Calibration Layout

### UAT-5.1: No gap between Journey and Calibration
**Given:** User is in a phase where both Journey card and Calibration banner render (gap-revealed, calibrated)
**When:** Page renders
**Then:** Calibration banner appears directly below the Journey card with no visible gap (0px margin between them)
**Then:** Calibration banner is ABOVE the story card (not below it as in P469)
**Verify:** Visual inspection. Browser devtools: inspect margin/padding between Journey card bottom and Calibration banner top — should be 0 or minimal (no ~24px gap).

### UAT-5.2: Calibration not shown before results exist
**Given:** User is in waiting or explain-back phase (no calibration data yet)
**When:** Page renders
**Then:** Only Journey card is shown — no Calibration banner
**Verify:** Visual inspection during waiting phase.

## Accordion Behavior

### UAT-6.1: Story collapses when points expand
**Given:** Story text is fully expanded (user tapped "Show more")
**When:** User taps the "N points" toggle to expand the points list
**Then:** Story text auto-collapses to truncated state (first ~100 chars + "Show more")
**Then:** Points list expands showing peek previews
**Verify:** Visual inspection. Expand story text -> tap "N points" -> story collapses, points appear.

### UAT-6.2: Points collapse when story expands
**Given:** Points list is expanded (showing peek previews or one expanded point)
**When:** User taps "Show more" on the story text
**Then:** Points list collapses back to "N points" summary line
**Then:** Story text fully expands
**Verify:** Visual inspection. Expand points -> tap "Show more" -> points collapse, full story visible.

### UAT-6.3: Default state on page load
**Given:** User enters a /live phase with a story that has linked points
**When:** Page loads (initial render)
**Then:** Story text is truncated (existing behavior, ~100 chars)
**Then:** Points are collapsed ("N points" summary)
**Then:** No accordion conflict — both sections are in their default collapsed state
**Verify:** Visual inspection on fresh page load. Both sections collapsed.

### UAT-6.4: Accordion state resets on phase transition
**Given:** User has expanded points in the gap-revealed phase
**When:** Phase transitions (e.g., gap-revealed to explain-back)
**Then:** Accordion resets to default state (story truncated, points collapsed)
**Verify:** Expand points in one phase -> trigger phase transition -> verify both sections reset.

## Point Peek Previews

### UAT-7.1: 2-line peek preview for each point
**Given:** Points list is expanded on a story with 2+ linked points
**When:** Peek previews render
**Then:** Each point shows exactly 2 lines: (1) author name + stance badge, (2) first line of position text, truncated
**Then:** No point shows full position text in the collapsed peek state
**Verify:** Visual inspection. Check that each point card is ~2 lines tall. Browser devtools: verify text-overflow/line-clamp.

### UAT-7.2: Point peek shows author and stance
**Given:** Points list is expanded
**When:** Peek previews render
**Then:** Each preview shows the point author's name and their stance badge (Agrees, Disagrees, Neutral, etc.)
**Verify:** Visual inspection — author name and stance visible on line 1 of each peek card.

## One Point Expanded at a Time

### UAT-8.1: Expanding one point collapses the previous
**Given:** Points list is expanded; user taps point A to expand it fully
**When:** User taps point B (a different point)
**Then:** Point A collapses back to 2-line peek preview
**Then:** Point B expands to show full position text + tags
**Verify:** Visual inspection. Expand point A -> tap point B -> A is collapsed, B is expanded.

### UAT-8.2: Tapping expanded point collapses it
**Given:** Point A is fully expanded
**When:** User taps point A again
**Then:** Point A collapses to 2-line peek preview
**Then:** All points are now in peek mode (none expanded)
**Verify:** Visual inspection. Expand a point -> tap it again -> all points in peek mode.

### UAT-8.3: Expanded point shows full content
**Given:** User taps a point peek to expand it
**When:** Point expands
**Then:** Full position text is visible (not truncated)
**Then:** Tags are visible below the position text
**Then:** PositionButtons rendered in disabled/view-only state
**Verify:** Visual inspection. Compare expanded point content to the point's data in the database.

## Scrolling & Spacing

### UAT-9.1: Content scrolls freely
**Given:** Content area (journey + calibration + story + expanded points) exceeds viewport height minus sticky bar
**When:** User scrolls
**Then:** Content area scrolls smoothly and freely
**Then:** Sticky CTA bar does not move — only content behind it scrolls
**Verify:** Visual inspection on 375px mobile with enough content to require scrolling.

### UAT-10.1: Bottom padding prevents content hidden behind sticky bar
**Given:** Content extends to the bottom of the scroll area
**When:** User scrolls to the very bottom
**Then:** The last content element (bottom of story card or last point) is fully visible above the sticky CTA bar
**Then:** No content is clipped or hidden behind the sticky bar
**Verify:** Visual inspection. Scroll to bottom — last element fully readable. Browser devtools: verify padding-bottom on scroll container matches or exceeds sticky bar height.

### UAT-11.1: iOS Safari safe-area handled
**Given:** User is on an iPhone with a home indicator (iPhone X and later)
**When:** /live page renders with sticky CTA bar
**Then:** Sticky CTA bar includes safe-area padding at the bottom (`env(safe-area-inset-bottom)`)
**Then:** CTA buttons are not obscured by the home indicator
**Verify:** Visual inspection on iOS Safari (physical device or simulator). Browser devtools: inspect sticky bar — `padding-bottom` includes `env(safe-area-inset-bottom)`.
