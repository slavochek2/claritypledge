## AC-1: Auto-badge on certifier 10/10 with #understanding story

**Given** a /live free-mode session where the host (`is_certifier = true`) is the speaker  
**And** the story is linked to a point that has `understanding` in `system_tags`  
**And** both sliders reach 10/10  
**And** the listener is a logged-in user with an `agree` position on the point  
**When** the round completes  
**Then** a `badge_points` row is inserted for the listener  
**And** the celebration screen shows "Badge point earned! N/9 verified" as the primary headline

---

## AC-2: No badge when non-certifier is speaker

**Given** a /live free-mode session where the speaker does NOT have `is_certifier = true`  
**And** all other preconditions pass (10/10, #understanding point, listener has agree)  
**When** the round completes  
**Then** no `badge_points` row is inserted  
**And** the celebration screen shows the standard message only (no badge headline)

---

## AC-3: No badge for guest (not logged in) listeners

**Given** a /live free-mode session with a certifier as speaker  
**And** the listener has not authenticated (guest/anonymous)  
**And** both reach 10/10 on an #understanding-tagged point  
**When** the round completes  
**Then** no `badge_points` row is inserted (guests cannot earn badge points)  
**And** the celebration screen shows the standard message only

---

## AC-4: No badge when listener position is missing, disagree, or somewhat_agree

**Given** a /live free-mode session where the certifier is speaker  
**And** both reach 10/10 on an #understanding-tagged point  
**But** the listener has NOT filed a position, OR has `somewhat_agree`, `disagree`, or `strongly_disagree`  
**When** the round completes  
**Then** no `badge_points` row is inserted (silent skip — no error, no prompt)  
**And** the celebration screen shows the standard message only

---

## AC-5: Duplicate badge point is silently ignored

**Given** a listener already has a `badge_points` row for a given `(user_id, point_id)`  
**When** a second certification round completes with the same point  
**Then** no additional `badge_points` row is created (UNIQUE constraint, ON CONFLICT DO NOTHING)  
**And** the celebration screen shows the standard message only (no badge headline for the duplicate)

---

## AC-6: Celebration screen upgrades when badge point earned

**Given** a badge point was earned in the current round (AC-1 conditions met)  
**When** the celebration screen renders  
**Then** "Badge point earned!" is the primary headline  
**And** "N/9 clarity points verified" appears as subtitle  
**And** the standard celebration text ("You understood [name] perfectly!") appears below  
**And** the continue button and journey box are unchanged

---

## AC-7: Profile immediately shows ✓ and "See their badge (N/9)" after earning

**Given** a user has earned at least 1 badge point  
**When** a visitor navigates to `/p/:slug`  
**Then** a ✓ checkmark icon appears on the user's avatar (bottom-right position)  
**And** a "See their badge (N/9)" link appears in the profile navigation cluster  
**And** both the checkmark and the link navigate to `/p/:slug/badge`

---

## AC-8: Badge certificate shows correct progress, point titles, and dates

**Given** a user has N badge points (where 1 ≤ N ≤ 9)  
**When** a visitor navigates to `/p/:slug/badge`  
**Then** the page shows "CLARITY BADGE" heading  
**And** a progress bar displays N/9  
**And** each verified point shows its title and the date it was verified  
**And** unverified points (9 - N of them) are listed without dates, visually distinct (muted)  
**And** the certifier's name is shown as a link to their profile  
**And** each verified point title links to its `/point/:id` page

---

## AC-9: Badge certificate is shareable (link, social, image export)

**Given** the owner views their badge certificate at `/p/:slug/badge`  
**When** they open the share dropdown  
**Then** "Copy link", LinkedIn, WhatsApp, and "Export as image" options are available  
**And** copying the link puts the `/p/:slug/badge` URL on the clipboard  
**And** the image export renders a shareable image with name, progress bar, verifier, and date

---

## AC-10: Visitor to badge certificate sees "Join the next Clarity Workshop" CTA

**Given** a visitor (not the profile owner) views `/p/:slug/badge`  
**When** the page loads  
**Then** a CTA card appears below the certificate with "Join the next Clarity Workshop"  
**And** clicking it navigates to the events page on claritypledge.com  
**And** no owner share controls (copy link, export) are visible

---

## AC-11: Badge certificate publicly viewable without login

**Given** a user has badge points  
**When** an anonymous visitor navigates to `/p/:slug/badge`  
**Then** the page renders fully (progress, points, certifier, dates)  
**And** no auth gate or login wall is shown  
**And** the "Join the next Clarity Workshop" CTA is displayed

---

## AC-12: Profile correctly displays badge-only, pledge-only, and both states

| User state | Avatar | Navigation cluster |
|------------|--------|-------------------|
| Neither | No ring, no checkmark | No badge/pledge links |
| Badge only | ✓ checkmark at bottom-right | "See their badge (N/9)" |
| Pledge only | Blue ring | "See their pledge" |
| Both | Blue ring + ✓ checkmark | "See their pledge" · "See their badge (N/9)" |

**Given** a user whose profile matches each of the four states above  
**When** a visitor navigates to `/p/:slug`  
**Then** the avatar and navigation cluster match the table above exactly  
**And** when both badge and pledge are present, both indicators coexist without overlap  
**And** at small avatar sizes (40×40px), the checkmark remains visible at minimum 16×16px
