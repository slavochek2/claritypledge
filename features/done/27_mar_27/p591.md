# UAT: P591 — Story Supporting Images

## Image Upload During Story Creation

### UAT-1: Add image to new story
**Given:** Authenticated user navigates to `/create`
**When:** Page loads
**Then:** "Add image" button visible below textarea, above "Publish Story" button
**Then:** Button has ghost style with image icon and "(optional)" sublabel
**Verify:** Navigate to `/create` as authenticated user. "Add image" button visible in correct position.

### UAT-2: Upload JPEG image during creation
**Given:** User is on `/create` and clicks "Add image"
**When:** Native file picker opens and user selects a JPEG photo (< 5MB)
**Then:** Image preview appears inline replacing the "Add image" button
**Then:** Progress spinner shows during upload, then disappears on completion
**Then:** "Change image" and "Remove" links appear below preview
**When:** User clicks "Publish Story"
**Then:** Story detail page shows the uploaded image below title, above story text
**Verify:** Upload JPEG -> preview visible -> publish -> image visible on detail page.

### UAT-3: Upload HEIC image (iPhone photo)
**Given:** User is on `/create` and clicks "Add image"
**When:** User selects an HEIC file from iPhone camera roll
**Then:** HEIC is silently converted to JPEG (no error, no user message)
**Then:** Image preview appears normally
**When:** User publishes story
**Then:** Image displays correctly on detail page as JPEG
**Verify:** Upload .heic file -> silent conversion -> preview -> publish -> visible as JPEG.

### UAT-4: Upload large image (>1200px)
**Given:** User selects a 4000x3000 JPEG image
**When:** Image is processed client-side
**Then:** Image is resized to 1200x900 (longest edge = 1200px)
**Then:** Upload completes normally, preview shows resized image
**Verify:** Check network tab — uploaded file should be significantly smaller than original. Image dimensions should not exceed 1200px.

### UAT-5: Remove image before publishing
**Given:** User has selected and uploaded an image preview on `/create`
**When:** User clicks "Remove" (X) on the preview
**Then:** Image preview disappears, "Add image" button reappears
**When:** User publishes the story
**Then:** Story is saved as text-only (no image on detail page)
**Verify:** Upload image -> remove -> publish -> no image on detail page.

### UAT-6: Publish story without image (feature doesn't break existing flow)
**Given:** User is on `/create` with story text written
**When:** User does NOT click "Add image" and clicks "Publish Story" directly
**Then:** Story saves normally as text-only, matching existing behavior exactly
**Verify:** Create story ignoring "Add image" button -> story works normally.

## Image on Existing Stories

### UAT-7: Add image to existing story (no image)
**Given:** Author views their own story on `/story/:id` that has no image
**When:** Author clicks "Add image" in author controls area
**Then:** File picker opens, same upload flow as creation
**When:** Upload completes
**Then:** Image appears on story detail page below title
**Verify:** Existing story -> add image -> image visible immediately.

### UAT-8: Replace image on existing story
**Given:** Author views their own story that already has an image
**When:** Author hovers over image (desktop) or sees controls below image (mobile)
**Then:** "Change image" and "Remove image" controls visible
**When:** Author clicks "Change image" and selects a new file
**Then:** During upload, OLD image remains visible (atomic replacement per spec)
**Then:** On success, new image replaces old image
**Verify:** Change image -> old stays during upload -> new replaces on success.

### UAT-9: Remove image from existing story
**Given:** Author views their story with an image
**When:** Author clicks "Remove image"
**Then:** Image disappears immediately from UI
**Then:** Toast "Image removed" appears with "Undo" action (5 seconds)
**Then:** If author clicks "Undo" within 5 seconds, image is restored
**Then:** After 5 seconds, removal is persisted to DB
**Verify:** Remove -> undo toast -> undo within 5s restores. Remove -> wait 5s -> image gone on refresh.

### UAT-10: Replace image failure (network drop)
**Given:** Author clicks "Change image" and new upload begins
**When:** Network drops mid-upload
**Then:** Toast: "Upload failed. Please try again."
**Then:** Old image remains unchanged (not lost)
**Verify:** Simulate offline during replacement -> error toast -> old image preserved.

## Reader Experience

### UAT-11: View story with image
**Given:** Any user (authenticated or anonymous) views a public story with an image
**When:** Story detail page loads
**Then:** Image displays below title/metadata, above story body text
**Then:** Image has rounded border, respects max-height (400px desktop, 300px mobile)
**Then:** Image is not stretched or cropped (object-fit: contain)
**Verify:** View story as visitor -> image in correct position, properly formatted.

### UAT-12: Expand image to full resolution (lightbox)
**Given:** User views a story with an image
**When:** User clicks/taps the image
**Then:** Lightbox overlay opens: dark backdrop, image centered at full resolution
**Then:** Close button (X) visible in top-right corner
**When:** User clicks X, backdrop, or presses Escape
**Then:** Lightbox closes, back to story page
**Verify:** Click image -> lightbox opens -> close via X/backdrop/Escape -> back to story.

### UAT-13: Story cards in feed show compact image
**Given:** A story with an image appears in the feed or on author's profile
**When:** Story card is rendered
**Then:** Image shows as compact preview (max 200px height) above text snippet
**Then:** Clicking the image navigates to story detail (NOT lightbox)
**Verify:** Find story card in feed -> image preview visible -> click -> navigates to /story/:id.

## Error Handling

### UAT-14: Invalid format rejection
**Given:** Author clicks "Add image" on any story page
**When:** Author selects a GIF, SVG, or PDF file
**Then:** Toast: "Please use JPEG, PNG, or WebP format (max 5MB)"
**Then:** No image preview appears, "Add image" button remains
**Verify:** Select .gif -> error toast -> button still visible.

### UAT-15: Oversized file rejection
**Given:** Author clicks "Add image"
**When:** Author selects a 10MB JPEG
**Then:** Toast: "Please use JPEG, PNG, or WebP format (max 5MB)"
**Verify:** Select >5MB file -> error toast.

### UAT-16: HEIC conversion failure
**Given:** Author selects a corrupted HEIC file
**When:** heic2any fails to convert
**Then:** Toast: "Could not process this image. Try a different file."
**Verify:** Upload corrupt .heic -> specific error toast.

### UAT-17: Upload failure does not block story creation
**Given:** Author is on `/create` with story text and an image upload fails
**When:** Author sees upload error toast
**Then:** Story text is preserved in the textarea
**Then:** Author can publish text-only story immediately
**Then:** Author can retry image upload
**Verify:** Upload fails -> text not lost -> can publish without image or retry.

## Security & Privacy

### UAT-18: Non-author cannot modify image
**Given:** Visitor views a story authored by someone else
**When:** Story detail page loads
**Then:** No "Add image", "Change image", or "Remove image" controls visible
**Verify:** Log in as different user -> view another's story -> no image edit controls.

### UAT-19: Non-author controls hidden on imageless story too
**Given:** Visitor views another author's story that has no image
**When:** Story detail page loads
**Then:** No "Add image" button visible
**Verify:** View imageless story as non-author -> no "Add image" button.

## Edge Cases

### UAT-20: Extreme aspect ratios display gracefully
**Given:** Author uploads a panoramic image (6000x1000) or tall portrait (500x4000)
**When:** Image displays on story detail page
**Then:** No horizontal overflow, no stretching, no cropping
**Then:** Panoramic: thin strip at full width. Portrait: full max-height, narrow width, left-aligned.
**Verify:** Upload panoramic -> no layout break. Upload tall portrait -> left-aligned, no overflow.

### UAT-21: Transparent PNG shows against visible background
**Given:** Author uploads a PNG with transparency
**When:** Image displays on story detail page
**Then:** Image container has subtle background (not transparent) so image doesn't "float"
**Verify:** Upload transparent PNG -> image has visible container background.

### UAT-22: Existing banner_url (OG) unaffected
**Given:** A story has both an author-chosen image AND an auto-generated banner_url
**When:** Story is shared on social media (OG preview)
**Then:** OG image comes from banner_url (existing behavior), not author-chosen image
**When:** Author removes the supporting image
**Then:** banner_url and OG sharing continue to work independently
**Verify:** Share story URL -> OG preview uses banner, not author image. Remove image -> OG still works.

### UAT-23: Text-only story matches current behavior exactly
**Given:** A story with no image (before and after P591)
**When:** Story detail page loads
**Then:** No empty image placeholder, no skeleton, no layout shift
**Then:** Page looks identical to current production for text-only stories
**Verify:** Compare text-only story page before/after P591 deployment — no visual difference.
