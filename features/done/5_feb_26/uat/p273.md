# UAT P273: Verification gate — consistent blocked-action UX

## Problem statement

Unverified users currently get inconsistent or confusing feedback when attempting gated actions:
- Create story → generic "Save failed. Please check your connection." (RLS rejection)
- Set position → one-off inline check (correct, but different message and pattern from any future gate)
- Future gated actions → whoever implements them must invent their own pattern

## Intention

Every action that requires email verification should show the same clear, helpful toast message, with no special-casing per action.

---

## Test Categories

### Category 1: Hook contract (unit)

#### UAT-1.1: Returns true for verified user
**Given:** A verified user (`isVerified: true`) is authenticated
**When:** `checkVerified('some action')` is called
**Then:** Returns `true`, no toast is shown
**Verify:** Unit test `src/tests/useVerificationGate.test.ts`

#### UAT-1.2: Returns false + shows toast for unverified user
**Given:** A user with `isVerified: false` is authenticated
**When:** `checkVerified('some action')` is called
**Then:** Returns `false`, `toast.error()` is called with a message containing the action label
**Verify:** Unit test

#### UAT-1.3: Returns false + shows toast for null user
**Given:** No user is authenticated (`user = null`)
**When:** `checkVerified('some action')` is called
**Then:** Returns `false`, a toast error appears
**Verify:** Unit test

#### UAT-1.4: Toast message matches spec exactly
**Given:** An unverified user
**When:** `checkVerified('create a story')` is called
**Then:** Toast message is exactly: `"Verify your email to create a story — check your inbox or resend below."`
**Verify:** Unit test asserting exact string

### Category 2: Create story page

#### UAT-2.1: Unverified user sees gate toast on submit
**Given:** A user whose profile has `is_verified = false`
**When:** They visit `/create`, fill in the story text, and click Save
**Then:**
- The page does NOT show "Save failed. Please check your connection."
- The page shows a toast containing "Verify your email to create"
- No story is created in the database
**Verify:** Playwright — `expect(page.getByText(/verify your email to create/i)).toBeVisible()`
**Verify:** DB — `select count(*) from stories where profile_id = '<unverified_user_id>'` → 0

#### UAT-2.2: Verified user creates story without interruption
**Given:** A verified user
**When:** They visit `/create`, fill in story text, and click Save
**Then:**
- A success toast appears ("Story saved!" or similar)
- The page navigates to `/story/:id`
- No verification toast is shown
**Verify:** Playwright — URL changes, no `/verify your email/` text visible

---

### Category 3: Set position on point (story detail page)

#### UAT-3.1: Unverified user sees consistent gate toast (not old message)
**Given:** A user with `is_verified = false` viewing a story detail page with points
**When:** They click a position button (Strongly Agree / Agree / etc.)
**Then:**
- The page does NOT show the old message: "Please verify your email to record positions"
- The page DOES show the hook-generated toast: "Verify your email to set a position — check your inbox or resend below."
- Position is NOT recorded in the database
**Verify:** Playwright — `expect(page.getByText(/verify your email.*check your inbox/i)).toBeVisible()`
**Verify:** DB — `select count(*) from point_positions where user_id = '<unverified_user_id>'` → 0

#### UAT-3.2: Verified user can set position normally
**Given:** A verified user viewing a story detail page with points
**When:** They click a position button
**Then:** Position is recorded (button state changes), no gate toast
**Verify:** Playwright — button state updates, no verification toast visible
