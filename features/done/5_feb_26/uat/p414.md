# UAT: P414 — Profile Bio

Manual validation scenarios. Run with Claude in Chrome MCP or manually.

---

## UAT-1: Bio displays on profile

### UAT-1.1: Bio shown below role when set
**Given:** A profile with bio "Helping leaders communicate with clarity."
**When:** Any visitor navigates to the profile page (`/p/{slug}`)
**Then:** Bio text appears below the role, above the pledge CTA
**Verify:** `mcp__claude-in-chrome__read_page` — confirm bio text is in the profile card

### UAT-1.2: No blank space when bio is empty
**Given:** A profile with no bio set (null)
**When:** Visitor views the profile
**Then:** No empty gap or placeholder is visible between role and pledge CTA
**Verify:** Visual inspection — card looks identical to pre-P414 state for bio-less profiles

### UAT-1.3: URL in bio renders as a tappable link
**Given:** Bio contains "linkedin.com/in/sarah"
**When:** Visitor views the profile
**Then:** "linkedin.com/in/sarah" is rendered as a blue underlined link opening in a new tab
**Verify:** `mcp__chrome-devtools__click` on the link — new tab opens to correct URL

### UAT-1.4: Non-URL text in bio is plain text
**Given:** Bio is "Helping leaders communicate clearly. 10+ yrs."
**When:** Visitor views the profile
**Then:** Text renders as plain text — no unwanted link wrapping
**Verify:** No `<a>` elements around plain text in DOM

## UAT-2: Settings — bio edit

### UAT-2.1: Bio textarea present in settings
**Given:** Authenticated user navigates to `/settings`
**When:** Page loads
**Then:** A "Bio" textarea is visible with placeholder text and a character counter showing "0 / 160"
**Verify:** `mcp__claude-in-chrome__read_page` — confirm textarea and counter visible

### UAT-2.2: Char counter updates live
**Given:** Settings page open, bio textarea empty
**When:** User types "Hello world" (11 chars)
**Then:** Counter updates to "11 / 160" immediately
**Verify:** `mcp__claude-in-chrome__form_input` then check counter text

### UAT-2.3: Textarea enforces 160-char max
**Given:** Settings page open
**When:** User pastes 200 chars into the bio textarea
**Then:** Input is capped at 160 chars; excess is discarded
**Verify:** Check textarea value length ≤ 160

### UAT-2.4: Hint text shown below textarea
**Given:** Settings page open
**When:** Bio textarea is visible
**Then:** Hint "Links auto-detected and made clickable" appears below the textarea
**Verify:** Text visible near the textarea

### UAT-2.5: Saving bio persists
**Given:** User types "Coaching with clarity." and clicks Save
**When:** Save completes (success toast shown)
**Then:** Navigating to their profile shows "Coaching with clarity." as the bio
**Verify:** Navigate to `/p/{slug}` and confirm bio text visible

### UAT-2.6: Bio pre-populated on revisit
**Given:** User has bio "Existing bio."
**When:** User opens `/settings`
**Then:** Bio textarea contains "Existing bio." pre-filled
**Verify:** Textarea value matches saved bio

## UAT-3: Security / edge cases

### UAT-3.1: javascript: in bio text is rendered as plain text
**Given:** Bio contains the text "javascript:alert(1)"
**When:** Visitor views the profile
**Then:** Text is rendered as plain text, NOT as a link
**Verify:** No `<a>` wrapping the text in DOM

### UAT-3.2: Long URL with path is linkified correctly
**Given:** Bio is "See linkedin.com/in/sarah-coach-icf for details"
**When:** Visitor views the profile
**Then:** Full URL including path is the link text and href (with https:// prefix)
**Verify:** DOM inspection of the `<a>` href attribute
