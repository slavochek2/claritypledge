## UAT-A: Position-triggered entry

### UAT-A.1: Stake position → CTA appears
**Given:** A verified user is on a Point detail page (e.g. `/points/{id}`)
**When:** User stakes a position (selects a score and confirms)
**Then:** A "Tell your story →" CTA button appears on the point card or below the position widget
**Verify:** CTA is visible after position is staked; it was not visible before

### UAT-A.2: CTA navigates to /chat with context params
**Given:** The "Tell your story →" CTA is visible
**When:** User clicks "Tell your story →"
**Then:** Browser navigates to `/chat?from=position&pointId={id}` where `{id}` matches the point
**Verify:** URL contains `from=position` and the correct `pointId`; no blank screen or error

### UAT-A.3: Context chip is pinned and AI sends opening message
**Given:** User lands on `/chat?from=position&pointId={id}`
**When:** Page finishes loading
**Then:**
- A context chip appears at the top of the chat thread (or pinned above input) showing the point text
- The AI sends an opening message in the thread acknowledging the point context
- The input bar shows the brain dump placeholder (e.g. "What happened?")
**Verify:** Chip shows point label; AI message is visible; input is ready for typing

## UAT-B: Direct entry — brain dump → draft card

### UAT-B.1: Direct /chat visit shows empty state
**Given:** Authenticated user navigates to `/chat` directly (no `?from=position` params)
**When:** Page loads
**Then:**
- No context chip visible
- Empty thread (no AI opening message yet)
- Input bar is visible with placeholder text (e.g. "What's on your mind?")
**Verify:** Thread is empty; input is ready; no chip

### UAT-B.2: Brain dump sent → AI responds with draft card (not a bubble)
**Given:** User types a brain dump of ~3–10 sentences in the input bar
**When:** User presses Ctrl+Enter (or clicks Send)
**Then:**
- User's message appears in the thread as a standard message bubble
- AI response appears as a **draft card** (labelled "Draft v1 · Draft · not saved") — NOT as a chat bubble
- Draft card contains the AI-structured story text
**Verify:** Draft card is visually distinct from message bubbles; label reads "Draft v1"; content is a structured story

### UAT-B.3: Thread order is preserved
**Given:** AI has responded with Draft v1
**When:** Thread is scrolled to the top
**Then:** Messages appear in chronological order: user brain dump → AI message (if any) → Draft v1 card
**Verify:** No messages appear out of order; scroll position is at the bottom after AI response

## UAT-C: Rating loop — type rating → AI revises → new versioned draft

### UAT-C.1: Typing a mid rating (5–7) triggers revised draft
**Given:** Draft v1 is visible in the thread; user is in `rating` phase
**When:** User types "6" in the input bar and sends
**Then:**
- User's "6" message appears as a bubble
- AI responds with a plain-text message explaining what it heard and options/questions
- A new draft card appears: "Draft v2 · Draft · not saved"
**Verify:** Draft v2 is visible; AI message between drafts is plain text (not a card); draft version increments

### UAT-C.2: Typing a high rating (8–9) triggers targeted clarification options
**Given:** Draft is visible; user is in `rating` phase
**When:** User types "8" and sends
**Then:** AI message offers 2–3 targeted options labelled A, B, C (e.g. "A: deepen the vulnerability; B: sharpen the contrast; C: keep as is")
**Verify:** AI message contains options A/B/C as plain text; a new draft card appears after

### UAT-C.3: Typing a low rating (<5) triggers a re-attempt
**Given:** Draft is visible; user is in `rating` phase
**When:** User types "3" and sends
**Then:** AI message acknowledges the low score and re-attempts a different framing; new draft card appears
**Verify:** New draft is substantially different from previous; draft version increments

## UAT-D: A/B/C options — user types letter in input

### UAT-D.1: AI offers A/B/C options → user types "B" → AI applies option B
**Given:** AI has presented options A, B, C in a message
**When:** User types "B" in the input bar and sends
**Then:** AI applies option B interpretation; a new draft card appears incorporating that change
**Verify:** New draft card is visible; change note (if any) reflects option B was applied

### UAT-D.2: User types free text instead of letter — AI treats it as refinement instruction
**Given:** AI has presented options A, B, C
**When:** User types a free-form instruction (e.g. "Make it shorter and more direct")
**Then:** AI interprets as a refinement instruction (not an option letter); new draft incorporates the instruction
**Verify:** Draft updates according to the instruction; no error or confusion message

## UAT-E: Escape hatch — 3 iterations without rating 10

### UAT-E.1: Escape hatch appears after 3 iterations
**Given:** User has gone through 3 rating cycles (brain dump → Draft v1 → rate → Draft v2 → rate → Draft v3 → rate) without giving a 10
**When:** Third rating is submitted (any score below 10)
**Then:** AI message includes an escape hatch: "[Save at this version]" button AND "[Keep refining]" button appear in the thread
**Verify:** Both buttons visible in thread after 3rd iteration; input may be disabled until user chooses

### UAT-E.2: "[Save at this version]" triggers polish pass immediately
**Given:** Escape hatch is shown
**When:** User clicks "[Save at this version]"
**Then:** AI proceeds to polish pass (same as rating 10 path); polish draft card appears; visibility selector appears
**Verify:** Polish card labelled "Draft v4 · Polish · not saved" (or equivalent); visibility selector visible

### UAT-E.3: "[Keep refining]" clears escape hatch and reactivates input
**Given:** Escape hatch is shown
**When:** User clicks "[Keep refining]"
**Then:** Escape hatch disappears; input bar re-activates; user can continue rating
**Verify:** Input bar is enabled; escape hatch buttons gone; placeholder shows "What should I change?"

## UAT-F: Polish pass — rating 10 → polish draft → Changes note

### UAT-F.1: Rating 10 immediately triggers polish pass (no congratulations message)
**Given:** Draft is visible; user is in `rating` phase
**When:** User types "10" and sends
**Then:** AI immediately proceeds to polish pass — no congratulations message. Polish draft card appears in thread labelled "Draft vN · Polish · not saved"
**Verify:** No "Great job!" message; polish card appears without intermediate messages

### UAT-F.2: Polish card shows a brief Changes note
**Given:** Polish draft card has appeared
**When:** User reads the card
**Then:** A small "Changes: [brief note]" line appears below or within the polish card text, describing what changed in polish
**Verify:** Changes note is visible; it is brief (1 sentence); story content is the polished version

**Given:** Visibility selector is visible; Private is selected
**When:** User clicks "Shared"
**Then:** "Shared" becomes selected; Save button label changes to "Publish story"
**Verify:** Label updates immediately on click; no page reload

### UAT-G.3: Selecting "Public" updates button label to "Publish story"
**Given:** Visibility selector is visible
**When:** User clicks "Public"
**Then:** "Public" becomes selected; Save button label stays "Publish story" (same as Shared)
**Verify:** Label reads "Publish story"; "Public" option is visually selected

## UAT-H: Post-publish — story card in thread, toast, naming prompt

### UAT-H.1: Clicking Save shows spinner then transitions to saved story card
**Given:** Visibility is selected; Save button is enabled
**When:** User clicks Save button
**Then:**
1. Button shows spinner + "Saving..." text; is disabled
2. On success: spinner disappears; polish draft card transitions in-place to a **saved story card** in the thread
3. Saved story card shows the story content and "saved" state (no "Draft" label)
**Verify:** Spinner visible during save; saved card appears in place of draft card; no page navigation

### UAT-H.2: Sonner toast "Story saved." appears
**Given:** Save completes successfully
**When:** Save succeeds
**Then:** A toast notification appears (Sonner): "Story saved."
**Verify:** Toast is visible briefly; no persistent error messages; input bar re-enables

### UAT-H.3: Saved story card does NOT show [▷ Start /live] CTA (deferred to P428)
**Given:** Saved story card is visible in thread
**When:** User views the saved card
**Then:** No "[▷ Start /live]" button is present on the saved story card. Only `[✏ Edit]` (disabled stub) and `[···]` (menu stub) are visible.
**Verify:** CTA is absent; no reference to `/live` on the card

## UAT-K: Rate limiting

### UAT-K.1: Rate limit reached — informative message, no crash
**Given:** User has made 30+ calls to the AI in a single hour (or test environment rate limit is triggered)
**When:** User sends another message
**Then:** A user-friendly message appears: `"You've been on a roll — take a short break and you can keep going in X minutes."` The app does not crash, no generic error shown.
**Note:** This is a manual observation test. Trigger by sending many messages rapidly in a test environment.
**Verify:** Message does not use the word "rate limited"; save button is not blocked; user can still save the current draft
