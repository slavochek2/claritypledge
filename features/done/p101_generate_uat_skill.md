## Problem

Creating a UAT (User Acceptance Test) file manually is tedious:
1. Read spec and extract success criteria
2. Convert to Given/When/Then format
3. Group into logical categories
4. Create scorecard table with checkboxes
5. Add ralph-loop instructions

This takes 20-30 minutes per spec.

---

## Proposed Skill: /generate-uat

```
/generate-uat <path-to-spec> [options]
```

**Purpose:** Generate a UAT file from a spec. Can be called standalone or by `/prep-spec`.

### What It Does

1. **Read spec** — Parse the entire spec file
2. **Find success criteria** — Look for these sections (in order):
   - "Success Criteria"
   - "Acceptance Criteria"
   - "Requirements"
   - "User Stories"
   - Bullet points under "Goals" or "Objectives"
3. **Extract testable statements** — Each criterion becomes a test
4. **Categorize** — Group tests by:
   - Feature area (if spec has sections)
   - Test type: Database, UI, Auth, API, etc.
5. **Convert to Given/When/Then** — For each criterion:
   - Given: precondition/context
   - When: action
   - Then: expected outcome
6. **Generate scorecard table** — With columns:
   - ID (UAT-N.M)
   - Category
   - Test description
   - Status (⬜ initially)
   - Notes
7. **Add ralph-loop metadata** — Instructions for the loop executor
8. **Output** — Save to `features/{spec-name}_acceptance_tests.md`

## UAT File Template

```markdown
# {Feature Name} — Acceptance Tests

**Spec:** `{spec_path}`
**Generated:** {date}
**Generated by:** /generate-uat
**Total tests:** {count}

---

## Scorecard

| ID | Category | Test | Status | Notes |
|----|----------|------|--------|-------|
| UAT-1.1 | Database | Events table exists with required columns | ⬜ | |
| UAT-1.2 | Database | RLS policies configured | ⬜ | |
| UAT-2.1 | UI | Events list page renders | ⬜ | |
| ... | ... | ... | ... | ... |

**Legend:** ⬜ Not started | ✅ Pass | ❌ Fail | ⏭️ Skipped/Blocked

---

## Tests by Category

### Category 1: Database

#### UAT-1.1: Events table exists
- **Given:** Database connection is available
- **When:** Query `SELECT * FROM events LIMIT 1`
- **Then:** Query succeeds (may return empty, but no error)

#### UAT-1.2: RLS policies configured
- **Given:** Events table exists
- **When:** Query RLS policies for events table
- **Then:** Policies exist for select, insert, update, delete

### Category 2: UI

#### UAT-2.1: Events list page renders
- **Given:** User navigates to /events
- **When:** Page loads
- **Then:** Events list component renders without errors

...

---

## Ralph Loop Instructions

When running this UAT with ralph-loop:

1. Start from first ⬜ or ❌ test
2. Implement using TDD (test assertion first)
3. Verify with Playwright MCP / Chrome DevTools MCP
4. Update scorecard: ⬜→✅ or ⬜→❌
5. Commit after each category completes
6. Report score after each test

**Exit when:** All tests ✅ or blocked with notes.
```

## Options

| Flag | Default | Description |
|------|---------|-------------|
| `--output` | `features/{spec-name}_acceptance_tests.md` | Output path |
| `--format` | `full` | `full` (with Given/When/Then) or `minimal` (scorecard only) |
| `--categories` | auto | Override category detection |

---

## Extraction Rules

### Where to find success criteria

1. **Explicit sections** (highest priority):
   ```markdown
   ## Success Criteria
   - Criterion 1
   - Criterion 2
   ```

2. **User stories** (convert to tests):
   ```markdown
   As a user, I want to see events so that I can join them
   → UAT: User can see events list
   ```

3. **Requirements tables**:
   ```markdown
   | Requirement | Priority |
   |-------------|----------|
   | Events have title | Must |
   ```

4. **Implicit in feature description** (lowest priority):
   ```markdown
   The events page shows upcoming events with title, date, and location.
   → UAT: Events show title
   → UAT: Events show date
   → UAT: Events show location
   ```

### Categorization heuristics

| Keywords in criterion | Category |
|----------------------|----------|
| table, column, migration, SQL, RLS | Database |
| page, render, display, show, UI, component | UI |
| login, auth, session, permission, role | Auth |
| API, endpoint, request, response | API |
| form, input, validation, submit | Forms |
| navigation, route, link, redirect | Navigation |

---

## Edge Cases and Error Handling

| Scenario | Behavior |
|----------|----------|
| Spec has no success criteria | Warning: "No explicit success criteria found. Extracting from description. Review generated tests carefully." |
| Spec is too vague | Error: "Couldn't extract testable criteria. Add a 'Success Criteria' section to spec." |
| UAT file already exists | Prompt: "UAT file exists. Overwrite / Merge / Cancel?" |
| Spec has 50+ criteria | Warning: "Large spec (N criteria). Consider breaking into smaller features." |
