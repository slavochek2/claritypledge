# P1705: A worktree on any slot works against shared TEST, and says when TEST runs another branch's server code

## Problem

> Founder framing, verbatim (2026-11-18): *"Investigate and propose (do not build yet) a sustainable fix for how worktrees and the shared TEST server interact"*, then *"you can not only propose it, you can create the spec and then review the spec and be the orchestrator ... KDD should commit after you test because I guess this is something not necessarily something I can or want to test manually."* On the sign-in emails: *"Fix both, so that any worktree's port (whatever scheme item 3 settles on) is allowed, and the verify link goes back to the port the person came from."*

**Situation.** Each worktree slot has its own identity: a dev port from `scripts/lib/worktree-port.mjs` (wN = 5000 + N×100; w10 shifted to 6050 because 6000 is browser-restricted; named worktrees hash into 5800–5899) and its own branch. The shared self-hosted TEST server keeps one value for each of those: one fixed app address for mail links, hand-kept lists of accepted ports, and one copy of the edge functions (whichever branch deployed last).

**Complication.** P1675's work on w21 (port 7100), 2026-11-17 and 18, hit all of these at once:

1. **Sign-in emails linked to `localhost:5001`, three times.** Verified cause (2026-11-18): TEST's auth server (GoTrue v2.189.0) accepts a redirect only if it matches `ADDITIONAL_REDIRECT_URLS` on the VM, which is hand-kept and stops at port 6500 (live container value: 5001, 5100 to 6500, the server's own address). A redirect to 7100 is refused and replaced by `SITE_URL` (the server's address), and TEST's email template (`scripts/selfhosted/lib/email_template_drift.py`, `LOCAL_VERIFY`) turns any non-localhost redirect into `http://localhost:5001`. A read-only probe reproduces it: `GET /auth/v1/verify` with an invalid token returns 303 to `redirect_to` when allowed, else to `SITE_URL`. Result: `localhost:5100` → allowed; `localhost:7100` → refused; `https://evil.example` → refused. The TEST auth log for the last 48 h holds redirects only for 5001, 5100, 5500, 5700, 6100 and 6300. The template keeps the first 21 characters of the redirect (`http://localhost:NNNN`), so it is correct only for four-digit ports.
2. **Mailed links use a fixed app address too, and two fixes for that exist.** The functions container's `APP_URL` on TEST is `http://localhost:5173` (read live 2026-11-18), which no checkout uses. P1691 (on main) added `_shared/link-base.ts` `resolveLinkBase(req, appUrl, supabaseUrl)`: uses the request's `Origin` header when it is a dev origin accepted by the CORS rule, and only on a project whose address has a self-hosted/local shape. Only `send-letter-emails` and `send-agreement-emails` call it. P1675 (unshipped, w21) added `siteFor`/`localSiteFor` in `_shared/event-links.ts`: keyed on an `origin` field in the request body, gated on `APP_URL` being a localhost address, used by `send-event-emails`. Two rules, two keys, two gates. Beyond those: `create-and-sign`, `create-and-open-letter` and `request-letter-response-signin` read `APP_URL` directly; `send-agreement-emails` builds its accepted/terminated links from `APP_URL` (lines 275, 346) although it resolves a base at line 450; and `_shared/email-helpers.ts` hard-codes the prod event page (`eventPageUrl`, line 181, used as the starting-soon fallback at 442). The P1691 guard test (`src/tests/p1691-link-host-source.test.ts`) scans every function, but its matcher only catches a direct `headers.get('origin')` read and a `startsWith('http://localhost')` test, so a body field parsed with `new URL` and plain `APP_URL` reads pass it.
3. **The port lists stop before the slots do.** `_shared/cors.ts` `DEV_ORIGIN_RE` accepts 5001, 5100–5999, 6050, 6100–6999. w20 (7000) and w21 (7100) are refused, so every browser call to an edge function from those worktrees fails CORS. Its test (`src/tests/inbox205-cors-dev-ports.test.ts`) enumerates w1..w19 by hand and asserts 7000 is *refused* as a control, so it pins the bug. The same port set is copied, each differently, into: TEST's auth redirect list (stops at 6500), `scripts/gcs-chat-voice-bucket.sh` (stops at 7000), `scripts/gcs-cors.json` (stops at 5700), and the TEST audio bucket's CORS list (not in the repo; a task-inbox note tracks it). The allocator itself has no upper bound (w50 returns 10000), returns 5000 for `w0` (AirPlay's port), and gives w8 the same port as a named worktree hashing to 00.
4. **TEST runs one branch's functions at a time, and the place the founder tests never says so.** The E2E check (P1312, `branch-functions-check.sh`, receipts in `<git-common-dir>/cp-function-checks.jsonl`) did flag it: P1675's one receipt, 2026-11-17 10:42, reads `differs: _shared, send-event-emails (server has feature/p1700-removed-attendee-notice …, uncommitted)`. It is a warning by default. Since 2026-11-10, 52 of 222 recorded E2E runs started with `differs`: 18 on another branch's code, 30 with the server on main (the branch's own change not yet deployed), 4 on an older copy of the branch itself; 47 of the 52 came from one branch. A dev server (`npm run dev`), where the founder tests by hand, runs no check at all. A branch that changes no function, main included, gets "no changed functions", exit 0, with no network call, even when the server holds another branch's copy (the gap P1312 recorded as accepted).
5. **Finished slots are never removed, so slot numbers climb.** 19 worktrees exist (w1–w21 without w11 and w18). Claim takes the lowest free number from w1 to w99 (`scripts/git-ops.sh` `cmd_claim`), so the highest number in use tracks how many slots are held at once. Verified 2026-11-18:
   - **Every slot reads as dirty.** `setup-worktree.sh` links `.env.development.local` into each slot (P1557), and the cleanup check's ignore list (`scripts/lib/worktree-changes.sh`, lines 121 and 135) exempts only the `.env.local` and `.env.test.local` links. Ship and archive-spec therefore always print "worktree RETAINED", and `tidy` turns a shipped slot into a question instead of a removal. Filed earlier as a task-inbox note (promoted into this spec).
   - **Slots without a `.lock` read as held.** For w4 and w8, `tidy` reads the missing hold answer as "held", whatever the slot's own `.hold` says (the fail-safe direction, so harmless today).
   - **Ship and archive-spec ignore holds.** `teardown_worktree_if_clean` (`scripts/git-ops.sh:755`) removes any clean slot without reading `.hold`; `tidy` does read holds (`tidy_hold_blocks`). Today the setup link makes every slot dirty, which is the only thing keeping ship from removing a held slot. Fixing the link without fixing this would turn the next ship of w8 or w10 into a removal of founder-held work.
   - **Founder holds outlive their ship, by design.** All 16 slots' `.hold` files are owned by the founder. The holds on w2, w4, w8 and w10 predate their ships. Only `hold --clear` ends one, and the session-start strandings report already names each such slot with its hold reason. That surfacing is enough. This spec does not end founder holds automatically (see Alternatives).
   - Other leftovers behind the four STRANDED lines: in w2, two screenshots under `tmp/`; in w4, a `test-results-p1608/` folder.
   - Slot growth reached w20, whose port 7000 is taken by macOS AirPlay Receiver (ControlCenter listens on `*:7000`; Vite runs with `strictPort`), so a dev server on w20 cannot start at all.
   - Not a problem, checked: every kanban process runs from main's `tools/kanban`.

**How they connect.** One cause underneath: a per-checkout identity (port, branch) meets a server that keeps one global value, and the copies of that value are hand-kept in five places. Slot growth (5) pushes ports past the hand-kept lists (3), which breaks sign-in links (1) and CORS. The link rule (2) depends on the CORS rule. The functions problem (4) is the same "one global value" on the code side.

**Question.** Which single rule decides a mail link's address; which port set is the scheme, derived once and checked everywhere; how does a dev server or E2E run show that TEST is serving foreign code; and what keeps finished slots from reading as live.

## Appetite

Blast radius: medium. Every edge function's CORS (prod included) and every mailed link pass through the touched code. A wrong link rule on prod would send prod mail to a request-chosen host. Reversibility: high, plain code plus two TEST-server settings, both restorable. Decision density: low. The slot cap, port set and wildcard are engineering choices recorded here; prevention of foreign functions is already P1679's scope.

## Invariants

- **Prod mail links come from configuration alone.** On prod, no request value (header or body) reaches a mailed link's host. Carried from P1691 (`.private/features/done/2026-06-10/p1691_server_function_input_checks.md`, private ruling, summary: the dev exception applies only on a project positively known not to be prod).
- **One definition of the dev port set.** `scripts/lib/worktree-port.mjs` is the only definition (P1480). Every exact list elsewhere is generated from it or checked against it by a test that fails on difference (epistemic gate 7e: derived members, at least one known member per path). TEST auth is the one place that takes a wildcard instead (Solution B), and its check is a behavioural probe derived from the allocator.
- **Detect, do not auto-deploy.** No check deploys functions on its own (decisions.md 2026-11-05, P1312). Prevention by lanes stays with P1679 (decisions.md 2026-11-15, P1672).
- **Nothing destructive trusts a liveness verdict** (decisions.md 2026-09-17, P1326). No path (ship, archive-spec, tidy) removes a worktree that holds uncommitted work or a blocking hold. Ship and archive-spec gain the hold check `tidy` already has, in the same change that stops the setup link from reading as dirty.
- **Unknown is never a pass** (`branch-functions-check.sh` header). Every surface that shows the functions check shows `unknown` as its own state, never as silence.

## Solution

### A. One mail-link rule (symptoms 1, 2)

- `_shared/link-base.ts` becomes the only module that reads `APP_URL`. Its one call takes the request, or nothing for scheduled sends, and returns the base. It returns `APP_URL` in every case except one: the request's `Origin` is exactly one of the allocator's dev origins (the generated set from B, not "whatever CORS returned unchanged") **and** the project has a known non-prod address **and** `APP_URL` itself is a localhost address. That is two independent gates on the dev branch. P1691's project-shape gate stays, and P1675's localhost-`APP_URL` gate is kept as the second. P1675's body `origin` field is not kept: the browser sets `Origin` on every cross-origin call with no client change.
- Every mailed action link takes its base from it: `send-event-emails` (confirmation, ticket and event-page links), `create-and-sign`, `create-and-open-letter`, `request-letter-response-signin`, `send-agreement-emails` accepted/terminated links, and `email-helpers.ts` `eventPageUrl` (its hard-coded prod address becomes a base parameter). Scheduled senders (`event-dispatch`, `starting-soon`) call it with no request and get `APP_URL`; `_shared/event-links.ts` `linkBase` (main's own `APP_URL` reader, reached through `mintEmailLink`) delegates to it, with the request added as an optional parameter. Static footer links (brand, terms, privacy) stay on the prod address. They are not actions on the user's record.
- The P1691 guard test gains rules, each with a control built by mutating a real function file (gate 7d): no module other than `link-base.ts` reads `APP_URL` in any spelling; no function reads an `origin` field from a request body; no function parses an origin and compares its host to localhost; no app-route link (`/events/`, `/letters`, `/agreements/`) is built on a literal prod address. Its link-builder list is derived from the functions that send mail, not hand-kept.
- **P1675 coordination.** P1675 is unshipped on w21 and is not edited by this work. Whichever of the two lands second removes `siteFor`, `localSiteFor` and the client's body `origin` field. Both change `mintEmailLink` in `_shared/event-links.ts`, so the second to land resolves a real merge conflict there, and the extended guard test fails that rebase until P1675's rule is gone. P1675's spec gets a one-line pointer.
- TEST's `APP_URL` becomes `http://localhost:5001` (the main checkout). Function settings have one writer: the Mac's `functions.env`, pushed by `deploy-functions.sh --secrets`, which replaces the server's file (`/dev` first finds where today's 5173 comes from). `deploy-functions.sh` warns when `APP_URL` is absent from that file or is not a localhost address, so it cannot silently drift back. That puts both gates on TEST and on lanes, which copy `APP_URL` from main (`lanectl.py` `FN_ENV_ALLOW`).
  - **As built, a deviation (2026-11-18).** The one-writer path is not usable today: the Mac's `functions.env` lacks 18 names the server's file holds, and P1602 makes `deploy-functions.sh --secrets` refuse a push that would drop server names. So the server's `APP_URL` line was edited in place (backup `functions.env.bak-p1705-<timestamp>` beside it on the VM, functions container recreated), and the Mac file gained the same line so a later `--secrets` push keeps it. The warning in `deploy-functions.sh` reads the Mac file, as designed. Bringing the two files level (copying 18 server-only values to the Mac) is a founder decision about where those values may live, not part of this spec. Lanes copy `APP_URL` only when provisioned, so a lane created before this change keeps its old value; none is claimed today.

### B. One port scheme (symptom 3)

- `worktree-port.mjs`:
  - **Cap.** `MAX_SLOT = 49` for wN and legacy `claritypledge-N` alike (top port 9900: four digits, which TEST's email template needs, and below the restricted 10080). A slot above the cap, or `w0`, throws. Claim stops at the cap and its refusal names the slots `tidy` would reclaim. This deliberately changes P1480's w1..w99 contract (`src/tests/p1480-worktree-ports.test.ts`), so that test is updated to the new contract, not loosened.
  - **Reserved ports.** A Mac-reserved set {5000, 7000} (AirPlay), separate from `CHROMIUM_RESTRICTED_PORTS` (which a test keeps equal to the Fetch standard list), is shifted by the same +50 as the browser-restricted set. w20 moves from 7000, where its dev server cannot start, to 7050. Whatever w20 holds today cannot be running on 7000, so no live URL breaks.
  - **Named range.** Named worktrees hash into 5811–5889. That keeps them clear of load-test ports on both sides: w8 (5800) load-tests on 5801–5809, and the top named port plus nine is 5898, below w9's 5900 (Opus review; `src/tests/p1705-dev-origins.test.ts` asserts no dev port sits in another checkout's load-test range). Two named worktrees can still share a port; Vite's `strictPort` then refuses the second loudly. None is in use.
  - **Origin sets.** Two functions over the one definition: `slotOrigins()` (main and w1..w49 after shifts), and `devOrigins()` (those, the named range, and each checkout's E2E load-test ports `base+1..base+9` from `loadTestPort`). The load driver refuses a level above 9. Every port in either set is 1024–9999 and four digits (asserted).
  - The claim loop and its message (`git-ops.sh` ~415, ~448) follow the cap.
  - The type file `worktree-port.d.mts` follows.
- **CORS.** Edge functions cannot import `scripts/`, so a generated `_shared/dev-origins.ts` holds `devOrigins()` exactly, and a test asserts it equals the allocator's output (regenerate command in its header). `cors.ts` and `link-base.ts` both read it. The CORS test derives every slot from the allocator up to `MAX_SLOT`. Controls: 5000, 6000, 7000, 3000, 10000 and a non-slot port such as 5150 are refused.
- **TEST auth.** Add `http://localhost:[0-9][0-9][0-9][0-9]` and `http://localhost:[0-9][0-9][0-9][0-9]/**` to the VM's `ADDITIONAL_REDIRECT_URLS`, keeping every other entry, then restart the auth container. Why a pattern here and nowhere else: it covers every port the allocator hands out (all four digits) with nothing to regenerate. **Never `localhost:*`** (corrected 2026-11-18, after the first form was live on TEST for part of a day): GoTrue compiles each entry as a glob with `.` and `/` as separators (`internal/conf/configuration.go`, `glob.MustCompile(uri, '.', '/')`), so `*` matched `a@0x5db8d822`, and `http://localhost:a@0x5db8d822/x` was accepted. A browser reads that as host 0x5db8d822, an outside IPv4 address, so a recovery or sign-in link would carry its tokens off the machine. Found by the Opus adversary review and confirmed by the read-only probe on TEST; `--apply` now removes the unsafe entries and the check fails if that address or a five-digit port is accepted. It also removes the generator, the apply script and the drift comparator a generated list would need. Lanes copy main's list when created (`lanectl.py:390`), so new lanes inherit it. No lane is claimed today.
- **TEST auth check.** A repo script runs the read-only verify probe from the Problem for every port in the allocator's set (expect a 303 to that port), plus two controls (an external host and `SITE_URL`'s fallback must still behave as today). It becomes part of the existing TEST health check, so a hand edit that drops the four-digit pattern shows up as a failure, not a silent fallback to 5001. As built: `scripts/selfhosted/auth-redirects.sh --check` (and `--apply`, which made the change). The external-host control must still land on `SITE_URL`; if it does not, the check reports `unknown`, never `ok`. Four refusal controls follow it: the userinfo bypass in three forms, `http://localhost:a@0x7f000002`, `http://localhost:1@0x7f000002` and `http://localhost:a@0x7f000002/x` (aimed at a loopback address so the probe never names an outside host), and a five-digit port. One form per GoTrue entry shape, because `*` stops at `.` and `/`: a re-added plain `localhost:*` matches only the path-less form, `localhost:*/**` only the path form, and `localhost:[0-9]*` only a userinfo that starts with a digit (Opus review). If any is accepted the check prints `warn: UNSAFE` and exits 1. Hermetic canary: `scripts/test-p1705-auth-redirects.sh` (a stub plays GoTrue, and health.sh's own parser reads each verdict). `health.sh` runs it as check `auth-redirects` from every source, since it needs only public HTTPS.
- **TEST auth entries, not only probes.** Probes sample; an entry can admit a shape no fixed probe tries. The live list still held `http://localhost:58??` from an earlier named-worktree range, and `??` admits `http://localhost:58@a/x` (Codex round 5, 2026-11-18). So `auth-redirects.sh --audit` reads the running auth container's allow list over SSH and `--classify` judges every entry: it passes only if it is one of the four-digit patterns, or its scheme is letters and its host part (up to the first `/`) holds no glob character, no `@` and no `\`. Anything else prints `auth-config: warn: UNSAFE` and exits 1; an unreadable list is `unknown`. `--apply` removes the known unsafe entries (the `localhost:*` and `localhost:58??` pairs) and ends with both the probe check and the audit. `health.sh` runs the audit as check `auth-config` when it reads the server over SSH; the other sources print no `auth-config` line. Lanes copy main's list when created (`lanectl.py:390`), so cleaning main's list also cleans every later lane.
- **GCS lists.** `gcs-chat-voice-bucket.sh` and `gcs-cors.json` keep exact origins (GCS takes no wildcard). Their localhost entries are checked equal to `slotOrigins()` by a test (no named or load-test ports: none is used against a bucket, and GCS lists are exact origins). Applying a changed list to a live bucket is a separate step run with a human watching (each script says so), announced first.

### C. Show foreign server code where people test (symptom 4)

- **Dev server.** A dev-only Vite plugin (`apply: 'serve'`) runs the functions check at server start and again every 30 minutes, never blocking Vite. When the TEST host name does not resolve it reports `unknown: offline` without running. It skips under Vitest (`VITEST` set) and for dev servers started by Playwright or the load driver, whose global setup already runs the same check. It pushes the result to the page over Vite's dev channel. Four states, all visible:
  - `match`: a small dev-only status mark with the check time, so "checked and fine" is distinguishable from "never ran".
  - `differs`: a banner naming the functions, the branch the server holds and the command that fixes it.
  - `unknown` (timeout, SSH failure): a muted banner saying the check could not run.
  - `stale`: the last result is older than one interval, and it is shown with its age.
  
  The banner is not drawn in an automated browser (`navigator.webdriver`): it is for people, and a test that reuses a running dev server would otherwise find it over the page. Playwright's own check prints the same verdict as its `FUNCTIONS:` line. [FOUNDER FLAG: a browser launched by Puppeteer or Playwright, which is how the agent's DevTools screenshots run, also sets `webdriver`, so those screenshots will not show the banner.]

  The banner code is guarded by `import.meta.env.DEV` and carries a fixed marker string, so a prod build contains none of it and a grep of `dist` proves that.
- **Names in printed commands.** The check prints fix commands built from function directory names. A name that is not plain (letters, digits, `-`, `_`) would print a shell token, `a>b` a redirect, so the check reports `unknown`, naming the directory with the token replaced, and prints no command. The two fallbacks that pick the first function name pick the first plain one (Codex round 5; P1312 canary 10h–10j fail on the old script).
- **Close the no-change gap.** When a branch (main included) changes no function, the check compares every function on the server against main's tip in the same single SSH call, instead of exiting without looking. When a branch changes functions, those are compared against the branch and the rest against main. A function differing from both is reported with the branch the server's deploy record names. Nothing tries to discover which functions the client calls.
- **E2E** keeps the warning default (P1312) and prints the functions line again at teardown (`e2e/global-teardown.ts`). What changes is coverage: a branch that changes no function now gets a real verdict instead of "no changed functions", so its runs warn when TEST holds other code. An evidence run with `E2E_REQUIRE_FUNCTIONS=1` on such a branch refuses at start until TEST matches main; `/dev` sets that flag only on branches that change functions, so this binds only when someone opts in (criteria review, P1705).
- Prevention (a lane per function-changing branch, VM refusing branch deploys to the main lane) is P1679. Its spec gets the receipt evidence above, which meets P1312's recorded condition for revisiting prevention ("until the receipts show evidence runs regularly waiting on redeploys").

### D. Slots that read as finished when they are (symptom 5)

- The cleanup check ignores any `.env*.local` that is a symlink, in both places the ignore list appears, rather than naming a third file. A real file of that name still counts.
- **Ship and archive-spec respect holds.** `teardown_worktree_if_clean` keeps a slot whose hold blocks (the same `tidy_hold_blocks` classifier), printing the hold's reason and the clear command. This lands in the same commit as the symlink change. As built, `park` goes through the same check with no bypass: the `.hold` file lives inside the worktree, so a park that removed a held slot would end the hold, which only `hold --clear` may do. A lockless slot is told to delete its `.hold` by hand, since `hold --clear` needs the lock's nonce.
- `tidy` reads a slot's hold from the slot itself, so a slot without a `.lock` is judged by its real hold.
- Holds are not cleared by ship, archive-spec or tidy. A finished slot with a founder hold stays a one-line question until the founder runs `hold --clear`, which the strandings report already prompts for.
- Removal itself stays where it is (`/day`'s tidy step, ship, archive-spec). This work removes no worktree.

## Alternatives Considered

**Mail-link rule.** (a) Keep P1675's body field: rejected, a body field is sent by app code and needs every caller changed, while the `Origin` header is set by the browser with no client change. (b) Store the registering origin per RSVP so scheduled reminders link back too: rejected, schema for a dev-only convenience; reminders keep `APP_URL`. (c) An explicit deployment-identity variable instead of the project-address shape: not taken, because prod is hosted Supabase and `isProdProject` compares the hostname. The second gate (localhost `APP_URL`) already makes a mis-shaped prod need two independent misconfigurations.

**Port scheme.** (a) Cap at w19 and keep every list as is: rejected, 19 slots are in use today, most held by the founder. (b) Accept any localhost port in CORS: rejected, CORS runs on prod and `authorization`/`apikey` headers are allowed, so the set stays exact. (c) Re-stride the scheme to keep more slots under 7000: rejected, it moves every existing slot's port. (d) A generated ~55-entry TEST auth redirect list with apply script and drift check: rejected in favour of a four-digit pattern (three runtime units saved, no regeneration when the scheme changes). The first form, `localhost:*`, did add trust: see Solution, TEST auth.

**Slot reclamation.** (a) Ship or tidy ends a founder hold that predates the ship: rejected (Codex review): a hold can wait on something other than the ship (an inspection, another spec), and age does not prove the reason is met. (b) Expire every founder hold after N days: rejected, design explorations are held for weeks on purpose. (c) Ship deletes the worktree regardless of leftovers: rejected by the P1326 invariant.

**Foreign functions.** (a) Make E2E fail by default on `differs`: rejected for now, the only remedy is to redeploy over the other branch, which starts a redeploy war; lanes (P1679) are the real fix. (b) A public deploy-info endpoint on TEST read by the browser: rejected, new server surface. (c) A separate background process per dev server: rejected for the Vite plugin, which adds no process.

## Risks / Non-Goals

|---|---|---|
| Prod CORS accepts localhost origins up to 9909 (588 exact origins: the slot ports plus the named-worktree and load-test ports, generated from the allocator), versus the old pattern's 1,802 (5001, 5100–5999, 6050, 6100–6999) | ACCEPT | `authorization`/`apikey` are allowed headers, so a page on an accepted port that already holds a user's token can call prod functions and read the response. That is the same class as today's 5100–6999 range: a token cannot be read cross-origin, and prod mail ignores the origin. |

| Changing a live GCS bucket's CORS | MITIGATE | Repo lists are fixed and checked here; applying them to a live bucket is announced first, with a human watching, and verified with each script's `--check`. |
