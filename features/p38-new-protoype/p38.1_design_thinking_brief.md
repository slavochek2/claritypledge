# P38.1: Design Thinking Brief — Event Prototype UX Exploration

**Parent:** [P38: Event-Based Prototype Simplification](./p38_event_prototype_simplification.md)
**Purpose:** Generate 5 divergent design concepts for critical UX areas
**Process:** Design Thinking (Empathize → Define → Ideate → Prototype)
**Output:** 5 distinct concept variations with wireframes + rationale

---

## Context: What We're Designing

We're building a **prototype for Clarity Practice Community events** where:
- An organizer facilitates groups of people verifying understanding
- Participants mark positions on ideas (agree/disagree/unsure)
- Pairs self-select to verify understanding via /live
- The goal: test H2 (visibility changes group behavior) from [Theory of Change](../docs/visions/v0_theory-of-change.md)

**Current Prototype:** [http://localhost:5001/prototype/converged/feed](http://localhost:5001/prototype/converged/feed)
- Too cluttered (stories, search, visual noise)
- Desktop "super ugly", mobile not optimized
- No event context (participants, organizer, scoped ideas)
- No clear path from "see idea" → "verify with partner"

---

## Design Constraints (What We Know)

### ✅ Keep These
1. **/live verification protocol** — Core flow is validated, don't change it
2. **Mobile-first** — Most events = phones out, thumb-zone critical
3. **Event-scoped** — Ideas + participants belong to an event context
4. **Theory of Change alignment** — Must support Facilitation Ladder (Level 1-4)

### ❌ Remove These
1. **Stories section** — Adds noise, not needed for events
2. **Search functionality** — Event scope makes this unnecessary
3. **Visual complexity** — We want "wireframe simple" for now

### 🤔 Explore These (Creative Freedom Zones)
Everything else is **open for creative exploration**.

## The 5 Critical UX Areas (What to Design)

### **Area 1: Event Landing Experience**

**The Problem:**
- No way to "enter" an event context currently
- Participants need immediate orientation: "What is this? Who's here? What are we doing?"
- Organizer needs confidence participants know what to do

**Empathy Questions:**
- What does a participant feel when they join their first event? (Confusion? Curiosity? Overwhelm?)
- What's the **one thing** they need to see in the first 5 seconds?
- How does this differ for: first-timer vs returning participant vs organizer?

**Open Design Questions:**
- Should event landing be a **separate page** or **header context** on ideas feed?
- How do we show "who's here" without cluttering the view? (Participant list? Avatar chips? Count only?)
- What's the **call-to-action** on landing? ("Explore ideas"? "Mark your positions"? "Find a partner"?)
- Do we need an explainer for first-timers? (Tooltip? Overlay? Inline hint?)
- How do we communicate event purpose/goals?

**Constraints:**
- Must work on mobile (375px width)
- Must load in < 3 seconds (no heavy assets)

**Explore:**
- Generate **3-5 divergent concepts** for event landing
- Consider: Telegram group join, Zoom waiting room, Luma event page, Discord server channels
- Sketch mobile + desktop views

---

### **Area 2: Ideas Board Layout**

**The Problem:**
- Current feed mixes everything (not event-scoped)
- No visual hierarchy (ideas blend together)
- Desktop layout "super ugly"
- Unclear how ideas relate to event goals

**Empathy Questions:**
- When I see 5-10 ideas, how do I know which to engage with first?
- What makes me want to mark a position vs. scroll past?
- How do I know if anyone else has engaged with this idea?

**Open Design Questions:**
- Should ideas be **cards** (Pinterest), **list items** (Twitter), **poll tiles** (Telegram), or something else?
- How prominent should position buttons be? (Always visible? Expand on click? Float on hover?)
- Where do we show "who marked what"? (Below idea? In a modal? As avatar chips?)
- Should we group ideas by theme, author, or keep flat list?
- How do we handle long descriptions? (Truncate? Expand inline? Open modal?)
- What's the **information architecture**? (Event context at top? Sidebar? Floating?)

**Constraints:**
- Must show: idea title, description, position buttons, "who marked what", "verify understanding" CTA
- Must be scannable (can't force reading every idea)
- Mobile: single column, desktop: 1-2 columns max

**Explore:**
- Generate **3-5 divergent layout concepts**
- Consider: LinkedIn feed, Telegram polls, Twitter Spaces, Miro boards, Notion databases
- Show how layout adapts mobile → desktop

---

### **Area 3: Position Marking + Participant Visibility**

**The Problem:**
- Currently no way to mark position (agree/disagree/unsure)
- No visibility into "who thinks what"
- Unclear how this helps me find verification partners

**Empathy Questions:**
- Why would I bother marking my position? (What's in it for me?)
- When I see "3 people agree, 2 disagree", what do I do with that?
- How does this lead me to "I want to verify understanding with Carol"?

**Open Design Questions:**
- Should position marking be **one-click** (tap button) or **two-step** (select + confirm)?
- How do we visualize "who marked what"? (Name list? Avatar grid? Just counts?)
- Should we highlight **cross-disagreement** as valuable? ("Alice agrees, Bob disagrees — verify with them!")
- Do we show positions **inline on each idea** or in a **separate view** (e.g., "See all positions")?
- How do we make it **social**? (Show "Carol just marked disagree" in real-time? Notify me?)

**Constraints:**
- Must be **reversible** (I can change my position)
- Must show positions **before pairing** (so I can choose verification partner strategically)
- Mobile: touch targets min 44px

**Explore:**
- Generate **3-5 divergent concepts** for position marking flow
- Consider: Slack reactions, Instagram polls, Miro voting, WhatsApp read receipts
- Show how positions influence partner selection

---

### **Area 4: Partner Selection → /live Handoff**

**The Problem:**
- No current flow from "I want to verify" → "launch /live with partner"
- Participants might not know **why** they're verifying (what's the context?)
- Risk: pairs form but forget which idea they're verifying

**Empathy Questions:**
- When do I decide "I want to verify understanding with someone"? (After marking position? While reading idea? When organizer prompts?)
- How do I choose a partner? (Someone who disagrees? A friend? Random?)
- What do I need to know before clicking "Start verification"?

**Open Design Questions:**
- Should partner selection be **per-idea** ("Verify this idea with...") or **global** ("Verify with Alice, then pick idea")?
- How do we present the partner list? (Modal? Inline dropdown? Separate page?)
- Should we **filter partners** by position? (Show "People who disagree with you" first?)
- Do we need a **waiting state**? (If partner hasn't accepted yet?)
- How do we hand off to /live **with context**? (Show idea title at top? Pass via URL? Store in session?)
- Should there be a "Ready check"? (Both people confirm before launching /live?)

**Constraints:**
- Must preserve idea context (which idea are we verifying?)
- Must work for **self-pairing** (I pick partner) and **organizer-assigned** pairing
- Mobile-friendly (no tiny modal with scrolling list)

**Explore:**
- Generate **3-5 divergent concepts** for partner selection flow
- Consider: Calendar booking, Uber "finding driver", Zoom breakout rooms, speed dating apps
- Show transition: Ideas board → Partner selection → /live launch

---

### **Area 5: Mobile-First Interaction Model**

**The Problem:**
- Current prototype likely breaks on mobile
- Events = people holding phones, standing/sitting in a room
- Most critical actions must be **one thumb** away

**Empathy Questions:**
- What's the **one action** I do most often during an event? (Mark position? Read ideas? Find partner?)
- When am I holding my phone one-handed vs. two-handed? (Reading = one hand, typing = two hands)
- What's frustrating about existing mobile apps during in-person events? (Too many taps? Small text? Easy to get lost?)

**Open Design Questions:**
- Should we use **bottom navigation** (thumb-zone) or **top navigation** (standard)?
- What's the **primary action button**? (FAB? Bottom bar? Floating?)
- How do we optimize for **one-handed use**? (Right thumb zone? Left thumb zone? Both?)
- Should we use **swipe gestures**? (Swipe to mark position? Swipe between ideas?)
- How do we handle **keyboard input** on mobile? (Name entry, idea descriptions)
- Do we need a **landscape mode**? (Or force portrait?)

**Constraints:**
- Must work on 375px width (iPhone SE)
- Touch targets min 44px
- Primary actions in bottom 1/3 of screen (thumb zone)

**Explore:**
- Generate **3-5 divergent concepts** for mobile interaction model
- Consider: Instagram Stories, TikTok, Telegram, Twitter, Tinder (swipe patterns)
- Show thumb-zone heat map for primary actions

## Design Thinking Process to Follow

### **Step 1: Empathize**
For each of the 5 areas above:
- Read the empathy questions
- Imagine the user's emotional state, frustrations, goals
- Consider: first-time participant, returning participant, organizer

### **Step 2: Define**
For each area:
- Restate the core problem in one sentence
- Identify the **primary user need** (not the feature, the need)

### **Step 3: Ideate**
For each area:
- Generate **3-5 divergent concepts** (don't converge yet!)
- Each concept should feel **meaningfully different** from the others
- Use "How might we..." questions to spark ideas
- Reference UX patterns from other apps (but don't just copy)

### **Step 4: Prototype (Sketch)**
For each concept:
- Create a **simple wireframe** (Excalidraw or text-based ASCII art)
- Show mobile + desktop views
- Annotate key interactions (tap, swipe, scroll)

### **Step 5: Evaluate**
For each concept:
- **Pros:** What's great about this approach?
- **Cons:** What are the risks/downsides?
- **Best for:** What type of user or scenario is this optimal for?

## Success Criteria for Design Concepts

A good concept should:
1. **Solve the core user need** (not just "look pretty")
2. **Be meaningfully different** from other concepts (divergent thinking)
3. **Work on mobile** (375px width, thumb-zone)
4. **Support Theory of Change** (Facilitation Ladder, H2 validation)
5. **Feel "wireframe simple"** (function > decoration)

A great concept should also:
- **Reduce cognitive load** (less thinking, more doing)
- **Guide next action** (clear "what do I do now?")
- **Celebrate progress** (verified understanding = visible achievement)
- **Enable organic pairing** (participants self-organize without facilitator)

## Open Questions for Designer to Address

As you explore, consider these strategic questions:

### **Information Architecture:**
- Should event context be **persistent** (always visible) or **collapsible**?
- How do we balance **event-level info** (participants, ideas) vs. **idea-level info** (positions, verifications)?

### **Interaction Paradigm:**
- Is this more like a **feed** (infinite scroll) or a **board** (spatial layout)?
- Should navigation be **linear** (step-by-step) or **free-form** (jump anywhere)?

### **Social Dynamics:**
- How do we make **disagreement feel safe**? (Design problem, not just copy)
- How do we reward **listening over talking**? (Visual hierarchy, status signals)

### **Facilitation Support:**
- What does the organizer see that participants don't?
- How does organizer **nudge** participants without being intrusive?

### **Progressive Disclosure:**
- What's the **minimum info** needed at each step?
- When do we reveal complexity? (Never? Only when requested?)
