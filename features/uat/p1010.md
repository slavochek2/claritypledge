# P1010 UAT — Clarity Organizations community container

Manual verification checklist for the founder-facing acceptance criteria. Run against a deployed
feature branch, not localhost mocks — several of these depend on real RLS/auth behavior.

## Org page rendering

- [ ] **Given** I visit `/org/cm` **when** the page loads **then** I see the org name, blurb,
      member count, and the Events tab selected by default (has_events=true).
- [x] **Given** an org with `has_events=false` **when** the page loads **then** the About
      tab is selected by default and there is no Events tab at all. (Covered by E2E
      against a disposable fixture. The seeded `champions` org that used to serve this
      case was cut before reaching prod — founder decision, 2026-07-29.)
- [ ] **Given** I visit `/org/some-made-up-slug` **when** the page loads **then** I see a
      not-found state, never a create-org form.

## Join

- [ ] **Given** I am NOT logged in **when** I click Join **then** I am redirected to log in,
      with a way to return to the org page afterward.
- [ ] **Given** I am logged in and not a member, viewing the About tab **when** I read it
      **then** I see a description of the organization that names the Clarity Organization
      Terms and links to the join page — and NO "You're not a member yet" note and no
      in-tab accept action (both retired by the post-UAT founder revision, spec line 125:
      the terms are a join gate on their own page, not About-tab content).
- [ ] **Given** I am logged in and not a member **when** I click Join **then** I see the
      subtitle "Members accept these not legally binding terms as a shared intention."
      ABOVE the certificate (not as a line inside it), the Clarity Organization Terms,
      and an "Accept terms & join" action.
- [ ] **Given** I accept **when** the accept completes **then** I appear on the Members roster
      immediately with an accepted date, and the header CTA becomes "Manage membership".
- [ ] **Given** I click Join twice in a row **when** the second click resolves **then** nothing
      breaks (no duplicate row, no error toast) — Join is idempotent.

## Leave

- [ ] **Given** I am a member **when** I open "Manage membership" and click Leave **then**
      a confirm dialog opens (the shared `ConfirmDialog`, same one Cancel RSVP uses) —
      the click alone must NOT remove me.
- [ ] **Given** the leave confirm dialog is open **when** I click "Stay" or press Escape
      **then** nothing changes — I am still a member.
- [ ] **Given** the leave confirm dialog is open **when** I click "Leave" **then** I am
      removed from the Members roster and the CTA reverts to "Join as member".

## Members roster

- [ ] **Given** an org with zero members **when** I open the Members tab **then** I see the
      org blurb plus a "Be the first to join" prompt — never a blank grid.
- [x] **Given** I am a member of one org only **when** I view another org's Members tab
      **then** I do NOT appear there — rosters are per-org, not global. (Covered by E2E.)
- [ ] **Given** the Members tab **when** it renders **then** cards use the same PledgerCard
      look as `/pledgers` (avatar, name, role, reason if present).
- [ ] **Given** the Members tab **when** I click a member's card **then** it opens their
      PROFILE (`/p/:slug`) and reads "Open Profile" — never the pledge certificate, which
      does not exist for a member who has not pledged.
- [ ] **Given** a roster containing both pledgers and non-pledgers **when** it renders
      **then** ONLY the pledgers' avatars carry the blue pledge ring.

## Security / RLS (spot-check — full coverage is in the integration test)

- [ ] **Given** a public org **when** I view it signed out **then** the roster is visible
      (no login wall on read).
- [ ] **Given** I am signed in **when** I inspect network requests during Join **then** no
      request sends a `terms_version` or `role` field — both are server-defaulted.

## Regression

- [ ] **Given** I visit `/cm` (the standalone calendar page, unrelated to `/org/cm`)
      **when** it loads **then** it is unchanged — same calendar embed, no org chrome.
- [ ] **Given** I visit `/events/list` **when** it loads **then** it is unchanged — the
      standalone list, NOT redirected. It is the webinar funnel's target
      (`NextWebinarRedirect` → `/events/list?series=lost-cofounders`) and must not move.

## Events nav

- [ ] **Given** any page **when** I click "Events" in the desktop dropdown, the mobile
      menu, the bottom nav, or the footer **then** all four land on `/org/cm`, which
      opens on its Events tab showing the same events as `/events/list`.
- [ ] **Given** I visit `/events` directly **when** it loads **then** I land on `/org/cm`
      (founder decision REVERSED — the redirect deferred at spec time was built, because
      ~11 hardcoded "back to events" links across the app pointed at `/events` and so
      returned to a page the menu no longer reaches).
- [x] **Given** I visit `/events?series=lost-cofounders` **when** it loads **then** I land
      on `/events/list?series=lost-cofounders` — the BARE list, not the org page.
      (Revised 2026-07-29: funnel traffic is excluded from the redirect so a cold
      webinar visitor isn't wrapped in community chrome + a Join CTA. Previously this
      landed on `/org/cm?series=…`, which made the landing depend on which URL was in
      the email. Non-funnel query strings still ride along to `/org/cm`. Covered by E2E.)
- [ ] **Given** I open an event from `/org/cm` and click Back **then** I return to
      `/org/cm`, not to the standalone list.
- [ ] **Given** I am on `/org/cm` OR on `/events/:slug` (an event I clicked through to)
      **when** I look at the bottom nav **then** the Events item is highlighted in both
      places — it must not go dark after clicking into an event.
