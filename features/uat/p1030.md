# UAT: P1030 — Reverse Story and the Align Pipeline

Spec: [../p1030_reverse_story_and_align_pipeline.md](../p1030_reverse_story_and_align_pipeline.md)

These scenarios cover work that cannot be automated in CI: prod-only writes, the two
gate-exercise pairs from Decision 8, before/after query comparisons against live data, and
grep-based content checks over skill-file prose. Automated coverage lives in:

- `e2e/integration/p1030-calibration-exclusion.spec.ts`

## UAT-1: A reverse story exists in prod, delivered as a private letter

**Given:** The agent profile ("Slava's Agent") is bootstrapped in prod (AD-1) and authenticated
via password grant.

`mode = 'one-to-one'`.
**Then:** Query prod `stories` for the new row — `author_id` = agent, `experience_owner_id` =
founder, `visibility = 'private'`.

= test only, `.claude/rules/db-access.md`) — use curl with `PROD_SUPABASE_SERVICE_ROLE_KEY`. Paste
the row.

## UAT-6: Calibration averages — byte-identical before/after (Done-When)

**Given:** The founder's prod profile id, resolved at runtime (never hardcoded).
**When:** Run the exact query from AD-3 **before** UAT-2's rating happens, then **after**:

```sql
SELECT count(*) AS n,
       avg(speaker_rating)::numeric(12,6)  AS listener_calibration_avg,
       avg(listener_rating)::numeric(12,6) AS listener_self_rating_avg
FROM story_verifications
WHERE listener_id = :founder_id
  AND speaker_rating  IS NOT NULL
  AND listener_rating IS NOT NULL;
```

**Then:** All three values (`n`, `listener_calibration_avg`, `listener_self_rating_avg`) are
byte-identical across both runs.
**Verify:** Paste both outputs side by side. **Do not run this vacuously** — confirm a
`story_verifications` row for the reverse story exists between the two runs (query it), otherwise
the pair proves nothing (the reverse row was excluded from the aggregate by definition, but the
"exclusion happened" claim needs a row to exclude).

## UAT-9: `/align-decompose` recount gate — exercised failure + control (Decision 8, epistemic gate 7)

**Failure run:**
**Given:** A deliberate recount (conclusion only, no reasoning) fed to `/align-decompose`.
**When:** Run `/align-decompose`.
**Then:** The recount gate fires and blocks — the skill refuses to produce a story from a
conclusion-only paraphrase.
**Verify:** Paste the gate's refusal output and the exact input that triggered it.

**Control run:**
**Given:** A genuine reasoning-carrying paraphrase (same source item, expanded to include the
"why," not just the "what").
**When:** Run `/align-decompose`.
**Then:** The gate passes; a story + point + anti-point are produced.
**Verify:** Paste the produced story/point/anti-point. Confirm **nothing was written to prod** —
this is Done-When "Running `/align-decompose` alone writes nothing to prod." Check `clarity_docs`,
`stories`, `clarity_letters` row counts before and after the run; must be unchanged.

## UAT-10: `/align-create-letter` refuse-on-silence gate — exercised failure + control (Decision 8)

**Failure run:**
**Given:** `/align-create-letter` reaches the author-confirm gate.
**When:** Do not respond affirmatively — leave it silent, or respond ambiguously (not a clear
yes).
**Then:** The skill refuses and exits **without writing**. No flag bypasses it.
**Verify:** Paste the refusal. Confirm `clarity_letters` row count in prod is unchanged
before/after this run (query it — do not assert).

**Control run:**
**Given:** Same setup, this time responding with an explicit affirmative in the same turn.
**When:** Run `/align-create-letter` to completion.
**Then:** The letter is filed — `stories`, `points`, `story_points`, `point_positions`,
`clarity_docs`, `doc_stories`, `clarity_letters` rows all appear in the single atomic write. The
letter URL is printed and opened in the browser.
**Verify:** Paste each table's new row. Screenshot of the opened browser tab.
