# UAT: P1104 — A machine's reading of a person must never render as that person

Spec: [../p1104_agents_must_be_visually_distinguishable.md](../p1104_agents_must_be_visually_distinguishable.md)

**Read this first.** P1096's pipeline is unbuilt. There is no real agent account, no named
subject, and no generated avatar. Every automated fixture below is a **seeded** agent
account created through `create_or_reuse_agent_account` — the same call the pipeline will
make — and carries **no `avatar_url`**, so it renders initials rather than a robotified
portrait. That is deliberate: it means the automated suite proves the two channels that
survive 20px (the **square silhouette** and the **drained card**) plus the **name**,
without depending on an image that does not exist yet. The portrait channel is untested
and is listed under Blocked on P1096.

## UAT-1: Migration applied — schema, grants and guards exist

**Given:** the P1104 migration applied to the environment under test.
**When:** the migration spec runs.
**Then:** all 35 cases pass — `subject_key` returns 42501 for anon and authenticated while
`profile_id`/`operator_name` are readable; both client roles are blocked from
INSERT/UPDATE/DELETE; the RPC is service_role-only; reuse returns the first id and writes
nothing on the second call; a failing call leaves no orphan row in either table; a created
agent holds no pledge, no verification and no ear count; the reserved prefix is rejected in
**fifteen** variants — including the nine invisible-character and homoglyph bypasses found
during adversarial review — while four legitimate names, among them `Jean · Pierre`, still
pass, proving the guard discriminates rather than blanket-rejecting.
**Verify:** paste the Playwright summary line.

## UAT-2: Cold read — a stranger says the row is not a person

**Given:** a seeded agent account holding a position on a point, shown on `/point/:id`.
**When:** someone who has not read this spec is shown the page cold, with no explanation.
**Then:** they say, unprompted, that the row is not a person.
**Verify:** **Manual. Acceptance Criterion 1 — cannot be automated.** The automated suite
proves the signals are present (square avatar, no ring, no ear count, `Agent ·` name,
drained chrome); it cannot prove a stranger *reads* them correctly. Record the verbatim
reaction.
**Caveat to state to the tester's reviewer:** with no avatar image on the fixture, this
cold read tests a weaker specimen than the shipped one. A pass here is meaningful; a
failure would be more so.

## UAT-3: Cold read — the position is the reading's, not the speaker's

**Given:** the same cold-read setup.
**When:** the tester is asked what the row's position means.
**Then:** they say something equivalent to *"that's what the argument in that source
implies"* — **not** *"that's what the speaker thinks."*
**Verify:** **Manual. Acceptance Criterion 2 — cannot be automated.** No test assesses
comprehension of a semantic distinction.

## UAT-6: The registry row is what drives the marker

**Given:** a seeded agent account rendering with the marker.
**When:** only its `agent_accounts` row is deleted — profile, name and flags untouched —
and the page is reloaded.
**Then:** it renders as a person again.
**Verify:** **Automated** (`the registry row is what drives the marker`). This is the
gate-7 falsification: it proves the marker follows row existence rather than the
`Agent · ` name string or any flag that happens to correlate with it.

## Blocked on P1096

These cannot be run at all until the pipeline exists. They need a real subject, a real
rights-cleared photograph, or an actual pipeline run — a fixture cannot substitute.

1. **The robotified portrait at 20 / 40 / 96px**, including the measurement the spec's
   design rests on (at 20px the portrait is indistinguishable from the source photograph).
   Needs `/slava:content:gen-agent-avatar` to have run against a real photograph.
   **Partly closed since:** one E2E fixture now carries a real image, so
   `GravatarAvatar`'s `<img>` branch is exercised — square shape, no ring, disclosing alt
   text and un-drained colour are all asserted against a photograph rather than initials.
   What remains blocked is the *legibility* judgement at 20px, which needs the real
   robotified portrait, not a placeholder.
2. **Rights clearance of the source photographs** (`gen-agent-avatar` Step 0) — a manual
   human-judgment gate over images that do not exist.
3. **Both subjects named.** Nobody has chosen them; the spec says they cannot be chosen in
   advance because the pipeline creates them at runtime.
4. **"An account created by a pipeline run and NOT hand-registered."** Under the shipped
   mechanism this scenario is unreachable through the sanctioned path — creation and
   registration are one transaction, which the atomicity test proves. UAT-6 covers the
   residual the spec actually names: a second writer producing a profile with no registry
   row.
5. **Reuse across two real pipeline runs on the same subject.** Reuse is tested
   mechanically here (same `subject_key`, two calls); *when* the pipeline decides to reuse
   lives in P1096.
6. **Whether a claimed subject's portrait reads differently from an unclaimed one** — the
   spec itself flags this as unanswerable from this side of the screen.
