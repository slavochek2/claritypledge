### What the code review changed, and what it deliberately did not

**Fixed:** a header comment in `verify-all.mjs` that claimed `verify-fixture.mjs` "is not swept" while the array three lines below it swept exactly that (the file's own philosophy depends on its scope statements being accurate); an unescaped-dot regex in `two-callers.mjs` (`replace` → `replaceAll`, latent, would misfire only on a future module name carrying two dots); and the DW-20 wiring below.

**Attempted and REVERTED — the finding is real, the fix is not mechanical.** `store-inspection-scan.mjs` matches only `ls|find|cat|stat|test -f`, so `grep -r diarize-store ~/.local/share` passes; `input-block-scan.mjs`'s `INPUT_ASK` is anchored on the literal word "ask", so *"confirm the event tag with the founder"* passes. Both were widened; the gate went **red with three false positives**, including a line describing `grep -F` against a **transcript** being read as a store inspection. Widening trades false negatives for false positives, and §12's non-goal forbids tuning these mid-branch. Reverted, and carried to a follow-up spec. **This is `epistemic.md` gate 7c doing its job** — the widened gate was run against work that was already correct, and it rejected it.

**Accepted, not fixed:** `two-callers.mjs` cannot distinguish a runnable stanza from a prose mention of the same command (no current false pass; both affected modules have a genuine invocation elsewhere); `redact-run.mjs` resolves a cast code by surname only, so two arguers sharing a surname would collide (no such roster exists; no fixture covers it); `store-inspection-scan.mjs` requires verb and store name on the **same line**, so a two-line instruction evades it. All three go to the follow-up spec.
