## Root cause of UAT-1/2/3/4 (reproduced outside the browser)

`stripHashtags` collapses newlines to spaces. Five of six surfaces call
`stripQuoteLabel(stripHashtags(...))` — inner first — so by the time `stripQuoteLabel` runs, the
label is no longer at line start and its anchored `/^[ \t]*Supporting quotes from .*$/gm` never
matches.

Measured on the real DB content for story `8eaedb56`:

```
RAW around label   : "oblem.\n\nSupporting quotes from Yann LeCun\n\n\"we'r"
AFTER stripHashtags: "roblem. Supporting quotes from Yann LeCun \"we're"
stripQuoteLabel(raw)              -> label removed    : true
stripQuoteLabel(stripHashtags(x)) -> label removed    : false
```

`live-story-card-expanded.tsx:141` is the only surface with the order reversed
(`stripQuoteLabel` first, `stripHashtags` second) and is the only one that works.

## Why the suite did not catch it

`p1212-quote-label-parity.test.tsx` implements the `suppresses label` policy as
`expect(source).toContain('stripQuoteLabel')` — a source grep for the token, not a behavioural
check that the label leaves the rendered text. 48 tests pass, 0 fail, while the label is visibly
on screen on four surfaces. The one behavioural render test in that file targets the live card,
which is the single surface whose argument order is correct.
