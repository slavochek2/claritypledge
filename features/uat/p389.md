# UAT Scenarios: P151 - Position Loading Architecture

**Feature:** System-wide position loading architecture with efficient batch methods and React hooks

**Test Environment:** Production or staging with real user accounts

---

## Scenario 1: Profile Page Position Loading

**Given:** User has created points with positions
**When:** Viewing their own profile
**Then:** Position badges display correctly

### Setup
1. Login as test user (e.g., `test-user-1@example.com`)
2. Create 3 points:
   - Point A: "Climate change requires immediate action"
   - Point B: "Remote work improves productivity"
   - Point C: "AI will replace most jobs by 2030"
3. Set positions:
   - Point A: Strongly Agree
   - Point B: Agree
   - Point C: Disagree

### Execution
1. Navigate to your profile page (`/p/{your-slug}`)
2. Click "Points" tab
3. Observe position badges on each point card

### Expected Results
- [ ] Point A shows "Strongly Agree" badge
- [ ] Point B shows "Agree" badge
- [ ] Point C shows "Disagree" badge
- [ ] Position buttons reflect current selections (aria-pressed="true")
- [ ] Position counts are accurate (at minimum: 1 for your position)

### Acceptance Criteria
- All position badges are visible and correctly labeled
- Badge colors match design system (green for agree, red for disagree, gray for unsure)
- No console errors related to position loading
- Page loads within 2 seconds (even with 10+ points)

## Scenario 2: Batch Loading Efficiency (Performance Test)

**Given:** User has 10+ points with positions
**When:** Loading profile page
**Then:** Uses batch methods (not N+1 queries)

### Setup
1. Login as test user
2. Create 15 points with varied statements
3. Set positions on all 15 points (mix of agree/disagree/unsure)
4. Logout

### Execution
1. Open browser DevTools → Network tab
2. Filter by "Fetch/XHR"
3. Navigate to test user's profile (`/p/{test-user-slug}`)
4. Click "Points" tab
5. Wait for all points to load
6. Review network requests

### Expected Results
- [ ] **1 request** to `getPointsForProfileDisplay` or equivalent batch endpoint
- [ ] **0 individual requests** to `getPointWithUserPosition` (no N+1 pattern)
- [ ] Total requests for position data: ≤ 3 (points query, counts batch, positions batch)
- [ ] Page renders all 15 points with positions within 2 seconds

### Acceptance Criteria
- No N+1 query pattern detected (no loop of individual point requests)
- Database query count ≤ 3 for position loading (regardless of point count)
- Performance scales: 100 points should still use ≤ 3 queries
- Console logs (if enabled) show batch method calls, not individual calls

### Performance Benchmark
| Points Count | Max DB Queries | Max Load Time |
|--------------|----------------|---------------|
| 10           | 3              | 1.5s          |
| 50           | 3              | 2.0s          |
| 100          | 3              | 3.0s          |

- [ ] `points` array contains `PointWithUserPosition[]` type

## Scenario 5: Service Method Patterns

**Given:** Using new service methods
**When:** Loading points for display
**Then:** Returns `PointWithUserPosition[]` type

### Setup
1. Code review or unit test environment
2. Access to `pointsService` instance

### Execution (Manual Testing)
```typescript
// Test in browser console or unit test:

  'user-id-123',
  'viewer-id-456'
);

console.log('Type check:', points[0]);
```

### Expected Results
- [ ] Method exists: `getPointsForProfileDisplay(validatorId, viewerUserId?)`
- [ ] Returns: `Promise<PointWithUserPosition[]>`
- [ ] Each point includes:
  ```typescript
  {
    id: string,
    statement: string,
    positionCounts: { agree: number, disagree: number, unsure: number },
    totalPositions: number,
    userPosition?: { position: 'agree' | 'disagree' | 'unsure', reasoning?: string }
  }
  ```
- [ ] If `viewerUserId` is `undefined`, `userPosition` is also `undefined`
- [ ] Position counts are always present (even if zero)

### Acceptance Criteria
- Service interface includes new methods (TypeScript compilation passes)
- Real service implementation matches interface
- Mock service implementation matches interface (for tests)
- Method handles edge cases:
  - Empty results (user has no points)
  - No viewer (unauthenticated)
  - Viewer has no positions on any points

## Scenario 6: Type Enforcement

**Given:** Component expects `PointWithUserPosition[]`
**When:** Passing incomplete point data
**Then:** TypeScript compilation fails

### Setup
1. Code editor with TypeScript enabled
2. Component that accepts `points: PointWithUserPosition[]` prop

### Execution (Compile-Time Check)
```typescript
// Attempt to pass incomplete data:
const incompletePoints: PointWithCreator[] = await pointsService.getPointsByValidator('user-id');
<PointCard points={incompletePoints} /> // Should fail TypeScript check
```

### Expected Results
- [ ] TypeScript error: `Type 'PointWithCreator[]' is not assignable to type 'PointWithUserPosition[]'`
- [ ] Missing properties highlighted: `positionCounts`, `totalPositions`
- [ ] IDE shows error before runtime
- [ ] `npm run build` fails (cannot deploy broken code)

### Acceptance Criteria
- Type system prevents passing incomplete point data to UI components
- Developers cannot accidentally use `getPointsByValidator()` for display
- ESLint rule (if implemented) warns about deprecated methods
- Pre-commit hook catches deprecated patterns

## Scenario 7: Multiple Viewers on Same Profile

**Given:** Two users view the same profile with different positions
**When:** Each user loads the profile
**Then:** Each sees their own position, not the other's

### Setup
1. User A creates Point X
2. User A positions: Agree
3. User B positions on Point X: Disagree
4. Both users navigate to User A's profile

### Execution
1. Login as User A → View own profile → Observe Point X
2. Logout
3. Login as User B → View User A's profile → Observe Point X
4. Logout
5. Open incognito → View User A's profile → Observe Point X

### Expected Results

**User A sees:**
- [ ] Point X with "Your position: Agree" badge
- [ ] Position counts: "1 Agree, 1 Disagree"

**User B sees:**
- [ ] Point X with "Your position: Disagree" badge
- [ ] Position counts: "1 Agree, 1 Disagree"

**Unauthenticated sees:**
- [ ] Point X with no user position badge
- [ ] Position counts: "1 Agree, 1 Disagree"

### Acceptance Criteria
- User positions are viewer-specific (not cached globally)
- Position counts are consistent across all viewers
- No position leakage between users
- Logging out clears user position badges
