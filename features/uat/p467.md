# UAT: P467 — /chat slim context header + inline rating

**Spec:** `features/p467_chat_context_header_inline_rating.md`
**Branch:** feature/p467 (check out before testing)
**Entry URL:** `/chat?from=position&pointId=<any-point-id-where-you-have-a-position>`

---

## Setup

1. Log in as yourself (or create a test account)
2. Navigate to any point where you have staked a position
3. Click "Write your story" or navigate to `/chat?from=position&pointId=<id>` directly
4. Have browser DevTools open (Console tab) to catch JS errors

---

## 1. Context Header

### 1a. Header renders correctly

- [ ] A slim sticky header appears below the nav bar, above the thread
- [ ] Header shows a Pin icon + truncated point text + position chip + [↗] icon
- [ ] Header height is ≤52px when measured at 375px viewport width (check in DevTools responsive mode)
- [ ] The OLD PointCardWithLinks pattern is gone: no "Vyacheslav Agrees:" quote, no interactive position buttons, no share button, no story CTA footer rows

### 1b. Position chip shows 1st-person text

- [ ] If your position is "agree" → chip shows **"You agree"** (not "Agrees" or "Vyacheslav Agrees:")
- [ ] If your position is "disagree" → chip shows **"You disagree"**
- [ ] If your position is "unsure" → chip shows **"You're unsure"**
- [ ] The chip is NOT clickable / does NOT open a dropdown

### 1c. Point text truncation + expand

- [ ] Long point text is truncated to one line with ellipsis
- [ ] Tapping/clicking the text area expands to show the full text
- [ ] Tapping again collapses back to one line
- [ ] Short point text (fits in one line) shows no expand affordance

### 1d. [↗] link

- [ ] Clicking [↗] navigates to `/point/:id` (the point detail page)
- [ ] Browser Back button returns to `/chat` with scroll position preserved

### 1e. No position (edge case)

- [ ] When you have no position on a point (rare case), header shows point text + [↗] but no chip
- [ ] Header layout is not broken without the chip

---

## 2. Rating Phase — Inline in Thread

### 2a. Rating prompt appears in thread (not a Drawer)

- [ ] After AI produces a draft, the rating prompt appears as an **AI message bubble** in the thread
- [ ] The bubble contains: "How well does this capture what you meant?" + 0–10 button row
- [ ] **No Drawer pops up from the bottom** — there is no bottom sheet or overlay
- [ ] The draft content does NOT appear twice (not duplicated in a drawer above the buttons)

### 2b. Click path

- [ ] Clicking any button [0]–[10] immediately sends the rating — **no separate Send button required**
- [ ] The selected number appears as a user message bubble in the thread
- [ ] The button row becomes non-interactive (visually grayed/frozen) after selection
- [ ] AI streaming begins for the next response
- [ ] The 0–10 buttons are visually clear at 375px width — labels "10" readable, tap targets ≥44px height

### 2c. Type path

- [ ] During rating phase, the input bar placeholder reads: `"What's off? Or type 0–10..."`
- [ ] Typing "7" + pressing Enter sends "7" as a user message (same as clicking [7])
- [ ] Typing "8 — the opening feels off" + Enter sends the message as-is (AI interprets mixed input)
- [ ] After send, input bar clears normally

### 2d. Escape hatch

- [ ] **On 1st iteration only:** No "Save as-is →" link visible below the rating buttons
- [ ] **On 2nd iteration onwards (iterationCount >= 1):** "Save as-is →" link appears below buttons
- [ ] Clicking "Save as-is →" transitions directly to the visibility/save flow
- [ ] The VisibilityAndSave panel renders inline in the thread (not a modal)
- [ ] The previous rating bubble stays frozen in thread history (escape hatch link becomes inert)
