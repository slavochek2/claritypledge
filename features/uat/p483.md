# P483 UAT Scenarios

## UAT-1: Create Page — Name Override for Existing User

### UAT-1.1: Lookup auto-overrides name even if creator typed first
**Given:** Creator is on `/agreements/new` and has typed "Wrong Name" in partner name field
**When:** Creator enters an existing user's email in the email field
**Then:** Partner name field updates to the existing user's profile name AND becomes read-only (no cursor, tinted background)
**Verify:** Playwright E2E (TC-01) + visual check via `/verify`

### UAT-1.2: "Using their registered name" notification
**Given:** Creator entered an existing user's email and lookup completed
**When:** "Account found" badge appears
**Then:** Below the avatar badge, muted text reads "Using their registered name"
**Verify:** Playwright E2E (TC-02)

### UAT-1.3: Name field reverts on email change
**Given:** Name field is locked from a successful lookup
**When:** Creator clears or changes the email field
**Then:** Name field reverts to editable + empty, notification disappears
**Verify:** Playwright E2E (TC-03)

### UAT-1.4: Non-existing email keeps field editable
**Given:** Creator enters an email with no account
**When:** Lookup returns "No account found"
**Then:** Name field stays editable, no "Using their registered name" text
**Verify:** Playwright E2E (TC-04)

## UAT-2: Accept Page — Existing User, Logged In

### UAT-2.1: Profile name shown read-only
**Given:** Existing user is logged in and navigates to accept page via invite link
**When:** Page loads with `pageState === 'partner'`
**Then:** Partner name appears as read-only text in "We, X and Y, agree to:" — no editable input field anywhere
**Verify:** Playwright E2E (TC-05)

### UAT-2.2: Profile name overrides creator-typed name
**Given:** Creator typed "Wrong Name" when creating the agreement, but partner's profile name is "Jane Doe"
**When:** Existing user (Jane Doe) opens the accept page while logged in
**Then:** Certificate shows "Jane Doe" (profile name), NOT "Wrong Name" (creator-typed)
**Verify:** Playwright E2E (TC-06)

### UAT-2.3: Direct to certificate after signing
**Given:** Existing user clicks "I Accept & Co-Sign" on the accept page
**When:** Accept succeeds
**Then:** User navigates to `/agreements/{id}` (certificate detail page), NOT to email confirmation
**Verify:** Manual — sign an agreement as existing user, verify redirect

## UAT-3: Accept Page — Existing User, NOT Logged In

### UAT-3.1: CTA says "Sign In to Co-Sign"
**Given:** Existing user clicks invite link from email, arrives unauthenticated
**When:** Accept page loads and detects existing user
**Then:** Primary CTA button reads "Sign In to Co-Sign" (not "Seal & Sign")
**Verify:** Playwright E2E (TC-07)

### UAT-3.2: No name input and no "Already have an account?" link
**Given:** Existing user on accept page, unauthenticated
**When:** Page detects existing user via partner email lookup
**Then:** No "Your name on this agreement" input field visible. No "Already have an account? Log in" link below certificate.
**Verify:** Playwright E2E (TC-08)

### UAT-3.3: OTP triggers correctly on CTA click
**Given:** Existing user clicks "Sign In to Co-Sign"
**When:** OTP magic link is sent
**Then:** User is redirected to sign-in flow (either interstitial with sign-in messaging or login page)
**Verify:** Manual — click button, verify OTP email received

## UAT-4: New User Path (Regression)

### UAT-4.1: New user sees editable name + "Seal & Sign"
**Given:** New user (no account) clicks invite link, arrives unauthenticated
**When:** Accept page loads
**Then:** Editable "Your name" input visible, CTA says "Seal & Sign", "Already have an account?" link visible
**Verify:** Playwright E2E (TC-09)

### UAT-4.2: New user full flow unchanged
**Given:** New user completes "Seal & Sign" flow
**When:** OTP sent, user clicks magic link, returns to accept page
**Then:** Auto-accept fires, agreement becomes active, user sees certificate
**Verify:** Manual — full flow walkthrough with a new email

## UAT-5: Edge Cases

### UAT-5.1: Existing user with empty profile name
**Given:** Existing user has no name set (profile name is null/'Unknown')
**When:** Their email is looked up on create page OR they open accept page
**Then:** Name field stays editable (fallback to creator-typed name). On accept page, editable name input appears.
**Verify:** Manual — create a test user without a name, test both pages

### UAT-5.2: Wrong user logged in
**Given:** User A is logged in, but the invite was sent to User B (also existing)
**When:** User A opens the invite link
**Then:** "This agreement has already been signed or is not addressed to you" message shown
**Verify:** Manual — log in as wrong user, open invite link
