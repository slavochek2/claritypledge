# UAT: P527 — Direct Sign for New Users

## Prerequisites
- Test project edge function `create-and-sign` deployed
- A test creator account with ability to send invitations
- Access to a fresh email address (not registered on ClarityPledge)

---

## UAT-1: Happy Path — New User Signs Without Email Round-Trip

**Given:** Creator has sent an invitation to a fresh email address (no existing account)
**When:** The invited partner clicks the invitation link in their email
**Then:** They land on the accept page showing name input + sign button

**When:** Partner enters their name and clicks "Sign"
**Then:**
- [ ] Agreement is signed immediately (no "check your email" page)
- [ ] Partner sees the signed agreement with both signatures
- [ ] Partner is authenticated (can navigate to other pages)
- [ ] Agreement shows status "Active"

**Verify:** Manual browser test. Check Network tab — confirm `create-and-sign` edge function was called (not `signInWithOtp`).

---

## UAT-2: Profile Completeness

**Given:** New user has just completed UAT-1
**When:** Partner navigates to their profile page (`/p/<slug>`)
**Then:**
- [ ] Profile exists with the name they entered
- [ ] Slug is auto-generated from their name
- [ ] Avatar color is assigned (from the palette)
- [ ] Email matches the invitation email

**Verify:** Check `/p/<slug>` page + Supabase dashboard profiles table.

---

## UAT-3: Session Persistence

**Given:** New user has just completed UAT-1
**When:** Partner refreshes the browser
**Then:**
- [ ] Session persists — still logged in
- [ ] Can navigate to /connections and see their agreement

**When:** Partner closes the browser tab and reopens ClarityPledge
**Then:**
- [ ] Session still active (within the standard JWT expiry window)

**Verify:** Manual browser test — refresh and check auth state.

---

## UAT-4: Creator Notification

**Given:** New user has just completed UAT-1
**When:** Check the creator's email inbox
**Then:**
- [ ] Creator received an "agreement accepted" email notification
- [ ] Email content is the same as before P527 (no regression)

**Verify:** Check creator's inbox (or Mailgun logs).

---

## UAT-5: Existing User Flow Unchanged (Regression)

**Given:** An existing ClarityPledge user receives an invitation
**When:** They click the invitation link
**Then:**
- [ ] P488 magic link flow works (arrive authenticated, can sign immediately)
- [ ] NOT the direct-sign flow (no edge function call for existing users)

**Verify:** Manual test with an existing account. Check Network tab — should NOT see `create-and-sign` call.

---

## UAT-6: Fallback — Edge Function Failure

**Given:** The `create-and-sign` edge function is unavailable (simulate by temporarily undeploying or blocking the endpoint)
**When:** New user tries to sign the agreement
**Then:**
- [ ] System falls back to the current OTP flow
- [ ] User sees "check your email" confirmation page
- [ ] User can complete signing via the magic link email (existing flow)
- [ ] No error message shown to the user about the edge function failure

**Verify:** Undeploy the edge function temporarily, attempt to sign, observe fallback.

---

## UAT-7: Decline Flow Unchanged

**Given:** New user (no account) clicks the invitation link
**When:** They click "Decline"
**Then:**
- [ ] Agreement is declined
- [ ] No account was created for the partner
- [ ] Creator receives the decline notification email

**Verify:** Manual test — decline, then check Supabase auth.users for the partner email (should not exist).

---

## UAT-8: Token Replay Protection

**Given:** New user has already signed the agreement (token consumed)
**When:** Someone navigates to the same accept URL with the same token
**Then:**
- [ ] Page shows invalid/expired state
- [ ] Cannot sign again
- [ ] No duplicate account created

**Verify:** Copy the accept URL, complete signing, then paste the URL in a new incognito window.
