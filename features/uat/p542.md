# UAT: P542 — Collapse Stories Behind Chevron on Point Page

## UAT-1: All collapsed default state
**Given:** Visitor navigates to a point detail page with 3+ position holders (some with stories)
**When:** Page loads
**Then:** All position holders render as uniform compact rows (avatar + name + EarBadge + PositionBadge)
**Then:** Rows with linked stories show a `>` chevron + "story" text indicator on the right
**Then:** No story cards are visible — all collapsed by default
**Then:** Story text, author headers, and ThreadLine connecting lines are absent
**Verify:** Load point page → all rows compact, no story cards visible. Chevrons only on rows with stories.

## UAT-2: Expand story via chevron
**Given:** Point page with a position holder who has a linked story (chevron visible)
**When:** Visitor clicks the chevron + "story" area
**Then:** Chevron rotates from `>` to `v`
**Then:** Story card expands below the row with a ThreadLine vertical connecting line
**Then:** Story card shows: avatar (regular size with pledger ring) + author name header
**Then:** Story card shows: role, relative date, visibility badge
**Then:** Story card shows: story text (150-char truncation with "...more")
**Then:** Story card shows: tag pills, "N understood" count, Share button
**Verify:** Click chevron → card expands with all elements. ThreadLine connects row to card.

## UAT-3: Collapse story via chevron
**Given:** A story is currently expanded on the point page
**When:** Visitor clicks the same chevron again
**Then:** Story card collapses with animation
**Then:** Chevron rotates back from `v` to `>`
**Then:** ThreadLine connecting line disappears
**Then:** Position list returns to all-compact state
**Verify:** Expand then collapse → row returns to compact. No residual visual artifacts.

## UAT-4: Accordion — only one story at a time
**Given:** Point page with 2+ position holders who have linked stories
**When:** Visitor expands Story A's chevron
**Then:** Story A is visible
**When:** Visitor clicks Story B's chevron
**Then:** Story B expands
**Then:** Story A auto-collapses
**Then:** Only one story card visible at any time
**Verify:** Expand A → expand B → A is collapsed, B is visible. Never two cards open.

## UAT-5: Click story card navigates to story detail
**Given:** A story is expanded on the point page
**When:** Visitor clicks the story card body (not the chevron, "...more", or Share)
**Then:** Page navigates to `/story/{storyId}` — the story detail page
**Verify:** Click expanded card → arrives at story detail page with full story.

## UAT-6: Viewer's own story (authenticated, has story)
**Given:** Logged-in user who has taken a position AND has a linked story
**When:** User views the point page
**Then:** User's own row shows chevron + "story" (same as any other holder)
**When:** User clicks own chevron
**Then:** Own story card expands (identical behavior to other holders)
**Verify:** Log in as story author → own row has chevron, expands own story.

## UAT-7: Viewer's "Add your story" CTA (authenticated, no story)
**Given:** Logged-in user who has taken a position but has NO linked story
**When:** User views the point page
**Then:** User's own row shows "Add your story →" CTA link where the chevron would be
**Then:** No chevron visible on this row
**When:** User clicks "Add your story →"
**Then:** Navigates to `/create?pointId={id}`
**Verify:** Log in as position holder without story → CTA visible, navigates to create page.

## UAT-8: Mobile layout (360px)
**Given:** Point page viewed on a 360px-wide viewport
**When:** Page loads with position holders
**Then:** Compact rows may wrap PositionBadge + chevron to second line (acceptable)
**Then:** Chevron touch target is at least 44px tall
**When:** Visitor taps chevron
**Then:** Story card expands, fills available width minus ThreadLine indent
**Then:** Story text wraps correctly with `break-words`
**Then:** Tag pills wrap naturally
**Then:** No horizontal overflow or clipping
**Verify:** Resize to 360px → rows render, chevron works, expanded card fits without overflow.

## UAT-9: Embed mode — iframe resize on expand/collapse
**Given:** Point page loaded in an iframe (embed mode)
**When:** Visitor clicks a chevron to expand a story
**Then:** `postMessage({ type: 'resize', height: ... })` fires after animation
**Then:** iframe height increases to fit expanded content
**When:** Visitor collapses the story
**Then:** `postMessage` fires with smaller height
**Then:** iframe shrinks accordingly
**Verify:** Open point in embed mode → expand/collapse triggers iframe resize. No content clipped.

## UAT-10: Avatar ring not clipped
**Given:** Position holder with pledger status
**When:** Viewing compact row (collapsed)
**Then:** Avatar at compact size — pledger ring suppressed (no clipping)
**When:** Story is expanded
**Then:** Avatar in story card header at regular size — pledger ring visible and not clipped
**Verify:** Check pledger avatar in both compact and expanded states — no ring overflow.

## UAT-11: Profile pages unchanged (regression)
**Given:** User has stories linked to points
**When:** Visiting the user's profile page (Points tab, Stories tab)
**Then:** Stories display in existing format — no chevron/accordion pattern
**Then:** Stories tab shows stories with linked points (QuotedPoint pattern)
**Then:** Points tab shows points with position badges
**Verify:** Visit profile page → stories visible without expand interaction. No visual change from before P542.

## UAT-12: Filter tab interaction with expanded state
**Given:** A story is expanded on the point page
**When:** Visitor switches filter tab (e.g., from Agree to Disagree)
**Then:** All stories collapse (expandedHolderId resets to null)
**When:** Visitor switches back to original tab
**Then:** All rows are in collapsed state — previously expanded story does not auto-reopen
**Verify:** Expand story → switch tab → switch back → all collapsed.

## UAT-13: Story fetch failure graceful degradation
**Given:** Point page where story data fails to load (network issue)
**When:** Page renders
**Then:** All rows render as compact (no chevrons) — same as if no stories exist
**Then:** No error UI shown to visitor
**Verify:** This is a preserved edge case from P411 — confirm no regression.
