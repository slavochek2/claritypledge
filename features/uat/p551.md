# UAT: P551 — Clarity Docs: Curated Story Collections

## Doc List & Creation

### UAT-1: View doc list
**Given:** Authenticated user navigates to `/docs`
**When:** Page loads
**Then:** "Your Docs" heading is visible with a "+ New" button
**Then:** If user has docs, each doc card shows: visibility icon (lock/globe), title, story count, last updated
**Then:** If user has no docs, an empty state message or prompt is shown
**Verify:** Navigate to `/docs` as authenticated user. Empty state if no docs. List if docs exist.

### UAT-2: Create a private doc
**Given:** User is on `/docs` and clicks "+ New"
**When:** Creation modal opens
**Then:** Modal shows title input and visibility toggle (Private/Public), defaulting to Private
**When:** User types "My Therapy Notes" and clicks "Create Doc"
**Then:** Modal closes, browser navigates to `/d/:newDocId`
**Then:** Doc title "My Therapy Notes" is visible, privacy banner says "Only you can see this"
**Verify:** Create private doc -> navigate to doc page -> title and privacy banner visible.

### UAT-3: Create a public doc
**Given:** User is on `/docs` and clicks "+ New"
**When:** User types "Workshop Beliefs" and selects Public visibility, then clicks "Create Doc"
**Then:** Browser navigates to `/d/:newDocId`
**Then:** Doc title "Workshop Beliefs" is visible, no privacy banner (or "Public" indicator)
**Verify:** Create public doc -> navigate to doc page -> no privacy banner, public visibility shown.

## Doc Detail Page

### UAT-4: View doc with stories
**Given:** A private doc "Session Notes" with 2 stories exists
**When:** Owner navigates to `/d/:docId`
**Then:** Title "Session Notes" visible, "2 stories" count displayed
**Then:** Privacy banner "Only you can see this" persists at top (doesn't scroll away)
**Then:** Each story card shows: content text, author, date, visibility indicator (lock/globe)
**Verify:** Open doc with stories -> all story cards visible in correct order with metadata.

### UAT-5: Rename doc title inline
**Given:** Owner is on doc detail page
**When:** Owner clicks the doc title
**Then:** Title becomes editable (inline input or contenteditable)
**When:** Owner types "Renamed Doc" and presses Enter
**Then:** Title updates to "Renamed Doc" and persists on page refresh
**Verify:** Rename title -> refresh page -> new title persists.

### UAT-6: Privacy banner sticky behavior
**Given:** Private doc with 5+ stories (enough to scroll)
**When:** Owner scrolls down through the stories
**Then:** Privacy banner stays visible at top of viewport (sticky or fixed)
**Verify:** Scroll through a long private doc -> privacy banner always visible.

## Adding Content

### UAT-7: Write a new story inline (private doc)
**Given:** Owner is on a private doc detail page
**When:** Owner focuses the bottom input area and writes "Last Tuesday when we discussed the budget..."
**Then:** Textarea expands to accommodate text
**When:** Owner clicks "Add to Doc" button
**Then:** New story card appears in the doc with the written content
**Then:** New story is automatically private (matching doc visibility)
**Then:** Story card shows lock icon (private visibility indicator)
**Verify:** Write story in private doc -> story appears with lock icon -> DB: story.visibility = 'private'.

### UAT-8: Write a new story inline (public doc)
**Given:** Owner is on a public doc detail page
**When:** Owner writes a story and submits
**Then:** New story is automatically public (matching doc visibility)
**Then:** Story card shows globe icon
**Verify:** Write story in public doc -> story has visibility = 'public'.

### UAT-9: Select existing story and add to doc
**Given:** Owner is on a doc detail page with the bottom input expanded
**When:** Owner clicks "Select from your existing stories" or equivalent
**Then:** List of owner's stories appears (filtered to match doc visibility rules)
**When:** Owner clicks "Add" next to a story
**Then:** Story appears in the doc
**Verify:** Select existing story -> appears in doc with correct position.

### UAT-10: Cannot add private story to public doc
**Given:** Owner has a private story and a public doc
**When:** Owner tries to add the private story to the public doc
**Then:** Action is blocked — either the private story doesn't appear in the selector, or an error toast explains why
**Verify:** Private stories are not selectable in public doc story picker.

### UAT-11: Public stories in private doc retain independence
**Given:** Owner adds an existing public story to a private doc
**When:** Visitor navigates to the story author's profile
**Then:** The public story is still visible on the profile (doc privacy doesn't hide it)
**Verify:** Public story added to private doc -> still visible on author's profile.

### UAT-12: Same story cannot be added twice to the same doc
**Given:** A story is already in the doc
**When:** Owner tries to add it again via the story selector
**Then:** It is either grayed out, hidden, or a toast explains "Already in this doc"
**Verify:** Attempt duplicate add -> blocked or explained.

## Ordering & Curation

### UAT-13: Reorder stories via drag-and-drop
**Given:** Doc has 3 stories: A, B, C (in order)
**When:** Owner drags story C above story A
**Then:** Order becomes C, A, B
**Then:** Order persists on page refresh
**Verify:** Drag-reorder stories -> refresh -> order preserved.

### UAT-14: Reorder stories via keyboard
**Given:** Doc has stories and owner focuses a drag handle
**When:** Owner presses Space (grab), then Arrow Up, then Space (drop)
**Then:** Story moves up one position
**Then:** Screen reader announces the move (aria-live region)
**Verify:** Keyboard reorder -> story moves -> announcement heard by screen reader.

### UAT-15: Remove story from doc
**Given:** Doc has a story
**When:** Owner opens the card menu (...) and clicks "Remove from doc"
**Then:** Story disappears from the doc page
**Then:** Story still exists on the owner's profile (not deleted, just unlinked)
**Verify:** Remove story from doc -> gone from doc, still exists in stories table.

## Privacy & Visibility

### UAT-16: Private doc invisible to non-owner (URL guessing)
**Given:** User A has a private doc at `/d/:docId`
**When:** User B (authenticated, different user) navigates to `/d/:docId`
**Then:** Doc content is NOT shown — "Not found" or "Access denied" message
**Verify:** Log in as different user -> navigate to private doc URL -> access denied.

### UAT-17: Private doc invisible to anonymous user
**Given:** A private doc exists at `/d/:docId`
**When:** Unauthenticated user navigates to `/d/:docId`
**Then:** Redirected to login or shown "Not found"
**Then:** Doc title and content are NOT visible in the page source
**Verify:** Open private doc URL in incognito -> no content leaked.

### UAT-18: Private doc not in search or discovery
**Given:** A private doc exists
**When:** Non-owner searches or browses the site
**Then:** Private doc title and content never appear in search results, feed, or profiles
**Verify:** Search for private doc title as non-owner -> zero results.

### UAT-19: Public doc accessible to all authenticated users
**Given:** User A has a public doc at `/d/:docId`
**When:** User B navigates to `/d/:docId`
**Then:** Doc content is visible (read-only — no edit controls for non-owner)
**Verify:** Visit public doc as non-owner -> content visible, no edit controls.

## Doc Deletion

### UAT-20: Delete doc with confirmation
**Given:** Owner is on a doc detail page
**When:** Owner opens menu and clicks "Delete Doc"
**Then:** Confirmation dialog appears ("This will permanently delete this doc")
**When:** Owner confirms deletion
**Then:** Doc is deleted, user is redirected to `/docs`
**Then:** DB: doc and doc_stories rows are gone, stories still exist
**Verify:** Delete doc -> redirected to /docs -> doc gone from list and DB.

### UAT-21: Cancel delete preserves doc
**Given:** Delete confirmation dialog is open
**When:** Owner clicks "Cancel" or presses Escape
**Then:** Dialog closes, doc is preserved
**Verify:** Cancel delete -> doc still exists.

**When:** User clicks "Docs"

**Verify:** Click Docs in nav -> arrives at /docs.

### UAT-23: Docs accessible from mobile nav
**Given:** Authenticated user on mobile
**When:** Mobile nav is opened (hamburger menu or bottom nav)
**Then:** "Docs" option is accessible
**When:** User taps "Docs"
**Then:** Navigates to `/docs`
**Verify:** Docs reachable from mobile nav -> /docs loads.

## Edge Cases

### UAT-24: Doc with 0 stories shows empty state
**Given:** A doc exists with no stories added
**When:** Owner navigates to the doc
**Then:** Empty state message (e.g., "Add your first story") and action button shown
**Verify:** Empty doc -> helpful empty state, not a blank page.

### UAT-25: Doc with long title displays correctly
**Given:** A doc with a very long title (100+ characters)
**When:** Displayed in the doc list and on the detail page
**Then:** Title is truncated or wrapped gracefully — no horizontal overflow
**Verify:** Create doc with very long title -> no layout breaks.

### UAT-26: Rapid story additions don't create duplicates
**Given:** Owner rapidly clicks "Add" on 3 stories in quick succession
**When:** All requests complete
**Then:** Exactly 3 stories in the doc, no duplicates, positions are correct
**Verify:** Fast-add 3 stories -> count is 3, no duplicates.
