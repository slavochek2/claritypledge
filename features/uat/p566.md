# UAT: P566 — Audio Chunk Upload Reliability

## UAT-1: Happy path recording — healthy banner
**Given:** User is in an active /live session with a partner, mic permission granted
**When:** Audio recording starts and chunks begin uploading
**Then:** RecordingIndicator banner shows `✨ Session recorded for AI Insights`
**Then:** Banner color is blue (healthy state)
**Verify:** Start a session → banner appears with healthy text. Uploads proceed in background.

## UAT-2: Degraded banner on network issues
**Given:** User is in an active recording session with healthy uploads
**When:** Network degrades and 3 consecutive chunk uploads fail
**Then:** Banner transitions to `⚠️ Weak connection — retrying audio upload`
**Then:** Banner color changes to amber (degraded state)
**Then:** Queue continues retrying with exponential backoff
**Verify:** Throttle network → after 3 failures, banner turns amber with degraded text.

## UAT-3: Critical banner on sustained failure
**Given:** User is in an active recording session, banner is degraded
**When:** Upload failures persist for 30+ seconds without any success
**Then:** Banner transitions to `❌ Audio upload failing — check your connection`
**Then:** Banner color changes to red (critical state)
**Verify:** Keep network blocked for 30s → banner turns red with critical text.

## UAT-4: Recovery from critical to degraded
**Given:** Banner is in critical state (red)
**When:** Any single chunk upload succeeds (network recovers)
**Then:** Banner transitions back to `⚠️ Weak connection — retrying audio upload` (amber/degraded)
**Verify:** Restore network → first successful upload transitions banner from red to amber.

## UAT-5: Recovery from degraded to healthy
**Given:** Banner is in degraded state (amber)
**When:** 3 consecutive chunk uploads succeed
**Then:** Banner transitions back to `✨ Session recorded for AI Insights` (blue/healthy)
**Verify:** Restore network → after 3 consecutive successes, banner returns to blue.

## UAT-6: Post-session upload gate — progress display
**Given:** Partner has left the session and chunks are still pending upload
**When:** PartnerLeftScreen renders
**Then:** Screen shows heading `Uploading session audio...`
**Then:** Screen shows progress text like `3 of 10 chunks uploaded`
**Then:** Screen shows warning `Don't close this tab until upload completes`
**Then:** Progress bar updates as chunks complete
**Verify:** End session with pending chunks → gate shows heading, progress count, and warning.

## UAT-7: Post-session upload gate — completion
**Given:** Post-session gate is showing upload progress
**When:** All remaining chunks finish uploading
**Then:** Screen shows `✓ Audio upload complete`
**Then:** Warning text disappears
**Then:** User can navigate away freely (no beforeunload warning)
**Verify:** Wait for all chunks to upload → completion message appears, user can leave.

## UAT-8: Post-session upload gate — failure after timeout
**Given:** Post-session gate is showing upload progress
**When:** 5 minutes pass with no successful uploads
**Then:** Screen shows `Some audio could not be uploaded`
**Then:** User is released (can navigate away, no further blocking)
**Verify:** Block network for 5 minutes on post-session gate → failure message appears, user can leave.

## UAT-9: Orphaned chunk recovery
**Given:** User had a session yesterday where some chunks failed to upload (< 24h old)
**When:** User opens a new /live session
**Then:** Orphaned chunks from the previous session are detected and re-queued for upload
**Then:** Orphaned chunks use fresh signed URLs for upload
**Verify:** Close browser mid-session → reopen within 24h → orphaned chunks upload automatically.

## UAT-10: Orphaned chunk discard (> 24h)
**Given:** User had a session 2 days ago where chunks failed to upload (> 24h old)
**When:** User opens a new /live session
**Then:** Stale orphaned chunks are silently discarded (not re-queued)
**Verify:** Close browser mid-session → reopen after 24h → old chunks are cleaned up, not uploaded.

## UAT-11: Tab backgrounding triggers flush
**Given:** User is in an active recording session with chunks in the upload queue
**When:** User switches to a different browser tab (page becomes hidden)
**When:** User switches back to the session tab (page becomes visible)
**Then:** Any pending chunks are immediately flushed (upload attempts triggered without backoff delay)
**Verify:** Switch tabs during recording → switch back → observe immediate upload attempt in network tab.

## UAT-12: Force-close and reopen
**Given:** User is in an active recording session with pending chunk uploads
**When:** User force-closes the browser tab
**Then:** beforeunload event fires (browser may show "Leave site?" dialog)
**When:** User reopens the app and navigates to /live
**Then:** Chunks persisted in IndexedDB are detected as orphaned and handled per UAT-9/UAT-10 rules
**Verify:** Force-close tab → reopen → orphaned chunks are recovered if < 24h.
