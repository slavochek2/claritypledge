# P676 UAT: Letter Reading Visual Corrections

## UAT-1: Drawer backdrop transparency

### UAT-1.1: Story card visible when drawer is open
**Given:** A sealed letter with at least one story
**When:** Receiver reaches story-rate phase (drawer slides up)
**Then:** Story card is fully visible — no dark overlay, no dimming, no opacity reduction
**Verify:** Screenshot — compare to /live rating phase (should look identical)

### UAT-1.2: Preview page also transparent
**Given:** Sender previews their letter
**When:** Preview reaches story-rate phase
**Then:** Same transparent backdrop behavior as reading page
**Verify:** Visual inspection

## UAT-2: Drawer styling matches /live

### UAT-2.1: Drawer header is screen-reader-only
**Given:** Rating drawer is open
**When:** Inspecting the drawer visually
**Then:** No visible header text above the rating question — header is sr-only for accessibility
**Verify:** Visual inspection — compare to /live drawer

### UAT-2.2: Rating question centered with scale labels
**Given:** Rating drawer is open
**When:** Looking at drawer content
**Then:** Question is centered as h2, scale labels "Not at all" (left) and "Complete cognitive understanding" (right) visible below rating buttons
**Verify:** Screenshot comparison with /live

### UAT-2.3: Submit button small and centered
**Given:** Receiver selects a rating
**When:** Submit button becomes active
**Then:** Button is small (not full-width), centered in the drawer, max ~200px wide
**Verify:** Side-by-side with /live's Submit button

### UAT-2.4: Drawer bottom padding matches /live
**Given:** Rating drawer is open
**When:** Looking at drawer spacing
**Then:** Extra bottom padding (pb-8 equivalent) creates breathing room below Submit
**Verify:** Visual comparison with /live

## UAT-3: Continue button secondary weight

### UAT-3.1: Post-story-reveal Continue is outline style
**Given:** Receiver has submitted rating and seen gap reveal
**When:** Continue button appears below the story card
**Then:** Button reads "Continue", uses outline style (blue border + blue text, no filled background)
**Verify:** Screenshot — should be visually lighter than the in-drawer Submit

### UAT-3.2: Post-point-reveal Continue is outline style
**Given:** Receiver has positioned on a point and seen sender's position
**When:** Continue button appears
**Then:** Same outline styling as UAT-3.1
**Verify:** Visual inspection

### UAT-3.3: In-drawer Submit retains primary CTA style
**Given:** Rating drawer is open with a rating selected
**When:** Looking at the Submit button
**Then:** Submit remains blue/filled primary CTA — NOT outline
**Verify:** Contrast with Continue button (UAT-3.1) — Submit should be more prominent

## UAT-4: Position badge overflow

### UAT-4.1: Position badge inside card boundary
**Given:** A story card with a position badge (Agrees/Disagrees) visible after reveal
**When:** Badge renders on the card
**Then:** Badge is fully contained within the card's visual boundary — no overflow above or below the card edges
**Verify:** Screenshot at multiple viewport widths (mobile + desktop)

## UAT-5: Regression checks

### UAT-5.1: /live drawer unchanged
**Given:** A /live session between two users
**When:** Rating drawer opens during /live
**Then:** Drawer looks and behaves identically to before P676 — transparent backdrop, sr-only header, centered Submit
**Verify:** Side-by-side /live screenshot vs pre-P676 /live

### UAT-5.2: All P673 tests pass
**Given:** P676 changes applied
**When:** Running full P673 test suite
**Then:** All existing tests pass without modification
**Verify:** `npm run test:e2e -- --grep "P673"`
