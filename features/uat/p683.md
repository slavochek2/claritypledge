## UAT-1: New recipient — full consent flow

**Given** I receive a Clarity Letter email and click "Open Letter"
**And** I am not logged in (unauthenticated)
**When** the LetterCover loads
**Then** I see a click-wrap disclosure: "By opening, you agree to the Terms of Service and Privacy Policy. We'll create an account so you can save your responses."
**And** the "Open Letter" button is immediately active (click-wrap, not checkbox-gate)

**When** I click "Open Letter"
**Then** the reading flow begins
**And** `terms_acceptances` row is created with non-null ip_hash (64-char hex) and user_agent

**Verify in DB:** `SELECT * FROM terms_acceptances WHERE terms_version = 'v1.2' ORDER BY accepted_at DESC LIMIT 1;`
Expected: row exists with non-null ip_hash (64-char hex) and user_agent

## UAT-4: Sender preview — cover page first

**Given** I am the sender of a letter
**When** I navigate to `/letter/:id/preview`
**Then** I land on the LetterCover page (not the reading flow directly)
**And** I see "A Clarity Letter", my recipient's name, and "From [my name]"
**And** there is NO TOS disclosure (I am authenticated)
**And** the "Open Letter" button is active

**When** I click "Open Letter"
**Then** an amber "PREVIEW" banner appears at the top of the reading flow
**And** I can read through the letter in preview mode

## UAT-5: Results page after completion

**Given** I have completed reading a 1-to-1 letter (rated all stories)
**When** the letter transitions to the results screen
**Then** I see "Your responses have been shared with [SenderName]."
**And** I see "They'll see how your perspective compared to theirs."
**And** I see "You can close this tab."
**And** there is NO "Done" button, NO navigation chrome, NO CTA
**And** there is NO confetti (sender's LetterCompletionSummary behavior — not here)
**And** the tab does NOT close automatically (no window.close())

---

## UAT-6: Edge function — consent bypass attempt

**Given** I have the letter invitation token
**When** I POST to `/functions/v1/create-and-open-letter` with `{ token, termsAccepted: false, termsVersion: "v1.2" }`
**Then** the response is 400 with an error message
**And** NO auth account is created in Supabase

**When** I POST with `{ token, termsAccepted: "true", termsVersion: "v1.2" }` (string, not boolean)
**Then** the response is 400 (strict boolean enforcement)

---

## UAT-7: Edge function — version allowlist enforcement

**Given** the server-side allowlist is `['v1.1', 'v1.2']`
**When** I POST with `{ token, termsAccepted: true, termsVersion: "v9.9" }`
**Then** the response is 400 with error about invalid version
**And** NO auth account is created

---

## UAT-8: Error state recovery

**Given** the create-and-open-letter edge function returns an error (network offline or server error)
**When** I click "Open Letter"
**Then** an inline error message appears below the button
**And** the error message has role="alert" (announce to screen readers)
**And** the button re-enables (not stuck in loading state)
**And** I can try again by clicking the button

---

## UAT-9: create-and-sign version fix (agreement flow)

**Given** I create a new Clarity Agreement
**When** the partner signs via the acceptance flow
**Then** `terms_acceptances` table has a row with `terms_version = 'v1.2'` (not 'v1.1')
**And** `profiles.accepted_terms_version = 'v1.2'` for the newly created partner profile (if new account)

---

## UAT-10: Accessibility — keyboard-only flow

**Given** I am using keyboard navigation only (no mouse)
**When** the LetterCover loads (unauthenticated)
**Then** I can Tab to reach the "Open Letter" button
**And** pressing Enter on the button opens the letter
**And** all links (Terms, Privacy) are reachable via Tab
