# UAT: P696 — Letter Reading Flow Polish & Refactor

Manual verification checklist. Work through each scenario on the UAT test account after the feature branch is deployed to preview.

**Test URL base:** `https://claritypledge.com` (preview deployment)
**Auth:** E2E test account or personal account
**Prerequisite:** A sealed letter with 2+ stories and multiple points exists.

---

## Setup

1. Log in as a receiver of a sealed 1-to-1 letter with:
   - Story 1: 3 visible points
   - Story 2: 2 visible points
   - Story 3: 1 visible point
2. Have the drafts list page open in a second tab as the sender

---

## Phase 1: Metadata

### Cover Page

- [ ] Cover shows "N stories · M points · ~X minutes" (all three values present)
- [ ] Point count matches the actual number of visible points in all stories
- [ ] Reading time is `Math.max(1, ceil(totalPoints + storyCount))` — NOT `storyCount × 2`
- [ ] Example: 3 stories / 6 points → ~9 minutes (not ~6)
- [ ] No extra text, no double-counting of hidden points

### Drafts List

- [ ] Sender's drafts list shows "N stories · M points" for each doc
- [ ] Hidden points are NOT counted in the point total
- [ ] Format is "N stories · M points" (not "N stories, M points" or other variant)

---

## Phase 2: Centering

### Story Card Alignment

- [ ] At 375px viewport (mobile): story card is horizontally centered — not left-aligned with gap on right
- [ ] At 768px (tablet): same centering
- [ ] At 1280px (desktop): same centering
- [ ] JourneyToUnderstanding result card is also centered (not left-aligned)
- [ ] Preview flow has the same centering as reading flow

---

## Phase 3: LetterFlowContent (structural refactoring — no behavior regression)

### Preview Flow

- [ ] Sender can open preview and see the amber preview banner at top
- [ ] Preview flow shows all phases in order (point-engage → story-rate → etc.)
- [ ] Preview ratings do NOT persist (reload preview → state resets)
- [ ] Preview completion shows "End of preview" (not reading completion)

### Authenticated Reading Flow

- [ ] Receiver reading flow shows FocusHeader (back button)
- [ ] Auth gate appears at story-rate if reader is somehow not authenticated
- [ ] Completion view shows correct variant (LetterRecipientDone for 1-to-1, LetterCompletionSummary for 1-to-many)

### Public Reading Flow (one-to-many)

- [ ] Open a one-to-many letter without logging in
- [ ] Flow proceeds through all phases
- [ ] Completion shows LetterResponseSignupForm

---

## Phase 4: Interaction Consistency

### Action Zone: Drawer Everywhere

- [ ] **point-engage phase**: position selector (Disagree/Unsure/Agree) appears in bottom Drawer — NOT inline in the point card
- [ ] **point-revealed phase**: comparison card is in content area; Drawer shows only the "Next" button after delay
- [ ] **story-rate phase**: ComprehensionRatingCard (0-10) is in Drawer — consistent with P673 behavior
- [ ] **story-revealed phase**: JourneyToUnderstanding + GapBanner in content area; Drawer shows only "Next Story" / "Complete Letter" after delay
- [ ] **remaining-point-engage**: same as point-engage (Drawer has position selector)
- [ ] **remaining-point-revealed**: same as point-revealed (Drawer has delayed "Next")

### Button Labels

- [ ] "Submit Your Position" (not "Submit" or "Continue") in point-engage Drawer
- [ ] "Next" (not "Continue" or "Advance") in point-revealed Drawer after delay
- [ ] "Submit My Rating" (not "Submit" or "Rate") in story-rate Drawer
- [ ] "Next Story" (not "Continue" or "Next") in story-revealed Drawer — all stories except last
- [ ] "Complete Letter" (not "Next Story" or "Done") in story-revealed Drawer — **last story only**
- [ ] No generic "Continue" button anywhere in the reading flow

### Comparison Card (point-revealed)

- [ ] After submitting a position, point card transitions to comparison layout
- [ ] Two-column layout: "You" on left, sender's name on right
- [ ] Both positions shown as badges (Agree/Disagree/Unsure)
- [ ] Comparison is neutral — no celebration or "match!" styling (calibration lives at story level)
- [ ] Position selector is gone — no way to change position after submission
- [ ] Card background subtly shifts to indicate result state (not question mode)

### 400ms Delay

- [ ] After submitting a position: "Next" button does NOT appear immediately
- [ ] After approximately 400ms, "Next" fades in smoothly
- [ ] Cannot click through by tapping immediately after position submit
- [ ] After submitting a rating: same delay before "Next Story" / "Complete Letter"
- [ ] On RESUME (navigate away and back to point-revealed): button appears immediately, no delay

### Disable-on-tap

- [ ] "Submit Your Position" disables immediately on first tap (before async completes)
- [ ] "Submit My Rating" disables immediately on first tap
- [ ] Error cases (network failure): button re-enables after error, selection preserved

### Edge Cases

- [ ] 0-point story: goes straight to story-rate → story-revealed (no point phases)
- [ ] Story with all points hidden: same as 0-point behavior
- [ ] Fast network: flow completes without any visible loading state
- [ ] Slow network (throttle to "Slow 3G"): "Saving..." loading state visible during submit

## Accessibility (quick keyboard check)

- [ ] Tab from page into Drawer reaches position selector buttons
- [ ] Enter on a position button selects it (not a generic click)
- [ ] Tab to "Submit Your Position" → Enter submits
- [ ] Screen reader (VoiceOver/NVDA): announces "Choose your position" as Drawer title
- [ ] After position reveal: "Your position: [X]. [Author]: [Y]" announced via aria-live
- [ ] "Next" button NOT announced/focused immediately — appears only after delay
