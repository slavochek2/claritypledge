# UAT: P700 — Letter Overview (stacked cohort tables)

**Spec:** [p700_letter_results_aggregate_overview.md](../done/2026-04-22/p700_letter_results_aggregate_overview.md)
**Status:** ready-for-uat
**Revision:** 2026-05-05 — new design (stacked cohort tables, no selectors, no View 1/2/3)

---

## UAT-1: Navigation to Overview Page

### UAT-1.1 — Desktop: [Open overview] button on sent-tab card

**Given** I am the author of a sealed letter with at least one recipient
**And** I am on the Sent tab (`/letters?tab=sent`) at viewport width ≥ 768px
**When** I see the letter card
**Then** a solid blue `Open overview` button is visible in the card's action area, rightmost position directly before the `[···]` dropdown

**When** I click `Open overview`
**Then** the browser navigates to `/letter/:id/overview`

---

### UAT-1.2 — Mobile: [Open overview] in ··· dropdown

**Given** I am on the Sent tab at viewport width ≤ 767px
**When** I tap the `[···]` dropdown on a letter card
**Then** `Open overview` appears as the **first item** in the dropdown

**When** I tap `Open overview`
**Then** the browser navigates to `/letter/:id/overview`

---

### UAT-1.3 — Sent-tab cards default collapsed on mount and reload

**Given** I navigate to the Sent tab for the first time in this session
**Then** all letter cards are collapsed — no recipient rows or delivery details are visible
**And** I must manually expand a card to see recipient details

**When** I reload the page
**Then** all cards return to collapsed state (no session or local-storage persistence of expanded state)

---

## UAT-2: Overview Page — Content

### UAT-2.1 — Letter title renders as h1

**Given** I navigate to `/letter/:id/overview` as the letter's author
**When** the page loads
**Then** the letter's title is displayed as an `<h1>` element at the top of the page
**And** no other `<h1>` element is present on the page

---

### UAT-2.2 — Stories render in author order (not alphabetical, not by ID)

**Given** a letter with 2 stories added in a specific authoring order
**When** I view the overview page
**Then** Story 1 (position 0) appears above Story 2 (position 1) on the page
**And** the order matches the order the author added stories to the letter, not alphabetical order

---

### UAT-2.3 — Story header shows title and hashtags inline

**Given** a story section is visible on the overview page
**Then** the story's title is rendered as an `<h2>` element
**And** the story's hashtags appear inline after the title in muted text (e.g. `#ai-risk #labor`)
**And** the hashtag elements have `aria-hidden="true"` (decorative)

---

### UAT-2.4 — Cohort table has correct column headers per story

**Given** a story section is visible
**Then** the cohort table beneath it contains these column headers (left to right):
- **Person** — for recipient names
- **You → Them** — for sender expected → recipient actual rating
- One column per point in the story, with the point text and hashtag as the header
- A final unlabeled column for the end-of-row status link

**And** column headers use `<th scope="col">` for accessibility

---

### UAT-2.5 — Back link [← Sent] routes to sent tab

**Given** I am on the overview page
**When** I click `[← Sent]` in the top-left
**Then** the browser navigates to the Sent tab (`/letters?tab=sent`)
**And** the back link has `aria-label="Back to Sent tab"`

---

## UAT-3: Cohort Table — Per-Recipient Rows

### UAT-3.1 — Responded recipient — Person column (profile link)

**Given** recipient Alice has completed the letter and has a profile slug
**When** I view Alice's row in the cohort table
**Then** her display name appears in the Person column as a clickable link to `/p/<slug>`
**And** clicking her name navigates to her profile page (NOT to the results page)

---

### UAT-3.2 — Responded recipient — You → Them column

**Given** the sender rated Story 1 at 7/10 expected understanding
**And** Alice rated Story 1 at 8/10 actual understanding
**When** I view Alice's row for Story 1
**Then** the You → Them column shows `7 → 8`

---

### UAT-3.3 — Responded recipient — Position columns show position label

**Given** Alice responded with `agree` on the first point
**When** I view Alice's row
**Then** the column for that point shows `Agree` (from `POSITION_SHORT_LABELS`)
**And** the label is one of: `Agree+`, `Agree`, `Agree−`, `Unsure`, `Disagree−`, `Disagree`, `Disagree+`

---

### UAT-3.4 — Responded recipient — No-position cell shows —

**Given** Alice responded to the letter but did NOT set a position on the second point
**When** I view Alice's row in the second point's column
**Then** the cell shows `—` in muted text
**And** the cell contains sr-only text such as "No response" for screen reader users
**And** the cell does NOT show a signed integer, a zero, or any position label

---

### UAT-3.5 — Responded recipient — [open results →] link with correct URL

**Given** Alice has completed the letter (status = 'completed')
**When** I view Alice's row
**Then** the end-of-row cell contains the link `[open results →]`
**And** the link URL is `/letter/:id/results?delivery=<alice_delivery_id>&story=<story_id>`
**When** I click `[open results →]`
**Then** the browser navigates to P699, anchored to that story

---

### UAT-3.6 — Waiting recipient — · Waiting appears (no link)

**Given** recipient Carol has NOT completed the letter (delivery status = 'sent')
**When** I view Carol's row
**Then** the end-of-row cell shows `· Waiting` in muted text
**And** there is NO `[open results →]` link in Carol's row
**And** the `· Waiting` text is not a clickable element
**And** the cell contains sr-only text "Waiting for response"

---

### UAT-3.7 — Waiting recipient — You → Them shows X → —

**Given** Carol has not responded (delivery status = 'sent')
**When** I view Carol's row in the You → Them column
**Then** the cell shows the sender's expected rating followed by `→ —`
(e.g. `5 → —` where 5 is the sender's prediction and `—` signals no actual rating)

---

### UAT-3.8 — Anonymous recipient shows (Anonymous) with no profile link

**Given** a delivery has no `receiver_name` and no profile slug
**When** I view that recipient's row in the Person column
**Then** the cell shows `(Anonymous)` in muted text
**And** there is no clickable link in the Person cell for this recipient
**And** no raw email address is displayed

---

## UAT-4: Edge States

### UAT-4.1 — All recipients waiting — page renders, all rows show · Waiting

**Given** none of the letter's recipients have completed the letter
**When** I navigate to `/letter/:id/overview`
**Then** the page renders without crashing (no error overlay, no blank screen)
**And** every recipient row across every story shows `· Waiting` in the end-of-row cell
**And** no `[open results →]` links appear anywhere on the page
**And** no position labels appear in point columns (all cells show `—`)

---

### UAT-4.2 — Zero recipients — placeholder message

**Given** a sealed letter with no deliveries created yet
**When** I navigate to `/letter/:id/overview`
**Then** the page shows: **"No recipients on this letter yet."**
**And** no cohort tables are rendered
**And** the page does not crash or show an error state

---

### UAT-4.3 — Error state — retry button

**Given** the `get_letter_overview` RPC fails (simulated network error or 500)
**When** the page loads
**Then** the page shows: **"Could not load this letter overview."**
**And** a `[Retry]` button is visible
**When** I click `[Retry]`
**Then** the RPC is re-fired without a full page reload
**And** on success, the cohort tables render normally

---

### UAT-4.4 — Non-author visits /overview — blocked or redirected

**Given** I am logged in as a user who did NOT author this letter
**When** I navigate to `/letter/:id/overview`
**Then** I am either redirected away from the overview route
**Or** I see a **"Not authorized"** state with a `[← Sent]` back link
**And** no letter data (title, recipient names, ratings, positions) is visible

---

## UAT-5: No Forbidden Elements

### UAT-5.1 — No selectors or dropdowns for story or person

**Given** I am on the overview page
**Then** there is NO story selector dropdown
**And** there is NO person selector dropdown
**And** there are NO filter controls of any kind
**And** all stories and all recipients are visible by scrolling — no filtering required

---

### UAT-5.2 — No charts, dots, axes, or visualizations

**Given** I scroll the entire overview page
**Then** no charts, bar charts, dot plots, SVG axes, color-coded cells, or any graphical visualization is present
**And** all data is presented as text in table cells

---

### UAT-5.3 — No /live data (no movement, no verification status)

**Given** I view any cohort table
**Then** no verification status badges appear (no "★ Verified", no "→ Moved")
**And** no movement arrows are shown on position values (positions are single labels, not "X → Y" format)
**And** the You → Them column shows letter-response ratings only, not /live session ratings

---

### UAT-5.4 — No means or averaged values

**Given** I view any cohort table with multiple recipients
**Then** no mean, median, average, or aggregated value appears in any cell or header
**And** each cell shows a raw per-recipient value only

---

## UAT-7: Responsive Layout

### UAT-7.1 — Mobile (390px) — rows degrade gracefully

**Given** I view the overview page at 390px width
**Then** cohort tables that exceed viewport width either horizontally scroll (within an overflow container) OR each row collapses to a stacked layout with label/value pairs vertically
**And** no data is clipped without a scroll affordance
**And** the `[open results →]` link remains tappable (row height ≥ 40px)
**And** no horizontal scroll appears on the page body itself (only within the table overflow container if present)

---

### UAT-7.2 — Desktop (1280px) — full table layout

**Given** I view the overview page at 1280px width
**Then** all cohort tables render in full column layout: Person · You → Them · [one per point] · status
**And** story sections stack vertically
**And** the `[Open overview]` button is visible on sent-tab letter cards in the desktop action row
