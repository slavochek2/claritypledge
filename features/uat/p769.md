# UAT: P769 — Session-end must be terminal and authoritative

**Spec:** [features/p769_session_end_terminal_authority.md](../p769_session_end_terminal_authority.md)
**Test account:** Use `e2e-agent@claritypledge.com` for manual UAT on production; use local dev for pre-ship.

---

## UAT-1: Author ends session from ActiveSessionBanner

**Setup:** Author and partner are both authenticated. Author has an active session. Author navigates away from /live to /letters.

**When:** Author clicks "End Session" on the Active Session Banner.

**Then:**
- [ ] The banner disappears on the author's screen within 1 second.
- [ ] The partner — who is on /live — sees "This session has ended" screen within 3 seconds (no page reload needed).
- [ ] After the partner's ended screen appears, there is no "Rejoin Session" button visible.
- [ ] `clarity_sessions.live_state.sessionEnded` is `true` in the DB.
- [ ] `clarity_sessions.status` is `'completed'` in the DB.
- [ ] No console errors on either party's browser.

---

## UAT-2: Author ends session from /live (confirmExitMeeting)

**Setup:** Author and partner are both in an active /live session (letter-sourced — started from a letter send flow).

**When:** Author clicks "End Session" (or "Leave" / exit button) from the /live page and confirms.

**Then:**
- [ ] Author's /live shows a "session ended" or post-session state within 2 seconds.
- [ ] Partner on /letters sees the LetterLiveBanner disappear within 3 seconds.
- [ ] Partner on /letters sees the LetterLiveOverlay disappear within 3 seconds.
- [ ] `clarity_live_invites.closed_at` is set (non-null) in the DB.
- [ ] No "Rejoin Session" appears for the partner after the banner clears.

---

## UAT-3: Author ends session from RejoinPrompt

**Setup:** Author had an active session, left /live, then navigates back to /live. The RejoinPrompt ("Your session is still running") is visible.

**When:** Author clicks "End Session" from the RejoinPrompt.

**Then:**
- [ ] The RejoinPrompt disappears immediately.
- [ ] `clarity_sessions.live_state.sessionEnded` is `true` in the DB.
- [ ] `clarity_live_invites.closed_at` is set for letter-sourced sessions.
- [ ] The /live page does NOT show the create-session landing screen after ending.
- [ ] Author sees the "This session has ended" screen or navigates to /letters.

---

## UAT-4: Partner lands on /live after session ended

**Setup:** Author has already ended the session (by any method). Session is in `sessionEnded=true` state in DB.

**When:** Partner navigates to `/live/{code}` (either by clicking a link or direct URL).

**Then:**
- [ ] Partner sees "This session has ended" screen — NOT the "New Session / Join Session" landing screen.
- [ ] A CTA button/link to /letters is visible on the ended screen.
- [ ] The URL is `/live/{code}` — no redirect to `/live` (bare) or any other route.
- [ ] No console errors.

## UAT-5: Partner refreshes /letters within 5s of author ending session

**Setup:** Author and partner are in an active session. Partner is on /letters (viewing the original letter or inbox). Author clicks End Session.

**When:** Partner refreshes their /letters page within 5 seconds of author clicking End Session.

**Then:**
- [ ] The Active Session Banner ("In session with {name}") does NOT appear after the page load.
- [ ] The "Rejoin Session" button does NOT appear.
- [ ] The letter content is still readable normally.

## UAT-6: Partner refreshes /live within 5s of author ending session

**Setup:** Author ends session. Partner was on /live.

**When:** Partner manually refreshes the /live page within 5 seconds.

**Then:**
- [ ] "Your session is still running" (RejoinPrompt) does NOT appear at any point during the page load.
- [ ] "This session has ended" screen appears within 1 second of the page becoming interactive.
- [ ] There is no visible "flash" of the RejoinPrompt before the ended screen.

## UAT-7: sessionStorage cleared on both parties

**Setup:** Both parties have `clarity_live_*` keys in sessionStorage (from an active session). Author ends session from any entry point.

**When:** Author ends session.

**Then (within 5 seconds of End Session on each party's browser):**
- [ ] `sessionStorage.getItem('clarity_live_session_id')` returns `null` on author's browser.
- [ ] `sessionStorage.getItem('clarity_live_session_code')` returns `null` on author's browser.
- [ ] `sessionStorage.getItem('clarity_live_session_id')` returns `null` on partner's browser.
- [ ] `sessionStorage.getItem('clarity_live_session_code')` returns `null` on partner's browser.

*Verification: Open DevTools → Application → Session Storage on each browser tab.*

## UAT-8: invite.closed_at set for all letter-sourced end paths

**Setup:** A letter has been sent, the recipient has a clarity_live_invites row (`closed_at = null`). Author ends the session.

**When (test each entry point separately):**
- [ ] Author ends from ActiveSessionBanner
- [ ] Author ends from /live (confirmExitMeeting)
- [ ] Author ends from RejoinPrompt

**Then (for each):**
- [ ] `clarity_live_invites.closed_at` is non-null in the DB after termination.
- [ ] `clarity_live_invites.closed_at` reflects approximately the time of termination (within 30 seconds).

## UAT-9: Non-letter session — invite closure is a no-op (no error)

**Setup:** Author and partner have a standard /live session (not started from a letter). No `clarity_live_invites` row exists.

**When:** Author ends the session by any method.

**Then:**
- [ ] Session terminates normally.
- [ ] No error appears in the UI or console related to invite closure.
- [ ] `clarity_sessions.status` is `'completed'` and `live_state.sessionEnded` is `true`.

## UAT-10: Regression — refresh during active session does NOT end it

**Setup:** Both author and partner are in an active session on /live.

**When:** Author refreshes their /live page (F5 / Cmd+R).

**Then:**
- [ ] `clarity_sessions.live_state.sessionEnded` remains `false` after the refresh.
- [ ] `clarity_sessions.status` remains `'active'` (or whatever the active state is).
- [ ] Partner's /live page does NOT show "This session has ended".
- [ ] Partner's /live page continues to show the active session UI.
- [ ] After refresh, author reconnects to the same session (session code preserved).

---

## UAT-11: Regression — guest pagehide does NOT end session

**Setup:** Both parties are in an active session.

**When:** Guest closes their browser tab (or navigates away causing pagehide).

**Then:**
- [ ] `clarity_sessions.live_state.joinerEnded` is NOT set to `true` immediately.
- [ ] `clarity_sessions.live_state.sessionEnded` is NOT set to `true`.
- [ ] Author's /live shows "partner disconnected" or reconnecting countdown — NOT "session ended".
- [ ] Guest can rejoin via the RejoinPrompt and the session resumes normally.

**Setup:** Active session exists.

**Then (spot-check only — P511 E2E tests cover fully):**

- [ ] Active Session Banner appears on /events when session is active.
