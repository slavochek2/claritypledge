# P847 UAT Scenarios — Position Buttons: Explicit-Clear Interaction Model

**Feature:** P847: Position Buttons — Explicit-Clear Interaction Model
**Type:** change-request (`changes: p521`)
**Verify against:** `src/app/components/shared/PositionButton.tsx` (production component post-dev)

---

## UAT-1: Common Path (One-Click Selection)

### UAT-1.1: Click unselected Agree selects without forcing intensity sub-decision

**Given:** User is on a point page with no prior position.
**When:** User clicks the "Agree" segment button.
**Then:** The Agree segment immediately shows as selected (blue/pressed style). No dropdown menu opens. No intensity sub-decision is required.

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "click unselected Agree → button shows pressed state, no dropdown menu visible"

---

### UAT-1.2: Click unselected Disagree selects without forcing intensity sub-decision

**Given:** User is on a point page with no prior position.
**When:** User clicks the "Disagree" segment button.
**Then:** The Disagree segment immediately shows as selected. No dropdown opens.

**Verify:** Unit test — `src/tests/p847-position-buttons-explicit-clear.test.tsx` → "click unselected Disagree → calls onPositionClick('disagree'), no menu opens". Manual visual check: Disagree segment turns blue, no floating menu appears.

---

### UAT-1.3: Click unselected Unsure selects in one click (no sub-decision exists)

**Given:** User is on a point page with no prior position.
**When:** User clicks the "Unsure" segment button.
**Then:** Unsure segment immediately shows as selected. No menu of any kind opens — Unsure has a single intensity so no sub-decision is ever required.

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "Unsure: first click selects, second click opens 1-row Clear menu" (first assertion of that test: no Clear menu on first click).

## UAT-2: Refine Path (Intensity Selection via Menu)

### UAT-2.1: Refine intensity — click selected Agree, pick "Somewhat Agree"

**Given:** User already has position = Agree (default intensity).
**When:** User clicks the Agree segment again. The intensity menu opens showing "Somewhat Agree", "Agree", "Strongly Agree", and "Clear position".
**When:** User clicks "Somewhat Agree".
**Then:** Position updates to Somewhat Agree (segment may show "Agree−" label). Menu closes. No intermediate null state occurs.

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "click selected Agree → menu opens with 'Clear position', badge counts unchanged" (asserts menu opens). Unit test → "clicking 'Somewhat Agree' → calls onPositionClick('somewhat_agree')".

---

### UAT-2.2: Refine intensity to maximum — Agree → Strongly Agree

**Given:** User already has position = Agree.
**When:** User clicks Agree to open the menu, then clicks "Strongly Agree".
**Then:** Position updates to Strongly Agree. Segment label shows "Agree+" (short label for strongly_agree). Menu closes.

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "click selected Agree → menu opens…" (smoke of menu open). Unit test → "clicking 'Strongly Agree' → calls onPositionClick('strongly_agree'), closes menu".

## UAT-3: Explicit Clear

### UAT-3.1: Clear Agree position via "Clear position" row

**Given:** User has position = Agree (any intensity).
**When:** User clicks the Agree segment to open the menu. User clicks "Clear position" row (red text, trash icon) at the bottom of the menu.
**Then:** The position is removed. All three segments return to unpressed state. The `PositionButtons` component itself does NOT trigger a confirmation dialog (the deliberate menu interaction IS the component-level confirmation). Menu closes. *Note: consumers that wire `onClear={() => guardedRemovePosition(...)}` may surface their own `RemovePositionDialog` as a consumer-level policy — this is expected and out of scope for the component's contract (Architect Decision B).*

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "click 'Clear position' from menu → vote removed, segment returns to unpressed state".

---

### UAT-3.2: Clear Unsure position via 1-row Clear menu

**Given:** User has position = Unsure.
**When:** User clicks the Unsure segment (already selected). A 1-row menu opens containing only "Clear position" (no intensity options exist for Unsure).
**When:** User clicks "Clear position".
**Then:** Position removed. All segments unpressed. Menu closes.

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "Unsure: first click selects, second click opens 1-row Clear menu" (asserts correct 1-row structure). Unit test → "Unsure 1-row menu: clicking 'Clear position' calls onClear()".

## UAT-4: Dismiss Paths (No Mutation)

### UAT-4.1: Escape dismisses menu without changing position

**Given:** User has position = Agree, menu is open.
**When:** User presses Escape.
**Then:** Menu closes. Position remains Agree (unchanged). No position update event fires.

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "press Escape with menu open → menu closes, position unchanged". Accessibility test → "Escape closes menu, focus returns to segment that opened it".

---

### UAT-4.2: Click outside menu dismisses without changing position

**Given:** User has position = Agree, menu is open.
**When:** User clicks anywhere outside the position buttons component (e.g., the point statement text, a badge, whitespace).
**Then:** Menu closes. Position remains Agree. No position update event fires.

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "click outside menu → menu closes, position unchanged".

---

## UAT-5: Regression — No Silent Removes

### UAT-5.1: Two-click on same Agree segment never silently removes the vote

**Given:** User has position = Agree.
**When:** User clicks the Agree segment twice in quick succession (first click opens menu, second click is on the segment while menu is open).
**Then:** Position is NEVER removed silently. The segment remains pressed (aria-pressed="true") through both clicks. The only effect of repeated clicks is menu open/close toggle.

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "regression: rapid two-click on Agree segment never triggers null state". Unit test → "two-click sequence on Agree never calls onPositionClick(userPosition) or onClear".

## UAT-7: Responsive Modes

### UAT-7.1: Full-text mode at viewport ≥270px

**Given:** Browser viewport (or container width) is ≥270px.
**When:** User views the position buttons.
**Then:** Segment buttons show full text labels ("Disagree", "Unsure", "Agree"). Intensity short labels show when a position is selected ("Agree+", "Agree−", etc.). Badge counts are visible when > 0.

**Verify:** Manual screenshot at 375px viewport. E2E — existing P521 test "no truncated labels at narrow viewport" must still pass (non-superseded regression).

---

### UAT-7.2: Icon-only mode at viewport <270px

**Given:** Browser container width is <270px (e.g., 240px).
**When:** User views the position buttons.
**Then:** Only icons are shown (no text labels, no badge counts). Segment buttons remain clickable and functional. The interaction model (no menu on first click, menu on selected-click) still works correctly.

**Verify:** Manual — resize browser to 240px width, screenshot, confirm icon-only rendering. Check that clicking works as expected via keyboard in icon-only mode.

## UAT-8: Touch Targets

### UAT-8.1: All interactive elements meet ≥40px height

**Given:** User is on a mobile viewport (375px wide).
**When:** User opens the intensity menu (click selected Agree).
**Then:** All segment buttons are ≥40px height. All menu rows (intensity options + "Clear position") are ≥40px height. This meets WCAG 2.5.5 AAA touch target size.

**Verify:** Playwright — `e2e/p847-position-buttons-explicit-clear.spec.ts` → "touch targets ≥40px on menu rows and segments when menu is open". Accessibility test → "touch targets ≥40px height on all interactive elements".
