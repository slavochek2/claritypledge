# UAT: P857 — Clarity Agreement Versioning

Verification methods: **V** = Vitest unit test | **PW** = Playwright E2E | **SQL** = direct DB query | **M** = manual browser

---

## Scenario 1 — Existing agreement renders unchanged on legacy (oath + scope)

**Given** an existing `clarity_agreements` row with `agreement_version = 'legacy'`
**When** the agreement certificate is rendered for that row
**Then** the oath displays the bilateral legacy text:
- YOUR RIGHT: "When we speak, if either of us needs to know the other truly understood them..."
- OUR PROMISE: "We will explain back what we think the other meant—withholding judgment..."
- THE EXCEPTION: "If either of us can't keep this promise in the moment..."

And the `terms_text` scope section renders unchanged (same content as before the migration)

**Verification:** V — `p461-agreement-certificate-text.test.tsx` (legacy describe block) asserts all three oath strings byte-for-byte. SQL — `SELECT agreement_version FROM clarity_agreements WHERE id = '<existing-row-id>';` → returns `'legacy'`.

## Scenario 2 — New agreement created in Stage A receives 'legacy' version stamp

**Given** Stage A is deployed (migration applied, `CURRENT_AGREEMENT_VERSION = 'legacy'`)
**When** a user creates a new agreement via the create-agreement flow
**Then** the new row has `agreement_version = 'legacy'`

**Verification:** SQL — after creating a test agreement: `SELECT agreement_version FROM clarity_agreements ORDER BY created_at DESC LIMIT 1;` → `'legacy'`. PW — `p857-agreement-version-migration.spec.ts` "new rows default to 'legacy'" test.

**Verification:** V — `p461-agreement-certificate-text.test.tsx` (v4 describe block). PW — update the "renders current version oath text" test in `p857-agreement-certificate.spec.ts` to assert v4 text (per the Stage B comment in the test). SQL — `SELECT agreement_version FROM clarity_agreements ORDER BY created_at DESC LIMIT 1;` → `'4'`.

## Scenario 6 — Rollback: flipping CURRENT_AGREEMENT_VERSION back to 'legacy'

**Given** Stage B is deployed and `CURRENT_AGREEMENT_VERSION = 4`
**When** the developer flips `CURRENT_AGREEMENT_VERSION` back to `'legacy'` in `agreement-versions.ts` and redeploys
**Then** `/partner-template` reverts to showing the legacy bilateral oath text
**And** existing agreements (both legacy and v4) render the oath from their stored `agreement_version` — no row is affected

**Verification:** M — after config flip + redeploy, load `/partner-template` and confirm bilateral text. SQL — `SELECT id, agreement_version FROM clarity_agreements;` → rows retain their stored values.
