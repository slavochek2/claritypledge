# UAT: P904 — Async Letter Verification Threads (v0)

> Acceptance criteria source: P904 spec `## Acceptance Criteria` v0 section.
> v0 scope: capture + delivery only. Grading, ratings, and certify/correct stay in /live.
> Run after /dev completes and before /ship.
>
> Copy rules enforced throughout:
> - NEVER "paraphrase" in any user-facing UI text or label
> - Affordances always name-attributed on results page ("Jamie's story →", "What Jamie understood →")
> - The full CTA is "Explain back what you understood" (not shortened)

---

## UAT-1: Receiver records a text explain-back (v0 happy path)

**Pre-condition:** Authenticated receiver (Jamie) has a completed letter delivery from Alex.
The letter has at least one story.

**Given** Jamie is on the letter results page (`/letter/:id/results?delivery=:deliveryId`)
**When** Jamie sees the story card for "The timeline risk"
**Then** a "Explain back what you understood" button is visible below the story card
**And** the word "paraphrase" does not appear anywhere on the page

**When** Jamie clicks "Explain back what you understood"
**Then** the capture panel opens (FixedBottomBar-based, bottom of screen)
**And** the capture panel shows the story title context ("Alex's story: The timeline risk")
**And** a prominent "Explain back what you understood" button is visible (primary action)
**And** a de-emphasized "Prefer to type?" option is visible (text fallback)

**When** Jamie clicks "Prefer to type?"
**Then** a text input area appears
**When** Jamie types "I understood that the timeline has dependencies on Q3 hiring."
**And** Jamie clicks "Send"
**Then** the capture panel closes
**And** the affordance row now shows "What you understood →" (filled state, no longer the CTA button)
**And** a `story_explain_backs` row exists in the DB with:
  - `recorder_id = Jamie's user ID`
  - `medium = 'text'`
  - `text_fallback` contains the typed text
  - `author_read_at = NULL` (unread)
  - `delivery_id` matching the delivery

## UAT-2: Author (Alex) sees the return signal and listens

**Pre-condition:** Jamie has filed a text explain-back (UAT-1 completed).

**Given** Alex is on the Letters list page (`/letters`)
**Then** the letter to Jamie shows "• 1 new from Jamie" (or equivalent count label)

**When** Alex opens the letter results page
**Then** the story card for "The timeline risk" shows "What Jamie understood →" with an unread dot (bold or blue indicator)

**When** Alex clicks "What Jamie understood →"
**Then** Alex is navigated to `/explain-back/:id` (the view focus page)
**And** the page title/heading says "What Jamie understood"
**And** the page shows a context line: "On your story: The timeline risk" (linked)
**And** Jamie's name and avatar are visible
**And** Jamie's text explain-back content is displayed

**When** Alex leaves the page (back button)
**Then** Alex is back on the results page
**And** the unread dot is gone (read state updated)
**And** the `author_read_at` column is no longer NULL in the DB

---

## UAT-3: Receiver explains their position on a point

**Pre-condition:** Authenticated receiver (Jamie) has a completed letter delivery. The letter has a story with a linked point ("The timeline is realistic").

**Given** Jamie is on the letter results page
**When** Jamie sees the point "The timeline is realistic" inside the story card
**Then** an "Explain your position" affordance is visible inline with the point

**When** Jamie clicks "Explain your position"
**Then** Jamie is navigated to `/create?pointId=<id>` (the existing Create Story page)
**And** the URL contains `pointId=<id>` for the correct point

**When** Jamie creates the story and saves it
**Then** the new story is linked to the point and inherits the point's visibility
**And** on the results page, the affordance now shows "Edit your story →" (not "Explain your position")
**And** Alex sees "Jamie's story →" on the same point affordance

---

## UAT-4: Pair-private access — third party cannot access explain-back

**Pre-condition:** A `story_explain_backs` row exists for the Jamie→Alex delivery. A third user (Sam) is authenticated.

**Given** Sam is authenticated and knows (or guesses) the UUID of the explain-back
**When** Sam navigates to `/explain-back/:explainBackId`
**Then** Sam is redirected away (to `/letters` or `/` — NOT shown the explain-back content)

**And** (via DB check) querying `story_explain_backs` as Sam's user JWT returns 0 rows for that ID (RLS enforced)

---

## UAT-5: Audio explain-back (manual, requires mic + real browser)

> This scenario requires a real browser with microphone access. Cannot be driven headless.
> Run manually during first real-world usage or in headed Playwright with `--use-fake-ui-for-media-stream`.

**Given** Jamie is on the letter results page and has not yet filed an explain-back
**When** Jamie clicks "Explain back what you understood"
**Then** the browser requests microphone permission (or uses pre-granted permission)
**When** Jamie grants microphone access
**Then** the recording state begins: elapsed timer shows, recording dot pulses, "Stop" button visible
**And** "Cancel" button is visible (cancels recording without saving)

**When** Jamie clicks "Stop" after ~10 seconds
**Then** the preview state appears: audio player (`<audio>`) with the recording playable
**And** "Send to Alex" button (primary) and "Re-record" button (secondary) are visible

**When** Jamie clicks "Send to Alex"
**Then** the explain-back is uploaded and the DB row has:
  - `medium = 'audio'`
  - `audio_storage_path` pointing to the private GCS bucket
  - `text_fallback = NULL`

**And** Alex can play back the recording from the view page (signed URL works)

## UAT-6: Regression — letter without explain-backs unchanged

**Given** a sealed letter with no explain-back rows exists
**When** the receiver opens the results page
**Then** the page loads normally with no errors
**And** the story card, JourneyToUnderstanding, and GapBanner render exactly as before P904

**When** the sender opens the results page
**Then** same: no errors, no new broken UI elements

---

## UAT-7: Copy rule verification — no "paraphrase" anywhere

**Given** any surface added by P904 is visible (capture panel, view page, results affordance, return signal)
**Then** the word "paraphrase" does not appear in ANY user-facing text element, ARIA label, or button copy
**And** all affordances use "explain back" / "explanation" as the user-facing verb
