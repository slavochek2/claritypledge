# UAT: P962 — Pipeline (CRM) Board

Manual checklist. Run after `/dev` completes and board is visible in the browser at `http://localhost:9050`.

---

## 1. Board appears

**Given** the kanban tool is running (`npm run kanban` from `cp`)
**When** I open the browser
**Then** a "Pipeline" tab/page is visible alongside Features and Content

---

## 2. Columns render in stage order

**Given** I navigate to the Pipeline board
**When** the board loads
**Then** I see exactly six columns in left-to-right order:
  `contacted` → `in-conversation` → `qualified` → `committed` → `active` → `closed`

No extra columns. No missing columns.

---

## 3. Cards show name, type, next_step, next_date

**Given** `matt-jones.md` and `kai.md` exist with valid frontmatter
**When** the Pipeline board loads
**Then** each card displays:
  - The person's `name` (e.g. "Matthew Jones")
  - Their `type` as a visible tag/badge (e.g. "coach")
  - The `next_step` text
  - The `next_date` date

---

## 4. Matt and Kai appear in their correct columns

**Given** `matt-jones.md` has `stage: in-conversation`
**And** `kai.md` has `stage: contacted`
**When** the Pipeline board loads
**Then** Matthew Jones's card is in the **in-conversation** column
**And** Kai's card is in the **contacted** column

---

## 5. Refresh picks up a newly added opportunity file

**Given** the Pipeline board is open
**When** I create a new `.md` file in `.private/crm/opportunities/` with valid frontmatter
**And** I trigger a refresh (click the refresh button or reload the page)
**Then** the new opportunity appears on the board in the correct column

---

## 6. Stage move via drag updates the file on disk

**Given** a card is visible on the Pipeline board
**When** I drag it from one column to another
**Then** the card appears in the new column immediately
**And** the corresponding `.md` file's `stage:` frontmatter is updated to match

---

## 7. Existing boards unaffected

**Given** the Pipeline board is enabled
**When** I navigate to the Features board
**Then** it loads normally with all existing features
**When** I navigate to the Content board
**Then** it loads normally with all existing articles

---

## 8. Private data not committable

**Given** `.private/crm/` is listed in `.gitignore`
**When** I run `git status` in `cp`
**Then** no files under `.private/crm/opportunities/` appear as tracked or staged
